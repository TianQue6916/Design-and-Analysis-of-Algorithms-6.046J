<span style="color:#c0392b">**为什么用 LRU 块替换策略？（Why LRU block replacement strategy?）**</span>

```math
\text{LRU}_M \le 2 \cdot \text{OPT}_{M/2} \quad \text{[Sleator and Tarjan 1985]}
```

**证明（Proof）**：
- 把块访问序列划分为**极大阶段（phases）**，每阶段含 $M/B$ 个不同块。
- LRU 每阶段花费 $\le M/B$ 次内存传输。
- OPT 每阶段必须花费 $\ge M/2B$ 次内存传输：最好情况下，它以**装满所需物品的 $M/2$ 缓存**开始该阶段。但阶段内有 $M/B$ 个块。所以**至多一半免费**。

> <span style="color:#1e8449;">**[note] Note（译者注，LRU 的最优性常数因子）:**</span> 这一注要回答的设计问题是：cache（缓存）替换由硬件电路自动执行，软件一行代码也改不了它，那算法分析凭什么可以把它当成「总做对决定」来处理？答案是一句 resource augmentation（资源增广）形式的陈述：给 LRU（最近最少使用）大小 $M$ 的 cache（缓存），它的缺块次数不超过给 optimal offline（最优离线）算法一半容量 $M/2$ 时缺块次数的两倍。
>
> 先讲清楚为什么不能拿同一个 $M$ 直接比。LRU（最近最少使用）是 online（在线）策略，它只能看过去、按「最久没被访问就淘汰」这条局部规则动作；OPT（最优离线）是拿着完整请求序列的 offline（离线）裁判。不给补偿就硬比，对手可以构造出 LRU（最近最少使用）每步都缺、OPT（最优离线）一次不缺的序列，比值没有上界。所以 Sleator 与 Tarjan 在 1985 年那篇讲 list update（表更新）与 paging（页面置换）的论文里换了个问法：多给 LRU（最近最少使用）一倍容量，能不能买到一个与序列长度无关的常数？能，常数是 2。
>
> 证明只有三步，但它是一个可以反复搬用的模板，值得当工具记住。第一步，把请求序列切成极大的 phase（阶段），每个 phase（阶段）恰好含 $M/B$ 个彼此不同的 block（块），$B$ 是 block size（块大小），也就是一次 memory transfer（内存传输）搬动的字节数。第二步，数 LRU（最近最少使用）在一个 phase（阶段）内的花费：本阶段出现的不同 block（块）共 $M/B$ 个，而它的容量是 $M$、装得下 $M/B$ 个 block（块），于是除本阶段第一个 block（块）可能不在里面，其余每个 block（块）在阶段内首次被请求时都还留着——阶段的定义保证了阶段内没有谁因容量不足被挤掉。所以它每个 phase（阶段）至多付 $M/B$ 次 memory transfer（内存传输）。第三步，数 OPT（最优离线）的花费：只给它 $M/2$，阶段开始时它至多预装 $M/(2B)$ 个「正好属于本阶段」的 block（块），本阶段要用 $M/B$ 个，差额 $M/B - M/(2B) = M/(2B)$ 个必须现搬。两数相除，$(M/B) / (M/(2B)) = 2$。
>
> 代具体数字复核一遍。取 block size（块大小）$B = 64$ 字节、cache（缓存）$M = 256\ \mathrm{KiB}$，则 $M/B = 4096$ 个 block（块）。一个 phase（阶段）是 4096 个不同 block（块），LRU（最近最少使用）在这个 phase（阶段）至多搬 4096 次；OPT（最优离线）只有 128 KiB，即 2048 个 block（块），阶段开头最多预装 2048 个用得上的 block（块），另外 2048 个必须现搬。比值 $4096/2048 = 2$，而且这个比值不随请求序列变长而累积——每个 phase（阶段）都是同样一笔账，序列再长也只是把同样的二比一重复若干遍。若按 CSAPP 第 6 章的量级把一次 DRAM（动态随机存取存储器）随机访问记作 80 ns，LRU（最近最少使用）在这个 phase（阶段）付 $4096 \times 80\ \mathrm{ns} = 327.68\ \mu\mathrm{s}$，OPT（最优离线）付 $2048 \times 80\ \mathrm{ns} = 163.84\ \mu\mathrm{s}$，绝对差 $163.84\ \mu\mathrm{s}$ 就是「看不见未来」在这一个 phase（阶段）里的全部代价。
>
> 跨课程连接放在两处。其一，CSAPP 第 6 章的 set-associative（组相联）cache（缓存）里，硬件用的是每个 set（组）内的近似 LRU（最近最少使用），而且是被动、非理想的；这里给出的是它的比值上界，两者说的是同一套替换机制的不同侧面——CSAPP 关心的是 miss rate（缺失率）这类实测结果，也就是 memory mountain（内存山）那条随工作集大小变化的台阶曲线；这里关心的是与最优的比值能不能被常数封住。其二，这个证明的骨架是 amortized（摊还）计数：不逐次比较 LRU（最近最少使用）与 OPT（最优离线），而是把代价攒到整块 phase（阶段）上再比，这与 6.042J 里用势能函数把一串操作的总代价压成上界是同一手法。
>
> 收束：正因为有这条常数界，后面所有 cache-oblivious（缓存无关）分析都可以放心地把 memory transfer（内存传输）的计数建在 LRU（最近最少使用）之上——证明某算法对任意 LRU（最近最少使用）cache（缓存）不超过某个 transfer（传输）数，就等于证明它对理想的最优离线 cache（缓存）也在 2 倍以内成立。

<span style="color:#c0392b">**搜索（Search）**</span>

在比较模型中**预处理 $n$ 个元素**，以支持对 $x$ 的**前驱搜索（predecessor search）**。

<span style="color:#c0392b">**$B$-树（B-trees）**</span>

它们支持**前驱**（以及插入、删除），代价是 $O(\log_{B+1} N)$ 次内存传输。
- 每个节点占据 $\Theta(1)$ 个块。
- 高度 $= \Theta(\log_B N)$。
- **需要知道 $B$**。

> <span style="color:#1e8449;">**[note] Note（译者注，$B$-树 vs 缓存无关）:**</span> 这一注要拆开一句很容易滑过去的话：B-tree（$B$-叉搜索树）能做到 $O(\log_B N)$ 次 memory transfer（内存传输），代价是「必须知道 $B$」。为什么知道 $B$ 是这个界的**充分前提**，而不是一个可有可无的实现细节？因为那个界里「每下潜一层只付一次 transfer（传输）」是靠「一个节点恰好占一个 block（块）」堆出来的；节点一旦不占一个 block（块），账立刻崩。
>
> 把因果链推到底。B-tree（$B$-叉搜索树）在节点里塞约 $B$ 个 key（键），于是高度是 $\log_B N$——每下潜一层把候选集除以 $B$。为什么高度就等于 transfer（传输）次数？因为搜索每下潜一层只读一个节点，而这个节点刚好落在一个 block（块）里，硬件一次就把整块搬进 cache（缓存），节点内那 $B$ 次比较全在 cache（缓存）内完成、不再产生 transfer（传输）。所以「节点大小 = block size（块大小）」是让「高度乘一」成立的唯一支点。设计时 $B$ 是外部给定的常数，代码把它写死进节点布局；换一台机器，$B$ 变了，布局与 $B$ 不再匹配，支点就断。
>
> 算一下支点断掉的代价。设按 $B_{\text{design}} = 1024$ 个 key（键）一个节点建树，$N = 2^{30}$，高度就是 $\log_{1024} 2^{30} = 30/10 = 3$ 层。现在换到一台 block size（块大小）只有 $B_{\text{real}} = 64$ 个 key（键）的机器：一个节点占 $1024/64 = 16$ 个 block（块），每下潜一层要搬 16 次，三层共 $3 \times 16 = 48$ 次 memory transfer（内存传输）。若就地按 $B = 64$ 重建，高度变成 $\log_{64} 2^{30} = 30/6 = 5$ 层，每层 1 次，共 5 次。$48/5 = 9.6$：猜大 $B$ 的代价是**乘性**放大，放大倍数随 $B_{\text{design}}/B_{\text{real}}$ 线性增长，等于把 $\log B$ 带来的全部收益原样吐回去，量级退回 binary search（二分搜索）。反方向猜小也不免费：$B$ 猜小一半，高度翻倍。两个方向都没有「猜对了就赚、猜错了只亏一点」的余地，这就是为什么它不是可调参数而是承重结构。
>
> 再看动态性这一层。B-tree（$B$-叉搜索树）在缓存无关模型里还有一个隐痛：它的节点大小是被 $B$ 定死的，而插入与删除要维护「每个节点占常数个 block（块）」这条不变式，一旦 $B$ 与实际 block（块）不符，split（分裂）与 merge（合并）的阈值就全错位，最坏情况会退化成每层多次 transfer（传输）。这就是 cache-oblivious（缓存无关）模型要消除的东西：它要求算法源码里**不出现 $B$ 与 $M$**，却仍要在任意 $(B, M)$ 上达到同样的渐近界。便宜的替代是运行时去读 CPUID（处理器标识指令）或 `/sys/devices/system/cpu/cpu0/cache` 下的参数，再按实际 $B$ 重建结构——那是 cache-aware（缓存感知）路线，代价是每次换机器、换虚拟化环境、甚至工作集大小变了都要重建或重新调参，而且一旦程序要在两种缓存并存的机器上跑，单一的 $B$ 就不存在了。缓存无关路线把这份「参数知识」推到渐近界之外，用递归结构自动适配，下一注的 vEB layout（递归切层布局）就是第一步。
>
> 跨课程连接：6.006 的 Recitation 2 练的就是 B-tree（$B$-叉搜索树）的下降、split（分裂）与 merge（合并）；数据库里 InnoDB 的 page（页）固定 16 KiB，把 $B$ 硬写进存储格式，是「知道 $B$」最硬核的工程形态——换来的是可预测的延迟，代价是参数一变就得 dump（导出）重导。与 CSAPP 第 6 章的关系是同一枚硬币的两面：那里的 block（块）是硬件事实、编译器替你猜步长，这里的 block（块）是算法要么猜、要么绕开的东西。区别在于 CSAPP 的实验是被动测量，本讲要的是可证的界。
>
> 收束：正文里那个「$B+1$」的 $+1$ 是给 $B$ 极小（例如 $B=1$，一个 block（块）只装一个元素）的退化情形留的余量，让 $\log_{B+1}$ 的分母不至于退化；而这一注真正要记住的是——$B$-树（$B$-叉搜索树）的复杂度里藏着一个未经证明的假设：$B$ 是已知且恒定的。

<span style="color:#c0392b">**搜索（续）**</span>

**二分搜索（Binary search）**

大致上，每轮迭代访问**一个不同的块**，直到我们进入 $x$ 所在的块。因此，

```math
MT(N) = \Theta(\log N - \log B) = \Theta(\log(N/B)) \quad \text{SLOW（慢）}
```

<span style="color:#c0392b">**van Emde Boas 布局（van Emde Boas layout）**</span>

[Prokop 1999]

- 把 $N$ 个元素存在**完全二叉搜索树**中。
- 在**中间层（middle level）的边**处**切开** BST。
- **递归布局**各片段并**拼接**。
- 像分块矩阵乘法一样，**片段的顺序无关紧要**；只需每片段**连续存储**。

**vEB 布局中 BST 搜索的分析**：
- 考虑**细化级别**，此时结构 $\le B$ 个节点。
- vEB 树的高度介于 $\frac{1}{2}\lg B$ 与 $\lg B$ 之间 $\Rightarrow$ 大小介于 $\sqrt{B}$ 与 $B$ 之间。
- $\Rightarrow$ 任何根到节点的路径（搜索路径）访问 $\le \frac{\lg N}{\frac{1}{2}\lg B} = 2 \log_B N$ 棵大小 $\le B$ 的树。
- 每棵大小 $\le B$ 的树占据 $\le 2$ 个内存块。
- $\Rightarrow \le 4 \log_B N = O(\log_B N)$ 次内存传输。

> <span style="color:#1e8449;">**[note] Note（译者注，为什么朴素二分搜索慢）:**</span> 这一注要解释本讲第一个反直觉结论：binary search（二分搜索）在比较次数上是最优的 $\Theta(\log N)$，一旦把计价单位换成 memory transfer（内存传输），它就慢了整整一个 $\log B$ 因子。核心在于比较次数和 transfer（传输）次数是两个层次的计数：前者假设「取一个元素」免费，后者按「搬一整块」收费。
>
> 先追到最底层。一次 memory transfer（内存传输）把一个 block（块）的 $B$ 个元素同时送进 cache（缓存）。这意味着理论上一次 transfer（传输）能把候选集从 $n$ 缩到 $n/B$，相当于做一次 $B$ 叉决策而不是二叉决策；于是任何搜索的 transfer（传输）次数下界是 $\log_B N = \log N / \log B$。binary search（二分搜索）每轮把候选集缩一半，需要 $\log_2 N$ 轮，麻烦在于这 $\log_2 N$ 轮访问的是数组里互不相邻的位置，只有最后落进「$x$ 所在那个 block（块）」之后的 $\log_2 B$ 轮才在 cache（缓存）里命中。前面 $\log_2 N - \log_2 B$ 轮每轮一个新 block（块）、一次 transfer（传输），于是 $MT(N) = \Theta(\log(N/B))$。
>
> 代数字算到底。取 $N = 2^{30}$（十亿量级的 key（键））、block size（块大小）$B = 64 = 2^{6}$ 个 key（键）。binary search（二分搜索）：$30 - 6 = 24$ 次 memory transfer（内存传输）。最优量级：$\log_B N = 30/6 = 5$ 次。比值 $24/5 = 4.8$。这里要留意界的形式差异：候选集是逐轮**除**二的，而 cache（缓存）是按块把尾部那段**减**掉，所以前者出对数相减、后者出对数相除，多出来的 $\log_2 B = 6$ 就是白扔的部分。若一次 DRAM（动态随机存取存储器）随机访问记 80 ns，单次查询 $24 \times 80 = 1.92\ \mu\mathrm{s}$，最优量级 $5 \times 80 = 0.4\ \mu\mathrm{s}$；做 $10^{6}$ 次查询就是 $1.92\ \mathrm{s}$ 对 $0.4\ \mathrm{s}$，差 $1.52\ \mathrm{s}$。这不是常数级的实现差距，而是差一个随 $B$ 增长的因子。
>
> vEB layout（递归切层布局）的机制：把完全 BST（二叉搜索树）的节点按「递归切中间层」重排。具体做法是把高度 $h$ 的树从中间高度 $h/2$ 切开，上半是一棵规模约 $\sqrt{N}$ 的树，下半是约 $\sqrt{N}$ 棵规模约 $\sqrt{N}$ 的子树；对上下两半各自递归地做同样排布，最后按「上半在前、各子树依次接后」拼接。关键在于片段之间只要各自连续存储，先后顺序不影响正确性——搜索只沿树边上下走，不看地址是否相邻，所以排布是自由的。这与分块矩阵乘法里「块间顺序随意、块内连续」是同一个自由度。效果是：从根出发的任意一段前缀，在结构被切到足够细之前一直待在同一段连续内存里，于是「连续访问的节点落在同一 block（块）」自动成立，而算法完全不知道 $B$ 是多少。
>
> 为什么能到 $O(\log_B N)$：找「细化级别」，即递归切到某个深度时子结构规模落在 $\sqrt{B}$ 与 $B$ 之间（因为这类树的高度介于 $\frac{1}{2}\lg B$ 与 $\lg B$ 之间，取对数得规模落在 $\sqrt{B}$ 与 $B$ 之间）。搜索路径每穿过一个这样的子结构至少下潜 $\frac{1}{2}\lg B$ 层，故整条路径最多穿过 $\lg N / (\frac{1}{2}\lg B) = 2\log_B N$ 个子结构；每个子结构占至多 2 个 block（块），总共 $\le 4\log_B N$。代入 $N = 2^{30}$、$B = 64$：$\log_B N = 5$，上界 $4 \times 5 = 20$ 次 memory transfer（内存传输），而 binary search（二分搜索）是 24 次。要清楚这个 4 是**证明得到的常数上界**，不是实测值：真正的结论是阶为 $\log_B N$，常数 4 反映的是证明的粗放程度，工程实现里布局与对齐还会带来额外次数。
>
> 跨课程连接里有一处必须澄清：van Emde Boas 这个名字在本课出现两次，指两个不同的东西。1975 年的 van Emde Boas tree（比特分桶递归树）是一种支持整数 key（键）前驱后继的递归结构，递归对象是宇宙大小的开方；这里的 vEB layout（递归切层布局）只是把已有的 BST（二叉搜索树）换个地址排布，树本身一个节点都没改，递归对象是树的高度。Prokop 1999 年的 MIT 硕士论文做的是后者，而 Frigo、Leiserson、Prokop、Ramachandran 四人 1999 年那篇定义缓存无关模型的论文把它当成开局的第一块砖。与 CSAPP 第 6 章的连接更直接：那里的 stride（步长）实验显示同一段循环把步长从 1 改成 1024 就从 L1 掉到 DRAM（动态随机存取存储器），因为每步跨过了 block（块）边界；binary search（二分搜索）正是「步长指数增长」的最坏形态，而 vEB layout（递归切层布局）把访问序列重新捏成近似步长为 1 的形态。
>
> 收束：spatial locality（空间局部性）并没有被二分破坏，破坏它的是二分的寻址顺序；只改数据摆放、不改一行搜索代码，就能把 $\log B$ 因子收回来。

- 这可以推广到**非 2 的幂的高度**、**常数分支因子的 $B$-树**、以及**动态 $B$-树**：$O(\log_B N)$ 次传输的插入/删除。[Bender, Demaine, Farach-Colton 2000]

<span style="color:#c0392b">**排序（Sorting）**</span>

**$B$-树（B-trees）**

向（缓存无关）$B$-树插入 $N$ 次 $\Rightarrow MT(N) = \Theta(N \log_B N)$ **不是最优的（NOT OPTIMAL）**。相比之下，BST 排序是最优的 $O(N \lg N)$。

**二叉归并排序（Binary mergesort）**
- 二叉归并排序是缓存无关的。
- 归并是 3 个并行扫描。
- $\Rightarrow MT(N) = 2MT(N/2) + O(N/B + 1)$，$MT(M) = O(M/B)$。
- 递归树有 $\lg(N/M)$ 层，每层贡献 $O(N/B)$。
- $\Rightarrow MT(N) = \frac{N}{B} \lg \frac{N}{M}$。← 比之前讨论的 $B$-树版本**快 $B$ 倍**！

**$M/B$-路归并排序（$M/B$-way mergesort）**
- 把数组分成 $M/B$ 个相等子数组。
- 递归排序每个。
- 用 $M/B$ 个并行扫描归并（每个列表保持一个「当前」块）。
- $\Rightarrow MT(N) = \frac{M}{B} MT\left(\frac{N}{M/B}\right) + O(N/B + 1)$，$MT(M) = O(M/B)$。
- $\Rightarrow$ 高度变为 $\log_{M/B} \frac{N}{M} + 1 = \log_{M/B} \frac{N}{B} - \log_{M/B} \frac{M}{B} + 1 = \log_{M/B} \frac{N}{B}$。

<span style="color:#c0392b">**排序（续）**</span>

```math
\Rightarrow MT(N) = O\left(\frac{N}{B} \log_{M/B} \frac{N}{B}\right)
```

这在比较模型下是**渐近最优的（asymptotically optimal）**。

<span style="color:#c0392b">**缓存无关排序（Cache-oblivious Sorting）**</span>

这需要**高缓存假设（tall-cache assumption）**：对某个固定的 $\varepsilon > 0$，$M = \Omega(B^{1+\varepsilon})$，例如 $M = \Omega(B^2)$ 或 $M/B = \Omega(B)$。

那么，带递归（「**漏斗 funnel**」）归并的 $\approx N^\varepsilon$-路归并排序即可工作。

<span style="color:#c0392b">**优先队列（Priority Queues）**</span>

- 每次插入或 delete-min 的代价是 $O\left(\frac{1}{B} \log_{M/B} \frac{N}{B}\right)$（摊还）。
- 推广了排序。
- 同时适用于外部内存与缓存无关。
- 参见 6.851。

> <span style="color:#1e8449;">**[note] Note（译者注，排序的三个版本与最优界）:**</span> 这一注要把三种排序放进同一把尺子下量：都用 $MT(N)$ 计 memory transfer（内存传输）次数，都把「扫一遍 $N$ 个元素」当基本积木，差别只在递归树的高度与每层搬多少块。
>
> 先把下界钉住。Aggarwal 与 Vitter 在 1988 年那篇定义 external memory（外部内存）模型的论文里证明：比较模型下排序 $N$ 个不可分元素至少需要 $\Omega(\frac{N}{B} \log_{M/B} \frac{N}{B})$ 次 memory transfer（内存传输），这个下界在缓存无关模型里同样成立。看它的形状：前面的 $\frac{N}{B}$ 是每个 block（块）至少要被触碰一次量级的账；后面的对数是「每次 merge（归并）最多把 $M/B$ 段并成一段」的账。三个版本的差距全部体现在它们离这条线多远。
>
> 机制追到第一性原理：为什么 $k$ 路归并的上限是 $M/B$？归并 $k$ 个有序段时，每段需要一个「当前 block（块）」待在 cache（缓存）里，否则每取一个元素都要回内存；再加一个输出 block（块），共 $k+1$ 个 block（块）必须同时驻留。所以 $k+1 \le M/B$，即路数被 cache（缓存）能同时放下的 block（块）数**封顶**。这是后面所有加速的唯一来源，也是本讲标题里「路数 = 缓存块数」那句话的全部内容。
>
> 三个版本逐个数。取 $N = 2^{30}$、$B = 64 = 2^{6}$、$M = 2^{16} = 65536$ 个元素（按 8 字节 key（键）算是 512 KiB），于是 $M/B = 1024$。版本一，往 B-tree（$B$-叉搜索树）里插 $N$ 次再顺序读出：每次插入 $\Theta(\log_B N)$ 次 transfer（传输），总数 $N \log_B N = 2^{30} \times (30/6) = 5.37 \times 10^{9}$ 次。版本二，binary mergesort（二叉归并排序）：递推 $MT(N) = 2MT(N/2) + O(N/B + 1)$，递归树有 $\lg(N/M)$ 层、每层 $O(N/B)$，故 $MT(N) = \frac{N}{B} \lg \frac{N}{M} = 2^{24} \times \lg 2^{14} = 2^{24} \times 14 = 2.35 \times 10^{8}$ 次。版本三，$M/B$-路归并：分 1024 段递归排序，再 1024 路归并，每层仍是 $N/B$ 次 transfer（传输），层数压到 $\log_{M/B}(N/B) = \log_{1024} 2^{24} = 24/10 = 2.4$，故 $MT(N) = 2^{24} \times 2.4 = 4.03 \times 10^{7}$ 次。按每次 80 ns 折算，三者是 $429\ \mathrm{s}$、$18.8\ \mathrm{s}$、$3.22\ \mathrm{s}$：版本二比版本一快 $5.37 \times 10^{9} / 2.35 \times 10^{8} = 22.8$ 倍，版本三再快 $2.35 \times 10^{8} / 4.03 \times 10^{7} = 5.85$ 倍，且版本三的数就是下界本身，所以它渐近最优。
>
> 为什么「层数」一变就赢这么多？因为每层的 $N/B$ 次 transfer（传输）躲不掉（每个 block（块）至少碰一次），能优化的只有层数。二叉归并每层把段数乘 2，把 $M$ 个元素排好需要 $\lg(N/M)$ 层；$\frac{M}{B}$-路归并每层把段数乘 1024，层数就成了 $\log_{M/B}(N/B)$。$\lg$ 换成 $\log_{1024}$，14 层变 2.4 层，差距全在这里。注意版本三的 5.85 倍恰好是 $\lg(N/M)$ 与 $\log_{M/B}(N/B)$ 的比，不是巧合。
>
> 但 $\frac{M}{B}$-路归并要求知道 $M$ 与 $B$，又回到上一注的困境。缓存无关排序的做法是 funnelsort（漏斗归并）：把 $N^{\varepsilon}$ 路归并组织成一棵「漏斗」，每层的路数由数据自身规模决定，从而对任意 $(M, B)$ 自动取到合法的 $k$。代价是一个必要条件——tall-cache assumption（高缓存假设）：存在固定 $\varepsilon > 0$ 使 $M = \Omega(B^{1+\varepsilon})$，常简写为 $M = \Omega(B^{2})$。它的含义是 cache（缓存）必须能装下**很多块**（$M/B$ 也要足够大），而不是一个巨型 block（块）。Brodal 与 Fagerberg 2003 年证明了这个假设不是技术性借口：没有它，任何缓存无关比较排序都达不到最优界——这就把「缓存无关能不能完全免费」这个问题回答成了「不能，但代价只有一条结构假设」。
>
> 跨课程连接：CLRS 第 2 章的 $T(n) = 2T(n/2) + \Theta(n)$ 与这里 $MT(N) = 2MT(N/2) + O(N/B)$ 是同一个递推、两种计价单位——CLRS 数比较，这里数 block（块）；6.006 讲 heap（堆）时把 build 与 extract-min 的摊还代价算清，正是本讲末尾优先队列那行 $O(\frac{1}{B} \log_{M/B} \frac{N}{B})$ 的祖先；CSAPP 第 6 章的排序实验里小 $N$ 时 quicksort（快速排序）与 mergesort（归并排序）的差别在分支预测，大 $N$ 时差别在 block（块）局部性，本讲量化的正是后者。区别在于本讲的尺子不含任何常数开销，只认传输次数。
>
> 收束：三个版本可以读成同一条曲线上的三个点——$\Theta(N \log_B N)$ 贵在每元素都要一次下降；$\frac{N}{B} \lg \frac{N}{M}$ 已经用上块局部性；$\frac{N}{B} \log_{M/B} \frac{N}{B}$ 撞上 Aggarwal–Vitter 下界，再好也只能改进常数。

> <span style="color:#1e8449;">**[note] Note（译者注，本讲在算法版图的位置）:**</span> 这一注要回答的是「这六讲到底给算法分析加了什么」这个问题。从 Lec 16 到 24 一直在做同一件事：把机器从「透明的、每次访问都等价」变成「有层级、有价格」的一等公民，然后重新问每个经典问题的最优性。缓存无关算法是这条路线上的收尾动作，也是最强的那个——它连机器的参数都不许看。
>
> 机制上讲清「递归为什么能自动适配」。任取一个递归分治算法，以二叉归并为例，它在递归树上第 $d$ 层产生规模 $N/2^{d}$ 的子问题。对任意给定的 $M$，总存在某个深度 $d^{*}$，使 $N/2^{d^{*}}$ 刚好装得下 cache（缓存）而上一层装不下。这个 $d^{*}$ 在写代码时是未知的，**但它一定存在**；而算法在每一层做的是同样的事，于是递归到 $d^{*}$ 时子问题整体进了 cache（缓存），此后对这棵子树的所有访问都不再产生 memory transfer（内存传输）。换句话说，在任何 $M$ 下，每 $B$ 个元素都只被搬常数次，层级被递归「吸收」掉了。这就是自我缩放的准确含义：不是算法去适配机器，而是递归结构里天然含有适配每一档 $M$ 的层次，所以同一份代码在不同机器上各自贴着各自的下界走。反过来看，cache-aware（缓存感知）的做法是把这个 $d^{*}$ 用 $M$ 显式算出来再写死，省了递归的组织开销，代价是 $M$ 一变就得重算。
>
> 代数字看一台代码两种机器。机器甲：block size（块大小）$B = 64$ 个元素、$M = 2^{16}$ 个元素；机器乙：$B = 128$、$M = 2^{18}$。取 $N = 2^{30}$，funnelsort（漏斗归并）的界 $\frac{N}{B} \log_{M/B} \frac{N}{B}$ 在甲上是 $2^{24} \times \log_{1024} 2^{24} = 2^{24} \times 2.4 = 4.03 \times 10^{7}$ 次；在乙上是 $2^{23} \times \log_{2048} 2^{23} = 2^{23} \times 2.09 = 1.75 \times 10^{7}$ 次。同一份源码、不重编译、不调参，两次都贴着各自的 Aggarwal–Vitter 下界，比值 $4.03/1.75 = 2.3$ 完全由硬件参数解释。若换成 cache-aware（缓存感知）的 $\frac{M}{B}$-路归并，同一份二进制在乙上仍按 1024 路切，层数是 $\log_{1024} 2^{23} = 2.3$ 而不是 $2.09$，多搬 $2^{23} \times 0.21 = 1.76 \times 10^{6}$ 次——倍数不大，但它是结构性的，而且换机器越频繁、缓存档位越多，这个损失越难靠调参补回来。
>
> 把 LRU（最近最少使用）那 2 倍也接上，账才闭合。上面所有数字都是对理想 cache（缓存）说的，真实硬件是 LRU（最近最少使用），于是可证的界再乘 2：甲机器上 $4.03 \times 10^{7}$ 变 $8.06 \times 10^{7}$，按每次 80 ns 算是 $6.45\ \mathrm{s}$。要强调这个 2 是最坏情形的比值而不是实测倍率，但它是可证的上界，工程上能拿它做容量规划与可行性判断——这正是理论注记与实际测量之间该有的分工。
>
> 历史与人物只点到必要位置：Prokop 1999 年的硕士论文与 Frigo、Leiserson、Prokop、Ramachandran 1999 年那篇论文确立了模型与 funnelsort（漏斗归并）；Bender、Demaine、Farach-Colton 2000 年把静态结构做成动态的缓存无关 B-tree（$B$-叉搜索树），支持摊还 $O(\log_B N)$ 的插入与删除；优先队列把排序推广成逐元素操作，每次摊还 $O(\frac{1}{B} \log_{M/B} \frac{N}{B})$，并指向 6.851。这些人值得记的不是年份，而是他们各自消掉了哪一个「必须知道参数」的假设：Prokop 消掉了搜索里的 $B$，Frigo 等人消掉了排序里的 $M/B$，Bender 等人消掉了动态更新里的 $B$。
>
> 跨课程连接：CSAPP 第 6 章的 memory mountain（内存山）用同一段遍历代码测出 L1、L2、L3、DRAM（动态随机存取存储器）的台阶，正是本讲 $M$ 这个参数的物理来源；你在 6.042J 学过的递推展开（把 $T(n)$ 展成和式再求闭式）是这里读 $\lg(N/M)$ 层数的工具；Cover 那门信息论课程的前几章里「一次观测带来 $\log$ 比特」的记账方式，与「一次 transfer（传输）搬 $B$ 个元素本该带来 $\log B$ 倍加速」是同一句直觉的两种说法。区别在于：memory mountain（内存山）告诉你跌落在哪里，缓存无关算法告诉你如何让程序不跌。
>
> 收束：这条主线是「内存层级 → LRU（最近最少使用）的 2 倍上界 → vEB layout（递归切层布局）→ 最优归并 → 动态结构与优先队列」，每一环只做一件事——把上一层「必须知道的参数」变成递归结构自己长出来的性质，于是「不知道 $B$ 与 $M$」从工程缺陷变成了可证的优点。
