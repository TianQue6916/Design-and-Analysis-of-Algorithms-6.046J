<span style="color:#c0392b">**现代内存层级（Modern Memory Hierarchy）**</span>

到目前为止在本课中，我们把所有操作与内存访问都视为**等成本**的。然而，现代计算机有**内存层级**。

| | 大小 | 延迟 |
|:---|:---:|:---:|
| CPU | | |
| L1 | $\sim 10\text{KB}$ | $\sim 1\text{ns}$ |
| L2 | $\sim 100\text{KB}$ | $\sim 10\text{ns}$ |
| L3 | $\sim \text{MB}$ | $\sim 10\text{ns}$ |
| 内存 | $\sim \text{GB}$ | $\sim 100\text{ns}$ |
| 磁盘 | $\sim \text{TB}$ | $\sim 10\text{ms}$ |

层级中右侧的每一层**更大**，但由于数据需要传播的**距离更长**，**延迟也更长**。然而，不同层级之间的**带宽通常是匹配的**。

缓解延迟的常用技术是**分块（blocking）**：取一个数据字（word）时，**取包含它的整个块（block）**。用算法术语说，思想是**把延迟摊还到整个块上**。为使这个思想有效，我们还需要算法**使用块中的所有字（空间局部性 spatial locality）**，并在**缓存中复用块（时间局部性 temporal locality）**。

> <span style="color:#1e8449;">**[note] Note（译者注，内存层级与局部性）:**</span>
> 这一页的表格真正要回答的问题是：为什么内存必须分层，而不是造一块又大又快的统一存储？答案在物理里，不在工艺里。信号在硅和铜里的传播速度约 $2\times 10^{8}\ \mathrm{m/s}$，一颗 $3\ \mathrm{GHz}$ 的处理器一个时钟周期只有 $0.33\ \mathrm{ns}$，这段时间信号只跑得动大约 $7\ \mathrm{cm}$；而电容充放电、地址译码这类动作的时间尺度是纳秒到几十纳秒。距离一旦超过几厘米，延迟就被光速和器件参数锁死，工艺进步只能按比例把它压小，不能把它抹掉。分层是唯一出路：把马上要用的数据搬到离核心几毫米处，代价是容量小；把暂时不用的推远，代价是慢。
>
> 第二步解释了为什么表格里会出现「延迟差出几百万倍、带宽却基本匹配」这种奇怪的组合。一次内存访问分三段：地址译码、把整行电荷搬上感放大器，这一步就是 row activation（行激活），再按 burst（突发）的方式把连续若干个字送出去。前两段的开销与你「取一个字还是取一整行」几乎无关，第三段才与字数成正比。既然行激活的钱已经花掉，多送几十个字几乎是白送，硬件索性把传输粒度固定成块。于是取一个字必须付一整块的钱，**blocking（分块）不是优化技巧，而是成本函数被硬件改成「固定开销加线性项」之后的必然应对**；不做分块，就等于每取一个字都重新付一次固定开销，白白丢掉一个 $B$ 倍的摊薄。
>
> 把这笔账算成数。设块大小 $B = 64$ 字节即 16 个 4 字节字，内存延迟 $100\ \mathrm{ns}$，带宽 $10\ \mathrm{GB/s}$，传完一块要 $64/10^{10} = 6.4\ \mathrm{ns}$。取一个字付 $100\ \mathrm{ns}$；顺序取满 16 个字共 $106.4\ \mathrm{ns}$，摊到每字 $6.65\ \mathrm{ns}$，便宜 15 倍。规模放大到 $10^{8}$ 个 int 约 400 MB：逐字随机访问要 $10^{8}\times 100\ \mathrm{ns} = 10\ \mathrm{s}$，顺序扫描只要 $6.25\times 10^{6}$ 次传输、每次 $106.4\ \mathrm{ns}$，约 $0.67\ \mathrm{s}$。换到机械磁盘，延迟 $10\ \mathrm{ms}$，同样的 400 MB 随机访问要 $10^{6}\ \mathrm{s}$，也就是约 11.6 天；顺序读只要 4 秒量级。同一份数据、同一个循环，只改访问顺序就差了五个数量级。
>
> 跨课程连接：这套账你在 CSAPP 第 6 章已经算过一遍，那边固定了 64 字节的 cache line（缓存行）、8 路组相联、LRU（最近最少使用）替换策略，目标是估计一段具体代码的 miss rate（失效率）；这里把 $B$ 与 $M$ 抽成符号，问的是「机器换一代，算法的内存传输次数按什么阶增长」。同一套 spatial locality（空间局部性）与 temporal locality（时间局部性），在 CSAPP 里是观测对象，在本讲里是设计约束：前者靠改循环顺序把常数压下去，后者靠改递归结构把阶压下去，阶能跨机器，常数一旦换机器就要重算。6.006 里还有一次预演——归并排序的归并阶段是纯顺序扫描，堆排序的 sift-down（下沉）沿树跳，数比较次数时两者差不多，换成数传输才看得出谁在浪费。
>
> 所以本讲换的不是算法，是尺子：从「数操作」换成「数 transfer（传输）」。尺子一换，同一份代码在不同机器上的好坏排序就会变，后面两个例子的全部张力都从这里来。

<span style="color:#c0392b">**算法的内存模型（Memory Model of Algorithms）**</span>

<span style="color:#c0392b">**2.1 外部内存模型（External Memory Model）**</span>

- **缓存（cache）**：总大小 $M$，分成 $M/B$ 块；每块 $B$ 个字；访问**免费**。
- **内存/磁盘（memory/disk）**：无限大小，分成块；每块 $B$ 个字；**慢且按块**访问。

在此模型中，缓存访问是免费的。算法**显式地按块**读写内存。我们将**缓存与内存之间的内存传输次数**作为算法性能的一个重要指标来计数。

<span style="color:#c0392b">**2.2 缓存无关模型（Cache-oblivious Model）**</span>

与外部内存模型的**唯一区别**是：算法**不再知道 $B$ 和 $M$**。访问内存中的一个字会自动把**整个块**取入缓存，若缓存已满则**驱逐最近最少使用（Least Recently Used, LRU）**的块。

**每个算法都是缓存无关算法**，但我们希望找到**最小化新指标（内存传输次数）**的算法。

**为什么我们喜欢缓存无关算法**（相对于让算法知道 $B$ 和 $M$）？因为这样，算法可以**自动调优（auto-tune）**，在不同计算机上（可能有不同的 $B$ 和 $M$）**高效运行**。此外，这是**很酷的研究**！

<span style="color:#c0392b">**扫描（Scanning）**</span>

示例程序：

```python
for i in range(N): sum += A[i]
```

假设 $A$ 在内存中**连续存储**。外部内存模型可以把 $A$ **与块边界对齐**，所以它需要 $\lceil N/B \rceil$ 次内存传输。

<span style="color:#c0392b">**扫描（续）**</span>

缓存无关算法**无法控制对齐**（因为它不知道 $B$），所以它需要 $\lceil N/B \rceil + 1 = N/B + O(1)$ 次内存传输。$O(1)$ 个并行扫描仍需要 $O(N/B + 1)$ 次内存传输。

> <span style="color:#1e8449;">**[note] Note（译者注，扫描的 $N/B+1$）:**</span>
> 这条注要回答的是：一个连 $B$ 是多少都不知道的算法，凭什么还能接近最优？扫描给的是最干净的答案——额外代价恰好是一次 transfer（传输），而这个 1 与 $N$ 无关。
>
> 先把上界算干净。设数组首字在它所在块内的偏移是 $o$，其中 $0 \le o < B$，那么这 $N$ 个字横跨的块数是 $\lceil (o+N)/B \rceil$。$o = 0$ 时它正好等于 $\lceil N/B \rceil$；$o > 0$ 时最多是 $\lceil N/B \rceil + 1$。加一的全部来源就是这个：首尾各可能压在半个块上。反过来，$N$ 个字无论如何都要读一遍，所以 $\lceil N/B \rceil$ 是任何算法都躲不掉的下界，缓存无关只比下界多常数次。
>
> 这个一为什么消不掉？因为算法不知道 $o$，也没法在运行前和 hardware（硬件）握手对齐；对齐需要的信息是块大小与起始地址的模，它不在算法的可见范围里。任何固定策略在最坏偏移下都要多付一次。但它为什么只是 1 而不是 $B$？一旦从偏移 $o$ 处开始读，把这一块剩下的 $B-o$ 个字用完之后，后续每块都被完整用满，浪费只发生在两端。**连续性把无知的损失封顶在边界上**——这是缓存无关分析的第一个模板：只要访问模式是一条直线，无知就只值常数。反过来，一旦访问模式开始跳，这个封顶就失效，后面矩阵乘法要费的力气全在这里。
>
> 给数验一遍。取 $N = 10^{6}$ 个 int、$B = 16$ 个字，理想传输 $\lceil N/B \rceil = 62500$ 次，多一次只占 $0.0016\%$。取小的：$N = 1000$、$B = 16$，理想 63 次；若偏移 $o = 15$，实际 $\lceil 1015/16 \rceil = 64$ 次，多出的 1 次占 $1.6\%$。再取边界情形 $N < B$：$N = 10$、$B = 16$，理想 $\lceil 10/16 \rceil = 1$ 次，最坏 2 次，相对代价 100%。三个数的走向说明：加一是固定代价，摊薄靠 $N$；式子 $N/B+1$ 在 $N \gg B$ 时把加一吃掉，在 $N \le B$ 时反而由它主导，这两种情形必须分开读，混在一起就会得出「缓存无关很差」的错误结论。
>
> 跨课程连接给两条。CSAPP 第 6 章把 cache line（缓存行）固定成 64 字节，你在那里测过「顺序求和比按列跳跃求和快一个数量级」，那是同一事实的实测版；本讲把它写成 $\lceil N/B \rceil$，因为只有写成公式才能和分治算法的递归式比较，也才能说清多一个常数到底值多少开销。另一条是 CSAPP 第 11 章 socket（套接字）编程：`read` 返回的字节数由内核决定，应用层要循环补齐一个 header（首部）的固定长度，每次补齐都是一次边界修正，与本注的加一同构——都来自「你不知道边界切在哪里」。区别在量级：那里一次边界修正可能触发一次系统调用，约微秒；这里一次 transfer（传输）约百纳秒，差三个数量级，但结构完全一样，都把不规则性推到了边界上。还差一层假设要交代：缓存无关模型做分析时默认替换策略是 LRU（最近最少使用），而前者与事后看最优的替换策略之间在每一层只差常数倍，所以按它数出来的传输次数与最优策略同阶；这一条若破了，整套分析与真实机器就脱钩，后面的递归式也就不再可信。
>
> 记住这个基准：$N/B + O(1)$ 的含义是「数据量除以块大小，再加一条与机器参数无关的小尾巴」。它是后面所有例子的参照线——谁的传输数多出 $\lg$ 因子或多出 $B$ 因子，就说明局部性还没榨干，还有 $\lg$ 或 $B$ 的改进空间留在递归结构里。

<span style="color:#c0392b">**分治（Divide & Conquer）**</span>

分治算法把问题划分到 $O(1)$ 大小。递归的**基例（base case）**要么是：
- 问题**适合缓存**，即 $\le M$，或
- 问题**适合 $O(1)$ 个块**，即 $O(B)$。

下面我们将看到各一个例子。

<span style="color:#c0392b">**4.1 中位数查找 / 顺序统计量（Median Finding / Order Statistics）**</span>

回顾算法的步骤：
1. 把数组看成按 5 分组（每组 $O(1)$ 大小）。
2. 对每组排序。
3. 递归求**组中位数的中位数**。
4. 按 $x$ **划分**数组。
5. 在**一侧**递归。

我们现在分析每一步的**内存传输数**。令 $MT(N)$ 为总内存传输数。
1. 免费
2. 一次扫描，$O(N/B + 1)$
3. $MT(N/5)$，这涉及一个预处理步骤，把 $N/5$ 个元素**合并**成一个连续数组
4. 3 个并行扫描，$O(N/B + 1)$
5. $MT(7N/10)$

---

<span style="color:#c0392b">**分治（续）**</span>

因此，我们得到递归式

```math
MT(N) = MT(N/5) + MT(7N/10) + O(N/B + 1)
```

求解该递归式需要设定基例。一个明显的基例是 $MT(O(1)) = O(1)$。但我们能得到更强的基例：**$MT(O(B)) = O(1)$**。用这个基例，递归式解为 **$MT(N) = O(N/B + 1)$**。（直觉：递归每一层的成本**几何递减**，所以**根层成本主导**。）

> <span style="color:#1e8449;">**[note] Note（译者注，中位数递归与根层主导）:**</span>
> 这条注的核心是一个判据：分治算法什么时候在 transfer（传输）指标下是好的？答案藏在那两个系数里，$\frac{1}{5} + \frac{7}{10} = \frac{9}{10} < 1$。只要子问题规模之和严格小于父问题，递归树每层的总规模就按等比数列收缩，层成本几何递减，总和被根层封顶在常数倍：$\sum_{k \ge 0} (9/10)^{k} = 10$。这个论证有个名字，叫 geometric domination（几何级数支配），它是主定理在「成本线性、子问题多路」情形下的手工版，比套公式更值得记，因为它对任何系数组合都成立。
>
> 这个 10 不是估出来的。中位数查找按比较次数算，界是 $T(N) \le 10N$，常数 10 就是 $1/(1-9/10)$ 搬过来的；换成 transfer（传输）指标，界变成 $10N/B + O(1)$，同一个 10，分母多一个 $B$。指标换了，常数的来历没换，这是理解整讲最省力的一条线索：**分析结构不随指标变，变的只是每一层工作量的计价单位**。
>
> 为什么必须是 5 个一组？这值得停下来算。$k$ 个一组、$k$ 为奇数时，组内不小于本组中位数的元素有 $(k+1)/2$ 个；组中位数共 $N/k$ 个，其中至少一半不小于中位数的中位数 $x$，即 $N/(2k)$ 个组。于是不小于 $x$ 的元素至少 $\frac{k+1}{2}\cdot\frac{N}{2k} = N\frac{k+1}{4k}$ 个，递归那一侧最多剩 $N\left(1-\frac{k+1}{4k}\right)$。把系数加起来：$\frac{1}{k} + 1 - \frac{k+1}{4k} = 1 + \frac{3-k}{4k}$。$k = 3$ 时它恰好等于 1，两项刚好抵消，树每层总量不缩水，总和退化成 $\Theta(N\lg N)$；$k = 5$ 得 $0.9$，$k = 7$ 得 $6/7$，才严格小于 1。所以「5 个一组」不是教材的习惯，而是让系数和严格小于 1 的最小奇数，同时还挑到了组内排序只需 7 次比较的规模。这条判据可以直接搬走：任何分治算法要在 transfer（传输）下达到线性，先检查子问题系数之和是否严格小于 1，别急着写代码。
>
> 现在把递归式里每一项对上号。$MT(N) = MT(N/5) + MT(7N/10) + O(N/B+1)$：第一项是中位数的中位数递归，第二项是单侧递归，第三项覆盖五步里那几次扫描——组内排序一遍、划分时三个并行扫描一遍，各 $O(N/B+1)$。基例用 $MT(O(B)) = O(1)$ 的理由是：子问题缩到 $O(B)$ 个元素时它整个装得进 $O(1)$ 个块，一次读完就完事，树在深度 $\log_{10/9}(N/B)$ 处被剪断。若改用 $MT(O(1)) = O(1)$，树会一直长到底层，每个节点都要付一次 transfer（传输），节点数是指数的，那个加一项就会盖过主项——**强基例的作用是把加一关进常量里**，这是缓存无关分析与普通递归式分析唯一实质的差别。
>
> 代数字。$N = 10^{6}$、$B = 16$：根层扫描 $\lceil N/B \rceil = 62500$ 次；第二层总规模 $0.9N$，$56250$ 次；第三层 $0.81N$，$50625$ 次。等比求和 $62500/(1-0.9) = 625000$，即 $10N/B$，与比较次数版的 10 对上了。若换成 $k = 3$ 分组，系数和为 1，每层总量恒定，深度是 $\log_{3/2}10^{6} \approx 34$ 层，总传输约 $62500 \times 34 \approx 2.1\times 10^{6}$，是 5 分组版的 3.4 倍。四十行代码的差别，换来的就是这 3.4 倍。
>
> 跨课程连接两条。CLRS 第 9 章的 deterministic select（确定性选择）用比较次数做货币，你在那里能看到 $10N$ 里那个 10 怎么来；本讲把货币换成 transfer（传输），结论变成 $O(N/B+1)$，因为每层的工作从 $N$ 次比较变成 $N/B$ 次传输，而算法结构一个字没改。另一条是 CSAPP 第 6 章：hit rate（命中率）与传输数之间只隔一层除法，那边你盯着一块具体 cache（缓存）的行为，这边你盯所有 $B$ 与 $M$ 下的阶，一个是测量，一个是设计。
>
> 最后记住这组对照：本注的树每层成本几何递减、根层主导；下一个例子的树每层成本几何递增、叶层主导。缓存无关分析的全部技巧，就在于先判断手上这棵递归树属于哪一种，因为这两种树该优化的地方正好相反。

<span style="color:#c0392b">**4.2 矩阵乘法（Matrix Multiplication）**</span>

**问题（Problem）**：计算 $Z = X \cdot Y$，其中 $X, Y, Z$ 都是 $N \times N$ 矩阵。假设 $X$ 按**行主序（row-major order）**存储，$Y$ 按**列主序（column-major order）**存储以改善局部性。

若用**基本算法**，计算 $Z$ 中的一个元素需要一两个并行扫描，因为它要么扫描 $X$ 的新行、要么扫描 $Y$ 的新列。计算每个元素需要 $O(N/B + 1)$ 次内存传输，所以计算整个 $Z$ 需要 $O(N^3/B + N^2)$ 次内存传输。

反之，我们用**分块矩阵乘法（blocked matrix multiplication）算法**（不是 Strassen）。注意关键块应**连续存储**。我们得到递归式

```math
MT(N) = 8MT(N/2) + O(N^2/B + 1)
```

第一项是递归的子矩阵乘法，第二项是矩阵加法，需要扫描矩阵。

同样，我们可以有不同的基例：
- 弱：$MT(O(1)) = O(1)$
- 更好：$MT(O(B)) = O(1)$
- **甚至更好：$MT(\sqrt{M/3}) = O(M/B)$**

第三种情况代表**三个涉及的矩阵能一起放进缓存**的情形。因此，要乘它们，我们只需一次扫描把它们全部载入缓存。

若画出递归树，这一次**每层的成本几何递增**：$N^2/B,\; 8(\frac{N}{2})^2/B,\; 8^2(\frac{N}{4})^2/B, \ldots$。因此，**叶层成本主导**，总成本 = 每叶成本 × 叶数，

```math
MT(N) = O(M/B) \cdot 8^{O(\lg N/\sqrt{M})} = O(M/B) \cdot O((N/\sqrt{M})^3) = O\left(\frac{N^3}{B\sqrt{M}}\right)
```

> <span style="color:#1e8449;">**[note] Note（译者注，分块矩阵乘法的缓存无关分析）:**</span>
> 这条注要回答两件事：基本算法传输数的分母里为什么只有一个 $B$，分块又凭什么把它变成 $B\sqrt{M}$。
>
> 先看基本算法为什么只能做到 $N^{3}/B$。算 $Z[i][j]$ 要读 $X$ 的第 $i$ 行和 $Y$ 的第 $j$ 列，共 $2N$ 个字。算完 $Z$ 的一整行时，$X$ 的那一行还留在缓存里，空间局部性管用；但 $Y$ 的每一列都是新数据，除非 $M \ge N^{2}$ 让整个 $Y$ 都住得下，否则每算一个元素就要重新付 $N/B$ 次传输。$N^{2}$ 个输出元素累积起来就是 $N^{3}/B$。分母里只有 $B$，因为每次复用的跨度是「一行」，最多也就是 $B$ 个字。
>
> 分块把复用的跨度换成了「一块 $\sqrt{M}$ 见方的子矩阵」。递归到叶子时，$X$、$Y$、$Z$ 的三个子块一起住进缓存，块里那 $M$ 个字在乘完之前不会被换出去，复用的次数是 $O(\sqrt{M})$，于是每次 transfer（传输）摊到 $\sqrt{M}$ 个乘加上，分母从 $B$ 变成 $B\sqrt{M}$。这不是常数优化而是阶的改进：同一份代码换台机器，$\sqrt{M}$ 自动跟着变，不用重编译，也不用重新选参数。
>
> 递归树的算术要算干净。$MT(N) = 8MT(N/2) + O(N^{2}/B+1)$：第 $d$ 层有 $8^{d}$ 个规模 $N/2^{d}$ 的子问题，每个的矩阵加法扫描成本是 $(N/2^{d})^{2}/B$，层总成本 $8^{d}N^{2}/(4^{d}B) = 2^{d}N^{2}/B$，每层翻一倍，所以叶子主导。叶子在第 $\log_{2}(N/s)$ 层，叶子数 $8^{\log_{2}(N/s)} = (N/s)^{3}$，每个叶子付 $O(M/B)$，总计 $O\left(\frac{M}{B}\left(\frac{N}{s}\right)^{3}\right)$。取 $s = \sqrt{M/3}$ 即得 $O\left(\frac{N^{3}}{B\sqrt{M}}\right)$。
>
> 为什么基例里藏着一个 3？一次乘法要同时住三个矩阵块，每块 $s^{2}$ 个字，$3s^{2} \le M$ 给出 $s \le \sqrt{M/3}$。取成 $\sqrt{M}$ 会让第三块被挤出缓存，每层都多一次传输。这个 3 看着小，但它说明基例不是「差不多就行」，而是由缓存容量的精确除法定出来的；同理 $M/B$ 也不是随便写的，它是一整块缓存装满时正好需要的传输次数。
>
> 代数字验一遍。$N = 4096$、$M = 10^{5}$ 个字、$B = 16$ 个字：$s = \sqrt{33333} \approx 182.6$，$\log_{2}(4096/182.6) \approx 4.49$，叶子数 $8^{4.49} \approx 1.13\times 10^{4}$，每叶子 $M/B = 6250$ 次传输，总计约 $7.1\times 10^{7}$。渐近公式给 $N^{3}/(B\sqrt{M}) = 6.87\times 10^{10}/(16 \times 316.2) \approx 1.36\times 10^{7}$，两者差 5.2 倍，正好是 $3^{3/2} = 5.196$ 这个常数——阶对了，常数可以差五倍，读大 O 记号时不该指望它。再看边界：若 $N \le s$，矩阵本身装得下，叶子数 1，总传输是 $O(M/B)$ 而不是 $N^{3}/(B\sqrt{M})$，基例在 $N$ 小于缓存尺度时接管，这正是递归树被剪断的位置。同一组数下基本算法是 $N^{3}/B + N^{2} \approx 4.3\times 10^{9}$，比分块多三百倍；这还是乐观估计，它假设 $X$ 的行与 $Y$ 的列都能顺序读，行主序与列主序混用时每次跳块都要重开传输，真实代价还要再差一个量级。
>
> 历史坐标记两笔。1999 年 Frigo、Leiserson、Prokop、Ramachandran 在 FOCS 发表 "Cache-Oblivious Algorithms"，把「不知道 $B$ 也能最优」从猜想做成一套方法；同一年 Prokop 的 MIT 硕士论文把这个模型展开成完整报告。而 1981 年 Hong 与 Kung 用 red-blue pebble game（红蓝石子游戏）在外部内存模型里证明了矩阵乘法的输入输出下界 $\Omega(N^{3}/(B\sqrt{M}))$。两件事放在一起才看得见分量：最优上界与下界在同一个阶上相遇，而达到上界的算法根本不知道 $B$ 与 $M$ 是多少。讲义专门注明「不是 Strassen」也值得说清——Strassen 1969 年在 Numerische Mathematik 上把乘法次数从 8 降到 7，走代数路线省运算；这里走数据移动路线省 transfer（传输），两条路线正交，可以叠加。
>
> 跨课程连接：CSAPP 第 6 章的 loop tiling（循环分块）把循环切成 $8\times 8$ 或 $16\times 16$ 的 tile（分块），你在那里必须先量出 cache（缓存）有多大才能选尺寸；这里的递归版本不量也知道，因为每层递归自动匹配当层，同一份代码在 L1、L2、DRAM（动态随机存储器）三个层级同时接近最优。差别就在这一点：tile（分块）的尺寸是编译期常数，递归的分块尺度由递归深度隐式决定，运行期才定下来。
>
> 所以「叶层主导」的操作含义是：想改进这个算法，别去优化根层的加法扫描，去优化叶子的常数。
