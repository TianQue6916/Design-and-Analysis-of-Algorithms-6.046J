<span style="color:#c0392b">**对称密钥加密（Symmetric key encryption）**</span>

```math
c = e_k(m) \qquad m = d_k(c)
```

这里 $c$ 是**密文（ciphertext）**，$m$ 是**明文（plaintext）**，$e$ 是**加密函数**，$d$ 是**解密函数**，$k$ 是**秘密密钥（secret key）**。$e, d$ 置换并反置换**所有消息的空间**。

**可逆操作（Reversible operations）**：$\oplus$、$+/-$、左移/右移。

**对称算法（Symmetric algorithms）**：AES、RC5、DES

> <span style="color:#1e8449;">**[note] Note（译者注，对称加密）:**</span> symmetric encryption（对称加密）要回答的设计问题是：同一个 secret key（秘密密钥）既喂给加密函数 $e_k$ 又喂给解密函数 $d_k$，而且 $d_k$ 必须是 $e_k$ 的逆映射。把这句话拆开看，加密是对消息空间施加一个 permutation（置换），解密必须把这个置换撤销；这里有一条不能省的前提 —— 若 $e_k$ 不是 bijection（双射），两条不同的 plaintext（明文）可能映到同一个 ciphertext（密文），接收方就无从分辨该还原哪一条，信息已经在加密这一步被永久销毁了。所以「可逆」不是工程上的好习惯，而是信息守恒的硬要求：plaintext（明文）的每一 bit（比特）都必须在 ciphertext（密文）里以某种可逆方式被保存下来，加密只能改变「谁能读」，不能改变「能读出多少」。
>
> 可逆操作只算积木，本身还不是密码。XOR（异或）满足 $a \oplus k \oplus k = a$，加法满足 $(m+k)-k = m$，循环移位满足左移三格再右移三格回到原状 —— 这些都是 permutation（置换）或能拼出置换。但如果只做 $c = m \oplus k$，安全性就完全押在 $k$ 的随机性与长度上，这就是 one-time pad（一次性密码本）的全部内容；AES（高级加密标准）换了一条路：它把这些廉价运算与 S 盒（非线性替换表）混合、重复十轮以上，使得改动一个 bit（比特）会在两三轮内扩散到整块，于是用 128 bit（比特）的短 secret key（秘密密钥）模拟出极长的等价密钥材料。区别在于：前者靠密钥长度换安全，后者靠结构混淆换安全。
>
> 算一次就明白为什么 key space（密钥空间）的大小是唯一不能打折的指标。DES（数据加密标准）的 secret key（秘密密钥）只有 56 bit（比特），共 $2^{56} \approx 7.21 \times 10^{16}$ 把。取一台每秒试 $10^{9}$ 把的通用机器，穷举要 $7.21 \times 10^{7}$ 秒，折合约 834 天；而 1998 年 EFF（电子前沿基金会）造的专用机 Deep Crack 花 25 万美元、约 1000 片定制芯片，用 56 小时就穷举完，反推速率是 $2^{56} / (56 \times 3600) \approx 3.6 \times 10^{11}$ 把每秒。同样的速率用在 AES（高级加密标准）的 128 bit（比特）密钥上：$2^{128} \approx 3.4 \times 10^{38}$，需要 $9.5 \times 10^{26}$ 秒，约 $3 \times 10^{19}$ 年，比宇宙年龄 $1.38 \times 10^{10}$ 年还大九个数量级。这不是「快一点」的差别，而是从「一天」跨到「宇宙尺度」—— secret key（秘密密钥）每加一个 bit（比特），穷举成本翻一倍，所以标准从 56 挪到 128，而不是挪到 64。
>
> 再往前一步，Shannon（香农）在 1949 年证明：要达到 perfect secrecy（完美保密），secret key（秘密密钥）的 entropy（熵）不能小于消息的 entropy（熵）。用数字感受这个代价：加密一份 1 GB 的文件，若采 one-time pad（一次性密码本），就要 1 GB 的真随机 secret key（秘密密钥），而且一次都不许复用 —— 复用两次时，两条 ciphertext（密文）相 XOR（异或）会把 $k$ 消掉，只剩两条 plaintext（明文）的 XOR（异或），统计结构立刻暴露。这就是「信息论安全」与「计算安全」的分界：前者不需要任何计算假设，但密钥管理代价与消息等长；后者用短 secret key（秘密密钥）加一个计算困难假设换实用性。你在 Cover 的信息论里会看到这条下界的形式化版本 $H(K) \ge H(M)$。
>
> 跨课程连接有两处。其一是 6.042J 的双射与逆函数：那里证明有限集合上单射必是双射，所以只要 $e_k$ 是单射就自动可逆；密码学多要一层 —— 逆映射存在还不够，还要「没有 $k$ 时算不出逆映射」，即 one-way function（单向函数）的不可求逆性，而与纯数学的区别正在这里：双射是存在性命题，可证明；单向函数是复杂性命题，其存在性至今未被证明（若 $P = NP$ 则一个都不存在）。其二是 CSAPP 第 2 章的位级表示：XOR（异或）、掩码、移位在 x86 上各是一条指令，`xor` 的自反性让加密与解密在机器层面共享同一段代码，这是很多实现里只有一个例程的原因；区别在于 CSAPP 关心指令的延迟与溢出语义，密码学关心的是把同样的指令迭代足够多轮之后的统计性质。
>
> 回到正文：对称加密的全部优点（快、实现短、能用硬件加速）都建立在「双方已经共享 $k$」这个前提上，而这个前提无法由对称加密自己生产出来。于是下一节的问题被逼出来了：怎样在公开 channel（信道）上，先从零造出一个 $k$。

<span style="color:#c0392b">**密钥管理问题（Key Management Question）**</span>

**秘密密钥 $k$ 如何交换/共享？**

Alice 想给 Bob 发一条消息。Alice 和 Bob 之间有**海盗（pirates）**，他们会拿走**未上锁盒子**里的任何密钥或消息，但**不碰上了锁的盒子**。Alice 怎样才能把消息或密钥发给 Bob（且海盗不知道发了什么）？

**解法（Solution）**：
- Alice 把 $m$ 放入盒子，用 $k_A$ 上锁
- 盒子寄给 Bob

<span style="color:#c0392b">**密钥管理问题（续）**</span>

- Bob 用 $k_B$ 给盒子**再加一把锁**
- 盒子寄回 Alice
- Alice 解开 $k_A$
- 盒子寄给 Bob
- Bob 解开 $k_B$，读取 $m$

注意这个方法依赖**锁的可交换性（commutativity）**：即，上锁与解锁操作的**顺序无关紧要**。

> <span style="color:#1e8449;">**[note] Note（译者注，双重锁方案）:**</span> 海盗问题是个把死结摆在桌上的教学隐喻：「海盗不碰上了锁的盒子」等于公开 channel（信道）上的窃听者只能看到 ciphertext（密文）、看不到 plaintext（明文），而且这意味着攻击者被动而诚实 —— 他只读不换，这一点后面讲中间人时会专门被推翻。Alice 与 Bob 的「双锁往返」要成立，形式化的要求是这四次操作的复合等于恒等映射：$d_{k_B} \circ d_{k_A} \circ e_{k_B} \circ e_{k_A} = \mathrm{id}$
>
> 单靠 $d_{k_A} \circ e_{k_A} = \mathrm{id}$ 与 $d_{k_B} \circ e_{k_B} = \mathrm{id}$ 是推不出上面那行的，因为函数复合不满足交换律，中间两个 $d_{k_A}$ 与 $e_{k_B}$ 挨在一起抵消不掉。要把它消掉，就必须能把这些操作**重新排序**：一旦四种操作两两可交换，上面的式子可以改写为 $(d_{k_B} \circ e_{k_B}) \circ (d_{k_A} \circ e_{k_A}) = \mathrm{id}$，恒等式才成立。这就是为什么正文特别点出 commutativity（可交换性）——不是修辞，而是这个协议唯一的承重墙。反过来看失败的样子：若两把锁不可交换，Alice 解开自己的锁之后盒子里剩下的不是 $e_{k_B}(m)$，而是被两次置换搅乱的 $d_{k_A}(e_{k_B}(e_{k_A}(m)))$，Bob 再用 $k_B$ 去开，得到的东西既不是 $m$ 也不是任何有意义的中间态，整个往返白跑。
>
> 关键问题是：随机挑两把锁，碰巧可交换的概率有多大？在一个只有 3 bit（比特）的小 block（分组）上能把这件事数清楚：块内 8 个可能值，permutation（置换）共 $8! = 40320$ 个。固定一把锁是 8 循环 $\sigma$，能与之交换的 $\tau$ 必须属于 $\sigma$ 的中心化子，而 8 循环的中心化子只有它的 8 个幂，于是概率是 $8 / 40320 = 1/5040 \approx 0.0198\%$。块长大到 8 bit（比特）时置换数是 $256!$，中心化子大小仍不超过 256，概率落到 $10^{-504}$ 量级。结论很硬：在密码学规模的 block（分组）上，「碰巧可交换」的概率是零，可交换性只能来自**设计**，不能来自运气。AES（高级加密标准）这类分组密码里的每一轮都是非线性混淆，两把不同的 secret key（秘密密钥）给出的 permutation（置换）不共享任何结构，所以对称密码的「锁」天生不可交换，双锁方案在对称密码上走不通。
>
> 在可交换锁还没被发明之前，历史上真正的替代品是 Merkle 在 1978 年前后提出的谜题方案，它用「计算量的不对称」顶替「代数上的可交换」。算一遍就有体感：Alice 造 $N = 10^{6}$ 个谜题，每个谜题用 20 bit（比特）的小 secret key（秘密密钥）加密（$2^{20} \approx 10^{6}$ 个候选）。Bob 随机挑一个谜题暴力解，期望试 $2^{19} \approx 5.2 \times 10^{5}$ 次就拿到该谜题的 key（谜题内容里写明编号与真正的 session key（会话密钥）），然后回传 20 bit（比特）的编号。Alice 的开销是 $10^{6}$ 次加密，Bob 是 $5.2 \times 10^{5}$ 次解密，而 Eve 并不知道 Bob 挑的是哪一个，必须把 $10^{6}$ 个谜题全部解开才能定位，代价 $10^{6} \times 2^{19} \approx 5.2 \times 10^{11}$ 次。攻击者与合法方差 $N = 10^{6}$ 倍，这确实是从零建立密钥，但差距只是**二次**的：想拿到 $2^{128}$ 的安全度就要 $N = 2^{64}$ 个谜题，Alice 自己就得做 $2^{64}$ 次加密，方案直接不可用。这个二次 gap（差距）正是它被公钥密码淘汰的定量原因。
>
> 跨课程连接有三处。其一是 Strang 18.06 的矩阵乘法：$AB \ne BA$ 是线性算子复合不交换的标准例子，它在这里的对应物是 permutation（置换）复合不交换；区别在于矩阵是否可交换有可判定的充要条件（可同时对角化），而密码学根本不去判定这件事，直接在设计阶段就把可交换性写死。其二是 6.042J 的函数复合与双射，那里你只关心「有没有逆」，这里多要一条「逆能不能在不掌握 key（密钥）的情况下算出来」。其三是 CSAPP 第 11 章的 socket（套接字）与 TCP（传输控制协议）栈：双锁方案要 3 次传输、4 次加解密操作，落到网络上就是 2 个 RTT（往返时延）量级的握手，而今天 TLS（传输层安全）的握手在 1 个 RTT（往返时延）内完成 —— 协议轮数不是审美问题，它直接决定连接建立延迟。
>
> 回到正文：Diffie-Hellman 的聪明之处，是不去造「可交换的锁」，而是找一个本身满足交换律的代数运算 $x \mapsto x^{a}$，把可交换性变成恒等式 $(g^{a})^{b} = (g^{b})^{a}$，于是前面那个数到 $10^{-504}$ 的概率问题被彻底绕开了。

<span style="color:#c0392b">**Diffie-Hellman 密钥交换（Diffie-Hellman Key Exchange）**</span>

$G = \mathbb{F}_p^*$

这里 $\mathbb{F}_p^*$ 是**有限域（finite field）**（模素数 $p$）。$*$ 表示**仅可逆元素**（$\{1, 2, \ldots, p-1\}$）。

| Alice | 公开 | Bob |
|:---|:---:|:---:|
| | $g$ 公开 | |
| | $p$ 公开 | |
| | $2 \le g \le p-2$ | |
| 选择 $a$ | | 选择 $b$ |
| 计算 $g^a$ | $g^a$ | |
| | $g^b$ | 计算 $g^b$ |
| | $1 \le a, b \le p-2$ | |
| Alice 可计算 $(g^b)^a \bmod p = k$ | | Bob 可计算 $(g^a)^b \bmod p = k$ |

假设**离散对数问题（Discrete Log Problem）是困难的**（给定 $g^a$，计算 $a$）且 **Diffie-Hellman 问题是困难的**（给定 $g^a, g^b$，计算 $g^{ab}$）。

**我们能攻击它吗？中间人（Man-in-the-middle）**：
- Alice 不知道她在与 Bob 通信。
- Alice 同意与 Eve 做密钥交换（以为她是 Bob）。
- Bob 同意与 Eve 做密钥交换（以为她是 Alice）。
- Eve 能看到所有通信。

> <span style="color:#1e8449;">**[note] Note（译者注，Diffie-Hellman）:**</span> Diffie-Hellman 要解决的设计问题是：两方之间**一个共享秘密都没有**，却要在全公开的 channel（信道）上造出一个只有他们知道的 secret key（秘密密钥）。它的机制只有一句话 —— 找一个正着算便宜、倒着算昂贵的函数，让双方各自把一个秘密塞进去、把结果喊出来、再把自己的秘密塞进对方喊出的结果里。具体到正文的方案：公共参数是素数 $p$ 与 generator（生成元）$g$，Alice 私藏 $a$ 只发 $g^{a}$，Bob 私藏 $b$ 只发 $g^{b}$，两人各算 $(g^{b})^{a} = (g^{a})^{b} = g^{ab} \bmod p$。窃听者手里有 $p, g, g^{a}, g^{b}$，但要从 $g^{a}$ 反求 $a$ 就是 discrete logarithm（离散对数）问题；而即便不反求 $a$，直接算出 $g^{ab}$ 也做不到 —— 这两条都是假设，不是定理。
>
> 把数字代到底。取 $p = 23$、$g = 5$、$a = 6$、$b = 15$。Alice 发 $5^{6} \bmod 23$：用平方-乘，$5^{2} \equiv 2$、$5^{4} \equiv 4$，所以 $5^{6} = 5^{4} \cdot 5^{2} \equiv 4 \times 2 = 8$。Bob 发 $5^{15} \bmod 23$：拆成 $5^{8} \cdot 5^{4} \cdot 5^{2} \cdot 5^{1}$，其中 $5^{8} = (5^{4})^{2} \equiv 16$，连乘 $16 \times 4 \times 2 \times 5 = 640 \equiv 640 - 27 \times 23 = 19$。于是 A 拿到 19，算 $19^{6} \bmod 23$：$19 \equiv -4$，$(-4)^{2} = 16$、$(-4)^{4} \equiv 3$、$(-4)^{6} \equiv 3 \times 16 = 48 \equiv 2$；B 拿到 8，算 $8^{15} \bmod 23$：$8^{2} \equiv 18$、$8^{4} \equiv 2$、$8^{8} \equiv 4$，连乘 $4 \times 2 \times 18 \times 8 = 1152 \equiv 2$。两边都得 2，secret key（秘密密钥）$k = 2$。整个公开过程只泄露 23、5、8、19 四个数。
>
> 这个玩具规模之所以不安全，原因不在 $p$ 小，而在 $p - 1$ 太光滑（分解得太干净）：$p - 1 = 22 = 2 \times 11$，Pohlig-Hellman 的思路是先在大小为 2 和大小为 11 的两块里分别求 $a$ 的剩余，工作量是 $2 + 11 = 13$ 次尝试，而不是 22 次，然后拼起来 —— 代价由「最大素因子的规模」而不是「$p$ 的规模」决定。这就解释了为什么真实参数必须要求 $p - 1$ 含一个巨大的素因子，常用做法是取 safe prime（安全素数）$p = 2q + 1$（$q$ 也是素数），此时最大素因子约 $2^{2047}$，拼接法直接失效，只能对 $2^{2047}$ 大小的空间做通用搜索。所以正文那句「假设 discrete logarithm（离散对数）问题困难」不是自然事实，而是**参数条件**。
>
> 正向有多便宜？6.006 学的平方-乘给了答案：2048 bit（比特）的指数只需约 $2048$ 次平方加约 $1024$ 次乘法，共 $3072$ 次模乘；一个 2048 bit（比特）的数在 64 bit（比特）机器上是 32 个 word（机器字），一次 $32 \times 32$ 的竖式模乘约 $32^{2} \approx 10^{3}$ 次乘加，折合微秒量级，于是整次幂运算落在 $1$ 到 $3$ 毫秒 —— 这就是一笔灰色小钱，而倒过来算要 $2^{2047}$ 量级，这就是 one-way function（单向函数）的全部含义。注意这里有个不常被点明的裂缝：单向函数是否**存在**至今没有被证明（若 $P = NP$ 则不存在任何单向函数），所以整座公钥大厦站在一个未证命题上。
>
> 中间人攻击要单独算一笔账：Eve 不需要破解任何数学难题，她只要在 Alice 与 Bob 之间各做**一次完整的 Diffie-Hellman**，成本就是两次毫秒级幂运算再加两次转发。她随后与 Alice 共享 $k_{AE}$、与 Bob 共享 $k_{BE}$，读改一切而双方毫无察觉。也就是说这套协议只保证「传输中不泄露」，不保证「对面是谁」—— 认证是一个**独立**问题，不能靠加密顺手解决。TLS（传输层安全）的做法是让服务器出示 certificate（证书），证书里绑定公钥并由可信方出具 digital signature（数字签名），把「我的公钥是这个」这句声明本身保护起来。
>
> 跨课程连接：6.042J 的欧拉定理给你 $a^{\varphi(n)} \equiv 1$ 这个工具，它保证 $g^{a}$ 的取值落在一个有限集合里、并且可以被高效判定；区别在于 6.042J 用它算 $a^{b} \bmod n$ 的值（正向），这里用它说明正向可行、并把困难度完全推给逆向。CS144 里 socket（套接字）建连、TLS（传输层安全）握手那几行日志背后就是这段算术。历史上 Diffie 与 Hellman 1976 年发表这套想法（同期的 Merkle 谜题方案更早但更弱），而 GCHQ（英国政府通信总部）的 Ellis、Cocks、Williamson 在 1969 到 1974 年间已独立得到同类结果，因保密未公开，1997 年才解密。
>
> 回到正文：Diffie-Hellman 已经能造出 shared key（共享密钥），但它做不到「先把消息发过去、对方之后再解」。下一步要的 public key encryption（公钥加密）需要的是单向函数的**陷门版本** —— 正着算容易、没有陷门时反着算难，有陷门时反着算也容易。

<span style="color:#c0392b">**公钥加密（Public Key Encryption）**</span>

```math
\text{message} + \text{public key} = \text{ciphertext}
```

```math
\text{ciphertext} + \text{private key} = \text{message}
```

两个密钥需要以**数学方式关联**。知道公钥应该**无法推导出私钥**的任何信息。

<span style="color:#c0392b">**RSA**</span>

- Alice 选两个大的**秘密素数** $p$ 和 $q$。
- Alice 计算 $N = p \cdot q$。
- 选择**加密指数** $e$，满足 $\gcd(e, (p-1)(q-1)) = 1$，$e = 3, 17, 65537$。
- Alice 的**公钥** = $(N, e)$。
- Alice 用**扩展欧几里得算法（Extended Euclidean Algorithm）**求**解密指数** $d$，使 $e \cdot d \equiv 1 \bmod (p-1)(q-1)$。
- Alice 的**私钥** = $(d, p, q)$（存储 $p$ 和 $q$ 并非绝对必要，但为了效率我们这样做）。

<span style="color:#c0392b">**RSA 的加密与解密（Encryption and Decryption with RSA）**</span>

```math
c = m^e \bmod N \quad \text{（加密 encryption）}
```

```math
m = c^d \bmod N \quad \text{（解密 decryption）}
```

<span style="color:#c0392b">**为什么有效（Why it works）**</span>

令 $\varphi = (p-1)(q-1)$。因为 $ed \equiv 1 \bmod \varphi$，存在整数 $k$ 使 $ed = 1 + k\varphi$。分两种情况：

**情形 1（Case 1）** $\gcd(m, p) = 1$。由**费马小定理（Fermat's theorem）**，$m^{p-1} \equiv 1 \bmod p$。于是

```math
m^{ed} = m^{1+k(p-1)(q-1)} = m \cdot (m^{p-1})^{k(q-1)} \equiv m \bmod p
```

<span style="color:#c0392b">**RSA（续）**</span>

**情形 2（Case 2）** $\gcd(m, p) = p$。这意味着 $m \bmod p = 0$，所以 $m^{ed} \equiv m \bmod p$。

因此，两种情况下都有 $m^{ed} \equiv m \bmod p$。类似地，$m^{ed} \equiv m \bmod q$。因为 $p, q$ 是不同的素数，$m^{ed} \equiv m \bmod N$。所以 $c^d = (m^e)^d \equiv m \bmod N$。$\square$

<span style="color:#c0392b">**RSA 的困难性（Hardness of RSA）**</span>

- **因子分解（Factoring）**：给定 $N$，分解成 $p, q$ 是困难的。
- **RSA 问题（RSA Problem）**：给定满足 $\gcd(e, (p-1)(q-1)) = 1$ 的 $e$ 和 $c$，找到使 $m^e \equiv c \bmod N$ 的 $m$。

<span style="color:#c0392b">**NP 完全性（NP-completeness）**</span>

- **$N$ 是合数且有一个因子落在某个区间内吗？** —— 是否 NP 完全**未知**。
- **图可以 $k$-着色吗？** 换句话说：能否给每个顶点分配 $k$ 种颜色之一，使**没有一条边连接的两个顶点共享相同颜色**？—— **NP 完全**。
- **给定一堆 $n$ 个物品，各有权重 $w_i$，能否把物品放进背包使总重恰好为 $S$？** —— **NP 完全**。

<span style="color:#c0392b">**NP 完全性与密码学（NP-completeness and Cryptography）**</span>

- **NP 完全性**：关于**最坏情形（worst-case）**复杂度。
- **密码学**：想要一个**参数选取得当**的问题实例，它在**平均情形（average）**下是困难的。

**大多数背包密码系统都失败了**。

判断一个图是否 **3-可着色** 是 NP 完全的，但**平均情形下非常容易**。这是因为**超过一定规模的随机图通常不是 3-可着色的**！

考虑用标准**回溯搜索（backtracking search）**判断 3-可着色性：
- 把顶点排序 $v_1, \ldots, v_t$。颜色 = $\{1, 2, 3\}$
- 按顶点顺序遍历图。
- 访问一个顶点时，选择**可行**的最小颜色。
- 若卡住，**回溯**到上一个选择，尝试下一个选择。

<span style="color:#c0392b">**NP 完全性与密码学（续）**</span>

- 第 1 个顶点的颜色用完 → 输出「NO」
- 最后一个顶点成功着色 → 输出「YES」

在 $t$ 个顶点的**随机图**上，平均遍历的顶点数 $< 197$，**与 $t$ 无关**！

> <span style="color:#1e8449;">**[note] Note（译者注，最坏 vs 平均：密码学的核心张力）:**</span> 这一页要拆的，是密码学与算法理论之间那条缝：NP-complete（NP 完全）是关于 worst-case（最坏情形）的断言，而密码学要的是 average-case（平均情形）困难。前者说的是「存在至少一个难实例」，后者说的是「**随机**抽一个实例也难」。这两句话方向完全相反，中间没有蕴含关系。
>
> 为什么 3-着色恰好是反例而不是正例，可以算出来。在 $n$ 个顶点、每条边独立以 $1/2$ 概率出现的 random graph（随机图）上，合法的三染色方案数的期望是 $3^{n} \cdot 3^{-n(n-1)/2} = 3^{\,n - n(n-1)/2}$：分子 $3^{n}$ 是全部染色方案，一条边两端同色的概率是 $1/3$，边互相独立所以乘 $C(n,2)$ 次 $1/3$。取 $n = 10$，指数是 $10 - 45 = -35$，期望合法染色数 $3^{-35} \approx 6.5 \times 10^{-17}$ —— 一个远小于 1 的数，意味着「存在合法染色」的概率也远小于 1。要使这个期望不小于 1，必须 $n - n(n-1)/2 \ge 0$，解出来只有 $n \le 3$。换句话说：只要顶点数超过 3，随机图几乎必然不可三着色，原因不在全局安排，而在**局部已经很密**。再看 $K_4$（四顶点两两相连的小结构）：$n = 10$ 时它出现的期望次数是 $210 / 64 \approx 3.28$，故至少出现一次的概率约 $1 - e^{-3.28} \approx 0.962$。三个颜色根本喂不饱一个 $K_4$，所以回溯搜索走不了几步就会在同一片邻域里撞死，答案「NO」是**局部**被判定的。
>
> 这就把正文那个「平均遍历顶点数小于 197，且与 $t$ 无关」说清楚了：backtracking search（回溯搜索）失败得快，是因为局部密度给出了不可染的证据，与图的总规模无关 —— $t$ 从一万涨到一亿，搜索深度几乎不变，因为它在第 197 层附近就已经遇到矛盾。密码学的输赢全在这条性质上：一个密码系统的密文分布如果像随机图一样「局部就暴露结构」，那么攻击者根本不需要面对你精心设计的最坏实例，他只要在平均实例上跑一遍就赢了。
>
> 为什么「绝大多数背包密码系统失败」，定量理由也在这里。设计者的推理链是：一般背包是 NP-complete（NP 完全）→ 随机实例应该也难 → 可以做密码。但第一环只保证**存在**难实例，第二环是完全没有依据的跳跃；Merkle-Hellman 的公钥序列是从超递增序列做模乘变换得来的，随机性只是「看起来乱」，其分布里残留着可被统计方法抓住的算术结构，于是一族专门针对该分布的算法（后文要讲的格基约简那一路）在平均实例上就把它解掉了。要填上这个跳跃，需要的是从最坏情形到平均情形的 reduction（归约）：证明「若能在随机实例上破解，则能在**任意**实例上破解」。现代格密码正是靠这类归约站住的 —— Regev 在 2005 年给出一族问题的量子归约，这也是它比背包方案可信得多的原因 —— 不是因为格更难，而是因为它敢把最坏情形假设兑现成平均情形保证。
>
> 一个可复用的证明策略模板值得记下来：想证明「随机对象几乎不具备性质 $\mathcal{P}$」，就去算具备 $\mathcal{P}$ 的对象的**期望个数**；一旦期望远小于 1，由 Markov 不等式就有「具备 $\mathcal{P}$ 的概率远小于 1」。这叫 first moment（一阶矩）方法，上面那一步就是它的标准用法。
>
> 跨课程连接有三处，注意方向。CLRS 的快速排序是**平均好、最坏坏**（平均 $O(n \log n)$，最坏 $O(n^{2})$），密码学要的正好相反 —— 最坏可以坏，但平均不能好；这一点差别决定了你不能拿排序算法的分析经验类推密码安全。Strang 18.06 的 condition number（条件数）$\kappa(A)$ 描述的是「输入扰动被放大多少倍」，它的典型值（平均输入）与最坏输入差得很远，和这里「平均与最坏分离」是同一个现象在数值线性代数里的版本；区别是那里我们只关心最坏放大（因为误差会挑最坏的方向），密码学关心平均。CSAPP 第 6 章的 cache（高速缓存）同理：平均命中率高，但存在让它崩到近零的访问序列。
>
> 回到正文：讲义的这句话不是在贬低 NP-complete（NP 完全）的价值，而是在划清用途 —— 它适合证明「没有通用多项式算法」这类**悲观**结论，不适合承诺「我造的实例对所有人都难」。密码学必须自己把平均情形的困难度**证明**出来，这是它比一般算法设计更贵、也更少成功案例的根源。

<span style="color:#c0392b">**背包密码学（Knapsack Cryptography）**</span>

**一般背包问题（General knapsack problem）**：NP 完全。

**超递增背包（Super-increasing knapsack）**：**线性时间**可解。在此问题中，权重受如下约束：

```math
w_j \ge \sum_{i=1}^{j-1} w_i
```

<span style="color:#c0392b">**Merkle-Hellman 密码系统（Merkle Hellman Cryptosystem）**</span>

**私密变换（Private transform）**

```math
\text{私钥} \to \text{超递增背包问题} \xrightarrow{\text{私密变换}} \text{「困难」的一般背包问题} \to \text{公钥}
```

**变换（Transform）**：两个私有整数 $N, M$，满足 $\gcd(N, M) = 1$。把序列中所有值乘以 $N$ 再取模 $M$。

**例（Example）**：$N = 31$，$M = 105$，私钥 $=\{2, 3, 6, 14, 27, 52\}$，公钥 $=\{62, 93, 81, 88, 102, 37\}$。

<span style="color:#c0392b">**Merkle-Hellman 示例（Merkle Hellman Example）**</span>

消息 = `011000` `110101` `101110`

密文：
- `011000`：$93 + 81 = 174$
- `110101`：$62 + 93 + 88 + 37 = 280$
- `101110`：$62 + 81 + 88 + 102 = 333$
- = 174, 280, 333

接收者知道 $N = 31$、$M = 105$、$\{2, 3, 6, 14, 27, 52\}$。把每个密文块乘以 $N^{-1} \bmod M$。本例中 $N^{-1} = 61 \bmod 105$。
- $174 \cdot 61 = 9 = 3 + 6 = 011000$
- $280 \cdot 61 = 70 = 2 + 3 + 13 + 52 = 110101$
- $333 \cdot 61 = 48 = 2 + 6 + 13 + 27 = 101110$

> <span style="color:#1e8449;">**[note] Note（译者注，必须澄清的 M-H 示例数字错误）:**</span> 这一页的数值有三处不自洽，不是抄写笔误那么简单 —— 每一处都能用模算术的**不变量**先验地判死，不需要试算。我逐条给出判据与正确版本。
>
> 第一处：public key（公钥）的第四项印成 88，不可能是任何变换的结果。判据是一条恒等式：设 $a_i \equiv N w_i \pmod{M}$，则由 $\gcd(N, M) = 1$ 可推出 $\gcd(a_i, M) = \gcd(w_i, M)$ —— 因为同余式两边同时乘除一个与 $M$ 互素的数，不会改变与 $M$ 的公因子集合。现在 $w_4 = 14$、$M = 105$，$\gcd(14, 105) = 7$，所以 $a_4$ 必须也是 7 的倍数；而 88 连 7 都不整除。这一条把「88 是笔误」变成了**结构性不可能**，无论 $N$ 取什么值都造不出 88。正确取 $N = 31$ 时 $a_4 = 14 \times 31 = 434 = 4 \times 105 + 14$，即 $a_4 = 14$，恰与 $w_4$ 数值相同 —— 这本身是个巧合，也容易被误当成抄错而改掉。逐项算完，正确的 public key（公钥）是 $\{62, 93, 81, 14, 102, 37\}$：$2 \times 31 = 62$、$3 \times 31 = 93$、$6 \times 31 = 186 - 105 = 81$、$27 \times 31 = 837 - 7 \times 105 = 102$、$52 \times 31 = 1612 - 15 \times 105 = 37$。
>
> 第二处：ciphertext（密文）随 public key（公钥）一起变。位模式 `011000` 取第 2、3 项，仍是 $93 + 81 = 174$；`110101` 取第 1、2、4、6 项，变成 $62 + 93 + 14 + 37 = 206$（讲义写的 280 用到了那个假的 88）；`101110` 取第 1、3、4、5 项，变成 $62 + 81 + 14 + 102 = 259$（讲义写的 333 同样含 88）。这一步的机制是显而易见的：密文是选中项的**和**，任何一项错了，含该项的每一块都错。
>
> 第三处：解密的中间值必须落在 private key（私钥）能凑出的集合里。$N^{-1} = 61$ 可以手工验：$31 \times 61 = 1891 = 18 \times 105 + 1$。于是 $174 \times 61 = 10614 \equiv 9 \pmod{105}$，而 $9 = 3 + 6$ 正是超递增序列里第 2、3 项之和；$206 \times 61 = 12566 \equiv 71$，而 $71 = 2 + 3 + 14 + 52$ 恰好是第 1、2、4、6 项之和；$259 \times 61 = 15799 \equiv 49$，而 $49 = 2 + 6 + 14 + 27$ 是第 1、3、4、5 项之和。三个都回到了原 bits（比特）。对照讲义写的 70 与 48：70 被拆成 $2 + 3 + 13 + 52$，而 private key（私钥）里根本没有 13 这一项；48 拆成 $2 + 6 + 13 + 27$，同样凭空多出 13。这一处最容易骗过人，因为 70 与 48 都是合法的整数，错只错在「拆解时用了一个不存在的项」。
>
> 第四处更要紧：这组 private key（私钥）只是弱超递增，严格条件被破坏了。讲义写的是 $w_j \ge \sum_{i<j} w_i$，而这个例子满足的是等号：$2 + 3 + 6 + 14 + 27 = 52 = w_6$，即 $w_6$ 不大于前五项之和。后果不是学术瑕疵，而是**解密直接失效**：值 52 有两种表示，$\{52\}$ 与 $\{2, 3, 6, 14, 27\}$。演示一次代价：明文块 `000001`（只选第 6 项）对应密文 37，$37 \times 61 \equiv 52$，贪心取 52 得 `000001`，正确；但明文块 `111110`（选前五项）对应密文 $62 + 93 + 81 + 14 + 102 = 352$，$352 \times 61 = 21472 \equiv 52$，贪心同样先取 52 得 `000001`，**解错了**。两块不同的明文被映射到同一个可解值上，接收方无法分辨。这正是「严格超递增」存在的理由：只有 $w_j > \sum_{i<j} w_i$ 时，大于等于 $w_j$ 的目标值才**必须**包含 $w_j$，贪心的每一步才是被迫的唯一选择。
>
> 跨课程连接：CLRS 第 16 章证明贪心正确性用的是 exchange argument（交换论证）—— 先证「存在一个最优解包含贪心选的那一项」。这里的对应物是「若目标值不小于 $w_j$，则任何解都必须含 $w_j$」，等号情形让这条断言失效，交换论证当场崩塌，所以上面那个 `111110` 的反例不是巧合而是必然。6.042J 的 gcd（最大公因子）与扩展欧几里得给你两个工具：判 $\gcd(N, M) = 1$ 与求 $N^{-1} \bmod M$（本例 $61$ 就是这么来的）；区别在于 6.042J 只要求「逆存在且能算」，密码学还要确认「逆的存在性不会泄露 $M$ 的分解」。
>
> 顺带把两个参数的选取条件补齐，这两条都是**必需**而非优化。其一是 $M > \sum_i w_i$：否则不同的子集和会在模 $M$ 之后折叠到一起，解密的第一步就失去唯一性（两个不同的 bits（比特）向量给出同一个目标值，接收方无从选择）；本例 $\sum_i w_i = 2 + 3 + 6 + 14 + 27 + 52 = 104$，$M = 105$ 只多出 1 的余量，说明这对参数是刻意凑到极限的极小例子，真实参数会让 $M$ 远大于总和。其二是 $\gcd(N, M) = 1$：$N$ 在模 $M$ 下不可逆时，接收方连「乘 $N^{-1}$ 消去变换」这一步都做不了，解密流程在第一步就断掉；顺便验一下余量，$N = 31$ 与 $M = 105 = 3 \times 5 \times 7$ 的每个素因子都不相同，所以 $31$ 在模 $105$ 下确实可逆。
>
> 还可以从打包效率看这个例子有多勉强：public key（公钥）总和 $389$，需要 9 bit（比特）的密文块来承载 6 bit（比特）的明文块，信息率 $6/9 \approx 0.667$，即膨胀了一半；而这一半的膨胀换来的安全度是零（后两页就破）。把数字独立验证一遍，比相信排版便宜得多。

> <span style="color:#1e8449;">**[note] Note（译者注，M-H 原理与「美丽但已破」）:**</span> Merkle-Hellman 在 1978 年（IEEE 信息论汇刊 24 卷 5 期，525 至 530 页）做的事情，是把 Diffie 与 Hellman 两年前只在概念上提出的 trapdoor one-way function（陷门单向函数）**第一次具体造出来**。制造手法值得逐句拆开：它不去碰「一般背包难」这条 NP-complete（NP 完全）假设，而是先造一个**一定易解**的实例 —— super-increasing（超递增）序列，用 greedy（贪心）从大到小扫一遍就还原 bits（比特）；然后对每一项做同一个模乘变换 $a_i = N w_i \bmod M$，把「易解的结构」藏进一个「看起来像一般背包」的序列里。public key（公钥）就是这串 $a_i$，private key（私钥）是超递增序列加上陷门 $N, M$ 与 $N^{-1} \bmod M$。
>
> 为什么这个伪装在**方向**上成立而**难度**上不成立，是这条注真正的核心。方向上：加密只需对选中的项求和，$n$ 项一次加法扫描，$O(n)$；解密时先乘 $N^{-1}$ 消去变换，回到超递增背包再做一次 $O(n)$ 的 greedy（贪心），于是合法方两边都线性，而攻击者看到的是 $a_i$，既不知道哪些项被选中，也还原不出超递增次序 —— 这正是陷门该有的样子。难度上：这里没有任何一步能保证「$a_i$ 的随机实例真的和一般背包一样难」，从「超递增背包易」到「变换后的背包难」这一跳，既没有证明，也没有像样的启发式支撑。M-H 的全部自信都来自「NP-complete（NP 完全）所以难」这句话，而上一页刚说明这句话方向不对。
>
> 量的判据是 density（密度）。把讲义的定义代进这个玩具例子：public key（公钥）最大项 102，$\log_2 102 \approx 6.67$，$n = 6$，于是 $d = 6 / 6.67 \approx 0.90$。这个数字很有信息量 —— 它正好落在后来被证明可攻的区间内。真实规模下会更糟：超递增要求 $w_i > \sum_{j<i} w_j$，于是 $w_i$ 至少要按 $2^{i}$ 增长，$w_n$ 约占 $n$ 个 bit（比特），分母 $\log_2(\max a_i)$ 也就约等于 $n$，因此 $d \approx 1$，**与 $n$ 无关地卡在 1 附近**。也就是说 M-H 的 density（密度）不是设计者能调的旋钮，它被超递增结构本身锁死。
>
> 破解的时间线要分清是两路攻击，混为一谈会得出错误的教训。第一路是 density（密度）攻击：Lagarias 与 Odlyzko 在 1983 年前后证明，density（密度）低于 $0.6463$ 的背包「几乎所有实例」都能用 lattice（格）上的短向量计算在多项式时间内解掉，1992 年 Coster 等人把这个阈值改进到 $0.9408$。第二路是结构攻击：Shamir 在 1982 年（会议版）与 1984 年（期刊版，IEEE 信息论汇刊 30 卷，699 至 704 页）给出针对**单次迭代**版本的 poly-time（多项式时间）攻击，切入点不是 density（密度），而是「所有块共用同一个 $N, M$」这条结构关系；M-H 之后提出的多次迭代加强版，则由 Brickell 在 1985 年前后破掉。所以「M-H 因为低密度被 LLL（格基约简算法）击败」是个流行但不精确的说法：它被两把不同的刀先后砍到，密度只是其中一把。⚠ 需回查：真实参数下 M-H 的 density（密度）究竟略高于还是略低于 $0.9408$，我未在原始论文中核实数值。
>
> 跨课程连接：CLRS 第 16 章的 greedy（贪心）算法是这里「易解」那一半的全部来源 —— 超递增背包的 $O(n)$ 解就是最朴素的贪心，从最大项开始「能取就取」；区别是 CLRS 的贪心分析对权重几乎不加条件（只要求拟阵结构或交换性质），而这里必须**人为造出**超递增序，一旦这个序被抹掉，贪心立刻失效，这也正是「易解」能被藏起来的原因。6.042J 提供模逆的算法（扩展欧几里得），CSAPP 第 2 章的打包视角则解释了这个方案的信息率为何注定难看：每块 6 个 bit（比特）明文塞进 9 个 bit（比特）密文，膨胀一半，安全度为零。
>
> 它留下的正面遗产是 LWE（容错学习）这条路。思路可以只用你已有的线性代数说清：解 $A x = b$ 是高斯消元，多项式时间，所以「线性」不能直接当密码；LWE（容错学习）的做法是给每个方程掺一点小噪声，只公开 $A$ 与 $A x + e$，于是消元时噪声被放大成误差，恢复 $x$ 变难。这与 M-H 的教训一一对应：不是「问题难所以安全」，而是「**必须证明**你发布的那个分布上难」，噪声就是那个被证明过的结构。

<span style="color:#c0392b">**美丽但已破（Beautiful but broken）**</span>

**基于格的技巧（Lattice based techniques）**可以攻破这个方案。

背包密度（density）

```math
d = \frac{n}{\max\{\log_2 w_i : 1 \le i \le n\}}
```

**格基约简（Lattice basis reduction）**可以求解**低密度**的背包。不幸的是，M-H 方案**总是**产生低密度的背包。

> <span style="color:#1e8449;">**[note] Note（译者注，格攻击与密度）:**</span> 这一页要给「美丽但已破」补上真正的机制：density（密度）不是一句形容，而是一个能让攻击**有效或失效**的相变参数。先把定义读成一句大白话：$d = n / \max_i \log_2 w_i$，分子是背包里物品的个数，分母是最大那件物品要占多少 bit（比特）。它的真正含义是「明文 bit（比特）数除以密文 bit（比特）数」再取倒数 —— 也就是这个密码系统的**信息率**的倒数，所以 density（密度）量的是「每 bit（比特）密文承载多少 bit（比特）信息」。
>
> 为什么子集和问题能被 lattice（格）攻破，构造只有三步。第一步，把每个物品变成一行基向量：第 $i$ 行前 $n$ 位是单位向量 $e_i$，最后一位放 $N w_i$（$N$ 是个足够大的整数）。第二步，把「目标值 $S$」也做成一行 $(0, \ldots, 0, N \cdot S)$。第三步，取任何一个解 $y \in \{0,1\}^{n}$，令系数 $c_i = 2y_i - 1 \in \{\pm 1\}$，则 $\sum_i c_i (\text{第 } i \text{ 行}) - k \cdot (0,\ldots,0,N)$ 的前 $n$ 位全是 $\pm 1$、最后一位是 $N(2S - \sum_i w_i) - kN$，选整数 $k$ 恰好把它清零。于是**每个解都对应格中一个长度为 $\sqrt{n}$ 的向量**。而格中随便挑一个向量，最后一位是 $N$ 的倍数、量级就是 $N$，长度差着 $N/\sqrt{n}$ 倍。
>
> 代数字看这个落差有多大。取 $n = 2$、$w = (3, 7)$、$S = 10$，解是 $y = (1,1)$；取 $N = 105$，基向量是 $(1,0,315)$ 与 $(0,1,735)$，组合 $1 \cdot (1,0,315) + 1 \cdot (0,1,735) - 10 \cdot (0,0,105) = (1, 1, 0)$，长度 $\sqrt{2} \approx 1.41$，而典型格向量长度是 105 量级，差 74 倍。同样的构造放大到 $n = 100$：解向量长度 $10$，而 $N$ 约 $2^{100} \approx 1.27 \times 10^{30}$，落差 $1.27 \times 10^{29}$ 倍 —— LLL（格基约简算法，Lenstra-Lenstra-Lovász，1982，第一个多项式时间的格基约简）只要把基「压扁」，那个唯一特别短的向量就会被挤到基向量里，解直接读出来。这就是把 subset sum（子集和）几何化之后的全貌。
>
> 那 density（密度）为什么决定成败？算一个期望值就够了。长度为 $n$ 的 0-1 向量有 $2^{n}$ 个，它们产生的和落在 $[0, \max_i w_i]$ 这个区间；若把这些和看作近似均匀，则每个目标值的期望解数是 $2^{n} / 2^{\max_i \log_2 w_i} = 2^{\,n(1 - 1/d)}$。这一行式子说明一切：$d < 1$ 时指数为负，期望解数远小于 1，**解唯一**，那个短向量在格中鹤立鸡群，LLL（格基约简算法）一眼就能抓到；$d$ 越大指数越接近 0，期望解数越接近 1，短向量开始不唯一；一旦 $d$ 明显超过 1，期望解数是天文数字，格中布满大量等长的短向量，攻击者连「哪一个才是答案」都分不出来。这就是 density（密度）相变的机制 —— 不是算法变弱了，是**问题本身变得多解**（因此也更难，密码系统的方向反而对，但设计者又需要保证自己人能解，两者拉锯）。
>
> 把这个式子代到两头。$n = 100$、$d = 0.9$ 时指数是 $100(1 - 1.111) = -11.1$，期望解数 $\approx 4 \times 10^{-4}$，几乎必然唯一，攻击可行（这正是 Lagarias 与 Odlyzko 在 1983 年前后证明 $d < 0.6463$ 可解、以及 1992 年 Coster 等人把界推到 $0.9408$ 的那类结果的直观来源）。$n = 100$、$d = 1.2$ 时指数是 $100(1 - 0.833) = 16.7$，期望解数 $\approx 10^{5}$，短向量一片汪洋，纯 density（密度）攻击失效。对比上一页算出的玩具例子 $d \approx 0.90$：它落在可攻区间内；而真实 M-H 的 $d$ 被超递增结构推到 1 附近，恰好卡在阈值上沿 —— 所以讲义那句「M-H 总是产生低密度背包」应当打个折扣：更准确的说法是它的 density（密度）**紧贴阈值**，真正致命的是 Shamir 在 1982 年给出的结构攻击，而不是单纯的低密度。⚠ 需回查：这一区间的精确定位。
>
> 跨课程连接有两处很直接。其一是 6.042J 的计数与抽屉原理：上面 $2^{n}/2^{\max \log_2 w_i}$ 就是最朴素的「值域比定义域小则必然碰撞」的计数论证，抽屉原理给出的是存在性，这里给出的是**期望个数**，强度不同但推理同源。其二是 Strang 18.06 的 Gram-Schmidt（正交化过程）：LLL（格基约简算法）可以理解为「带尺寸上限的 Gram-Schmidt（正交化过程）」—— 它在正交化的同时不允许系数膨胀，于是得到一个「不太正交但也不太长」的基；区别是 Gram-Schmidt（正交化过程）是精确的、$O(n^{3})$ 的、且不保证基向量短，LLL（格基约简算法）是近似的、多项式但次数更高、并且保证基向量长度被控制住，这个「近似」正是它在多项式时间内可用的原因（精确求最短向量很难）。
>
> 回到正文：density（密度）这条判据成了后世背包类方案的定量红线 —— 想要抗格攻击，就必须让 $d$ 明显大于 $0.9408$；而想要自己人能高效解密，结构又必须足够「稀疏」。这条拉锯在 1980 年代没有解法，于是整个背包路线被放弃，密码学转向了 LWE（容错学习）那一路带噪声的线性结构。「密度」这个词因此不只是历史术语，它是「密码设计必须量化到数字」的第一个范例。
