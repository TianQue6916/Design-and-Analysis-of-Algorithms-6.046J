<span style="color:#2471a3;">**[section]**</span> <span style="color:#00838f;">**DP 的四个要点（DP notions）**</span>

🎥 *Devadas 在视频中[预告本讲难度]*："You'll probably see problems here, at least alternating coin game, that are beyond 006 in the sense that it wasn't covered. Those kinds of notions weren't covered in 006."（翻译：你在这里可能会看到一些超出 6.006 范围的问题，至少「交替取硬币游戏」在 6.006 没讲过——这类概念当时没覆盖。）——本讲的取硬币博弈是「对手也最优」的博弈型 DP，确实超出基础课程，值得重点关注。

1. **刻画最优解的结构**（Characterize the structure of an optimal solution）
2. **递归地定义**基于子问题最优解的最优解的值（Recursively define the value of an optimal solution based on optimal solutions of subproblems）
3. **自底向上**计算最优解的值（递归 + 记忆化 memoization）
4. 从计算出的信息**构造最优解**（Construct an optimal solution from the computed information）

> <span style="color:#1e8449;">**[note] Note（译者注）:**</span> 这四步要解决的设计问题是：把「在所有可行解上取最优」这句无法直接执行的话，编译成「有限个状态 + 每个状态一次可枚举的局部选择」这种可执行形式。原文四个动词分别对应四件事：characterize（刻画结构）、define（写递推）、compute（填表或记忆化）、construct（回溯重建）。它不是仪式，而是把「最优」这个数学词降级成指令的四条改写规则。
>
> 为什么结构必须先想清楚，而不是先写递推？因为递推式的每一项都是从步骤 1 的 cut-and-paste argument（替换论证）里抄出来的：设某个最优解 $S$ 在第一次决策后留下的子部分是 $S'$，若 $S'$ 不是对应子问题的最优解，就存在更优的 $S''$，把 $S'$ 换进去后整体代价严格下降，与 $S$ 的最优性矛盾。这条论证同时交付两样东西 —— 子问题该取什么形状（由「$S'$ 到底是什么」决定），以及递推里每一项的来源（由「替换后哪一部分变了」决定）。跳过步骤 1 直接写递推的人，通常是在证明一个并不成立的断言：式子能跑，结果算错，而且错得很安静。
>
> 给一个能手算复核的规模感。朴素递归的斐波那契函数，调用次数满足 $T(n) = T(n-1) + T(n-2) + 1$，解得 $T(n) = 2F(n+1) - 1$（$F$ 为斐波那契数）。取 $n = 30$：$F(31) = 1346269$，于是 $T(30) = 2 \times 1346269 - 1 = 2692537$，约 $2.7 \times 10^6$ 次调用；而互不相同的状态只有 $30$ 个。若单次调用按 $50\ \mathrm{ns}$ 估，朴素版约 $0.13\ \mathrm{s}$，加表后约 $1.5\ \mu\mathrm{s}$。这组数说明步骤 3 不是「怎么实现」的细节：它决定同一份递推是从指数掉到多项式，还是原地不动。
>
> 四步里最容易被跳过的是第 4 步。$L(i, j)$ 只存长度，所以它能说出 "character" 的最长回文子序列长度是 $5$，但交不出 "carac" 这个串本身。要交出来，每个状态必须额外记一次选择（两端配对、收缩左边界、收缩右边界，三者取一），再从 $(1, 9)$ 顺着记录回溯。这和 CSAPP 第 3 章里「调用前先把返回地址压栈，否则回不去」是同一类记账思想：算出数值只是过程，能复现路径才叫解。
>
> 跨课程连接有两处。其一是 CLRS 第 15 章：15.1 用 rod cutting（钢条切割）把四步逐一演一遍，§15.3 再抽出两条判据 —— optimal substructure（最优子结构）与 overlapping subproblems（重叠子问题）。其二是 6.042J 的 strong induction（强归纳）：递推式本身就是一条强归纳断言，而步骤 3 的自底向上填表，是把归纳的次序物化成循环次序（本讲按区间长度 $j - i$ 递增，恰好对应「所有更小规模都已成立」这个归纳假设）。区别在于：6.042J 的归纳只要求命题对所有规模成立，DP 还额外要求每个状态真的被算过、且只算一次 —— 这是一条关于 dependency order（依赖次序）的工程约束，归纳法里没有它。
>
> 与 divide and conquer（分治）的边界也在这里划线。归并排序的两个子数组互不相交，同一子问题不会出现第二次，递归树只有 $\Theta(n)$ 个结点；而最长回文的 $L(i+1, j)$ 与 $L(i, j-1)$ 会共同指向 $L(i+1, j-1)$，同一个状态被多条路径到达 —— 重叠才是 DP 的动机，没有重叠就该老实分治。本讲三个例子恰好覆盖三种子问题形状：interval（区间型）的最长回文、root-guessing（猜根型）的最优 BST、game（博弈型）的取硬币，形状不同，四步流程一模一样。
>
> 所以这四步的价值不在顺序本身，而在它把「想清楚」和「算出来」强制分开：结构错了，后面所有优化全部白做；结构对了，记忆化与迭代只是同一份递推的两种执行方式。

<span style="color:#2471a3;">**[section]**</span> <span style="color:#00838f;">**最长回文序列（Longest Palindromic Sequence）**</span>

**定义（Definition）**：**回文（palindrome）**是反转后不变的字符串。
**例子**：radar、civic、t、bb、redder

**给定**：字符串 $X[1 \cdots n]$，$n \ge 1$
**目标**：找出**作为子序列（subsequence）**的最长回文

**例子**：给定 "character"，输出 "carac"
**答案长度至少为 1**

**策略（Strategy）**：$L(i, j)$：$X[i \cdots j]$ 的最长回文子序列的长度（对 $i \le j$）。

> <span style="color:#1e8449;">**[note] Note（译者注）:**</span> 这条注要防一个看起来便宜、代价却极大的混淆：把 substring（子串）当成 subsequence（子序列）用。两者的可行解集合规模差一个指数级，状态设计也不同；混淆一次，后面所有复杂度推导都是错的。
>
> 先把两个定义域数出来。长度 $n$ 的串，subsequence（子序列）是下标的任意子集但保持相对次序，共有 $2^n$ 个（含空串）；substring（子串）必须是连续区间，只有 $n(n+1)/2$ 个。定义域大小不同，状态就必须不同：子序列问题的状态用区间两端 $(i, j)$ 表示「$X[i \cdots j]$ 里能取到的最优值」，允许「只收缩一边」这种跳过字符的转移；子串问题的状态必须显式带连续性，通常写成布尔量 $P(i, j)$ 表示「$X[i \cdots j]$ 整段是否回文」。
>
> 两条递推放在一起看，差别立刻显形。子序列：$L(i, j) = 1$ 当 $i = j$；若 $X[i] = X[j]$ 则 $L(i, j) = L(i+1, j-1) + 2$；否则 $L(i, j) = \max\{L(i+1, j), L(i, j-1)\}$。子串：$P(i, j) = (X[i] = X[j]) \land (j - i < 2 \lor P(i+1, j-1))$，答案取所有 $P(i, j)$ 为真的最长区间。前者用 $\max$ 合并两个「已经最优」的候选，因为被跳过的字符不影响最优性；后者用逻辑与串起一个必要条件，因为中间一旦断开，整段就不可能是回文。这也是为什么子序列版本能直接套四步模板，而子串版本要先想清楚「什么量在区间扩张时不会被破坏」——那个量是布尔的存在性，不是长度的最优性。
>
> 用讲义给的串算一遍。"character" 共 $9$ 个字符。子序列答案长度是 $5$（"carac"），子串答案是 $3$（"ara"，位置 $3$ 到 $5$）。手算可复核：相邻字符 $c h$、$h a$、$a r$、$r a$、$a c$、$c t$、$t e$、$e r$ 全部不相等，所以不存在长度 $2$ 的连续回文；长度 $3$ 的七个连续窗口 cha、har、ara、rac、act、cte、ter 里只有 ara 首尾相等；长度 $4$ 的六个连续窗口 char、hara、arac、ract、acte、cter 首尾都不等。于是子串答案锁死在 $3$，与子序列的 $5$ 差 $2$。差 $2$ 不是细节，它是两类问题。
>
> 状态数与暴力规模的对比同样值得记住。子序列版的状态是 $9 \times 10 / 2 = 45$ 个区间，每个 $O(1)$ 合并；暴力版要枚举 $2^9 - 1 = 511$ 个非空子序列，每个判回文最多 $9$ 次字符比较，约 $4600$ 次比较。规模再大一点，差距按 $2^n$ 对 $n^2$ 拉开：$n = 20$ 时是 $1048575$ 个子序列对 $210$ 个区间。
>
> 拿更短的串 "chara" 走一遍填表，确认「按长度递增」的次序不是约定。长度 $1$ 的五个状态全是 $1$；长度 $2$ 的四个状态全为 $1$（相邻字符都不等）；长度 $3$ 里 $L(3, 5) = 3$（两端都是 $a$，中间是单个 $r$），其余为 $1$；长度 $4$ 里 $L(2, 5) = 3$，$L(1, 4) = 1$；最后 $L(1, 5) = \max\{L(2, 5), L(1, 4)\} = \max\{3, 1\} = 3$，回溯出 "ara"。注意 $L(1, 5)$ 这一步两端是 $c$ 与 $a$，不相等，走的是收缩转移；若硬套「两端相等就加二」，会算出 $4$ 这个不存在的长度 —— 这是本题最常见的错。
>
> 跨课程连接有两处，路径要写清。一是 CLRS 15.4 的 LCS（最长公共子序列）：最长回文子序列可以先转成「$X$ 与 $X$ 的反转求 LCS」，两者答案长度相同，但状态语义不同 —— LCS 的状态是双串前缀对，两个下标分属两个串；回文的状态是单串区间 $(i \le j)$，两个下标是同一个串的两端。这解释了一个结构性事实：回文表只有上三角（$9$ 个字符是 $45$ 个格子），LCS 表是满的 $n^2$ 个格子。二是 6.042J 的计数：$2^n$ 与 $\binom{n+1}{2}$ 是两种不同族的基数（幂集对区间族），DP 的全部收益就是把前者代表的搜索空间，按 equivalence class（等价类）压到后者数量的代表元上，每个代表元的键就是 $(i, j)$ 这对下标。
>
> 回到正文：interval（区间型）DP 的组织顺序是「先按长度、再按左端点」，这条规则不是风格，而是由子问题依赖关系倒推出来的 —— 依赖图给什么拓扑次序，填表就按什么次序走。

<span style="color:#c0392b">**最长回文序列（续）**</span>

```
1  def L(i, j):
2      if i == j:  return 1
3      if X[i] == X[j]:
4          if i + 1 == j:  return 2
5          else:  return 2 + L(i + 1, j - 1)
6      else:
7          return max(L(i + 1, j), L(i, j - 1))
```

**练习（Exercise）**：计算实际的解（即具体回文序列）。

**分析（Analysis）**：照此实现，程序可能**指数时间**运行：假设所有符号 $X[i]$ 都互不相同。

```math
T(n) = \begin{cases} 1 & n = 1\\ 2T(n-1) & n > 1 \end{cases} = 2^{n-1}
```

**子问题（Subproblems）**：但只有 $\binom{n}{2} = \Theta(n^2)$ 个互不相同的子问题：每个是满足 $i < j$ 的 $(i, j)$ 对。通过每个子问题**只求解一次**，运行时间降到 $\Theta(n^2) \cdot \Theta(1) = \Theta(n^2)$，其中 $\Theta(n^2)$ 是子问题个数、$\Theta(1)$ 是在较小子问题已解时求解每个子问题的时间。

**记忆化（Memoize）**：记忆化 $L(i, j)$——把输入哈希成输出值，查哈希表看子问题是否已解，否则递归。

**记忆化 vs 迭代（Memoizing vs. Iterating）**
1. 记忆化用字典存 $L(i, j)$，以 $i, j$ 为键查 $L$ 的值。这里可以直接用 2-D 数组，其中 **null 项**表示问题尚未求解。
2. 可以**按 $j - i$ 递增的顺序**求解子问题，这样较小的子问题先被求解。

> <span style="color:#1e8449;">**[note] Note（译者注）:**</span> 这条注要回答的工程问题是：同一份递推，为什么直接写递归要 $2^{n-1}$ 次调用，加一张表就掉到 $O(n^2)$？差别不在递推，在「谁拥有状态」。递推描述的是状态之间的等式，而递归实现把「每次求值」当成一次性事件，两者之间隔着一层没被约束的自由：同一个状态可以被人反复求值。
>
> 把递归树数一遍就看清了。符号全不相同时，$L(i, j)$ 的两个分支各自走向长度更短的一个区间，递归树每层分两支、深度约 $n$，于是调用次数是 $2^{n-1}$ 量级；但互不相同的 $(i, j)$ 只有 $\binom{n+1}{2}$ 个（$n = 9$ 时是 $45$ 个，见注 #2）。调用次数与状态数之比就是冗余率。DP 做的唯一一件事，是把「函数调用」改成「查表加写回」：第一次遇到某状态算出值写进表里，之后直接读。代价于是从「路径数」变成「状态数乘以每状态工作量」，冗余率被整体抹掉。
>
> 给具体数字。$n = 30$ 的区间型问题：递归树调用次数 $2^{29} = 536870912$，约 $5.4 \times 10^8$；状态数 $30 \times 31 / 2 = 465$。两者之比约 $1.15 \times 10^6$。若单次调用按 $50\ \mathrm{ns}$ 估，朴素递归约 $536870912 \times 50\ \mathrm{ns} \approx 26.8\ \mathrm{s}$，加表后 $465 \times 50\ \mathrm{ns} \approx 23\ \mu\mathrm{s}$ —— 三个数量级的差，来源只有「有没有把结果留下来」。斐波那契上同样成立：$n = 30$ 时朴素调用 $2692537$ 次，加表后 $30$ 次，与 CPython 里缓存装饰器的行为机制完全相同。
>
> memoization（记忆化）有两个值得分开看的性质。第一是 lazy（惰性）：它只解真正被访问到的状态。若真实依赖只覆盖 $465$ 个状态里的一小部分（比如加了剪枝，或输入有特殊结构），省下的那部分就是纯收益。第二是栈深：递归深度可以到 $n$ 层，$n = 10^4$ 时超过 CPython 默认递归上限 $1000$，必须先调 `sys.setrecursionlimit` 或改写成迭代 —— 这是记忆化在生产代码里最常见的硬伤。
>
> tabulation（填表）走另一条路：按 $j - i$ 从小到大循环，保证「依赖必已就绪」——$L(i, j)$ 只依赖长度更小的两个区间，按长度递增填，任何时刻访问到的格子都是算过的。它没有递归栈、没有哈希查找，常数更小；代价是必须先写出 dependency order（依赖次序）。这个次序的数学身份，是 6.042J 里 partially ordered set（偏序集）的 linear extension（线性扩展）：把「区间更短」这个偏序，扩展成一个具体的二重循环。写不出这个次序，说明步骤 1 的结构其实没想清楚。
>
> 跨课程连接：CSAPP 第 6 章的 cache 用的是同一个思想。重复访问同一地址由 cache 命中兜住，代价从主存的约 $100$ 个周期降到 L1 的约 $4$ 个周期，靠的正是 temporal locality（时间局部性）—— 同一份数据被反复用到，所以留在近处。记忆化是这套思想在算法层的显式版本，区别有两条：cache 由硬件自动管理、容量固定、条目会被 LRU（最近最少使用）驱逐，所以命中是概率事件；memo 表由算法自己拥有、无驱逐、容量必须与状态数同阶（本讲是 $O(n^2)$ 个格子），已解状态的命中率是确定的百分之百。换个说法：cache 在用概率换延迟，memoization 在用空间换次数。
>
> 所以「记忆化还是迭代」不是风格问题，是问「求解次序由谁决定」：交给递归的调用图，换来惰性与省状态，付出栈深与查找开销；交给代码里的循环，换来确定性与小常数，付出「必须能写出拓扑次序」这个前提。两者空间都是 $\Theta(n^2)$、时间都是 $\Theta(n^2)$，渐进上分不出胜负，工程上差别很大。

<span style="color:#c0392b">**最优二叉搜索树（Optimal Binary Search Trees）：CLRS 15.5**</span>

**给定**：键 $K_1, K_2, \cdots, K_n$，$K_1 < K_2 < \cdots < K_n$（不失一般性设 $K_i = i$），权重 $W_1, W_2, \cdots, W_n$。

**目标**：找出最小化下式的 BST $T$：

```math
\sum_{i=1}^{n} W_i \cdot (\mathrm{depth}_T(K_i) + 1)
```

**例子**：$W_i = p_i$ = 搜索 $K_i$ 的概率。那么，我们在最小化**期望搜索代价（expected search cost）**。

（假设我们表示一个英→法词典，常用词应有更大权重。）

**枚举（Enumeration）**：树的数量**指数多**。

- $n = 2$：$W_1 + 2W_2$ 或 $2W_1 + W_2$（两种形状）
- $n = 3$：$3W_1 + 2W_2 + W_3$、$2W_1 + 3W_2 + W_3$、$2W_1 + W_2 + 2W_3$、$W_1 + 3W_2 + 2W_3$、$W_1 + 2W_2 + 3W_3$（五种形状）

**策略（Strategy）**：

```math
W(i, j) = W_i + W_{i+1} + \cdots + W_j
```

```math
e(i, j) = K_i, K_{i+1}, \cdots, K_j \text{ 上的最优 BST 的代价}
```

目标：$e(1, n)$。

**贪心解（Greedy solution）？**：用某种贪心方式选 $K_r$，例如 $W_r$ 最大。
**贪心不适用**（greedy doesn't work），见讲义末尾的例子。

> <span style="color:#1e8449;">**[note] Note（译者注）:**</span> 这条注要回答「optimal binary search tree（最优 BST）为什么必须用 DP」，答案不是「树形太多」这种量词上的理由，而是两个方向相反的约束同时作用：权重希望高概率键靠近根，inorder constraint（中序约束）要求键按大小排列，两者拉扯的结果是「把谁放根」这件事没有局部答案。
>
> 先看自由度。这个约束让树形变小，也让「选谁当根」的自由变大。变小，是因为一旦选定根 $K_r$，左子树只能装 $K_i \cdots K_{r-1}$、右子树只能装 $K_{r+1} \cdots K_j$，没有别的分区方式；变大，是因为每一步「选谁当根」都自由，于是 $n$ 个键的全部树形数量是 Catalan number（卡特兰数）$C_n = \frac{1}{n+1}\binom{2n}{n}$，渐近 $C_n \sim \frac{4^n}{\sqrt{\pi}\, n^{3/2}}$。这个数比 $2^n$ 略慢、比任何多项式快得多，所以枚举树形必然爆。
>
> 具体数字：$C_1 = 1$、$C_2 = 2$、$C_3 = 5$、$C_4 = 14$、$C_5 = 42$、$C_{10} = 16796$、$C_{20} = 6564120420$，约 $6.56 \times 10^9$。讲义正文里 $n = 3$ 的五个代价表达式，从 $3W_1 + 2W_2 + W_3$ 到 $W_1 + 2W_2 + 3W_3$，正好对应这五个树形；而且每一项的系数就是该键的比较次数，等于深度加一。把系数和树形一一对上，能直接看出为什么根的系数恒为 $1$：根在深度 $0$，比较一次。这也顺带说明为什么 $n = 4$ 时手写枚举已经不现实：$14$ 种形状，写全了也没人看得下去。
>
> 目标函数 $\sum_i W_i (\mathrm{depth}_T(K_i) + 1)$ 里的加一不是装饰。根在深度 $0$，但要比较 $1$ 次；最深叶子的比较次数等于深度加一。若 $W_i = p_i$ 是搜索概率且总和为 $1$，这个和就是期望比较次数，量级感可以这样估：$n = 1000$ 个键权重全相等时最优树接近平衡，期望比较次数约 $\log_2 1000 + 1 \approx 11$；若树退化成链，期望是 $(1 + 2 + \cdots + 1000)/1000 = 500.5$。约 $45$ 倍的差距全是「形状」的价格。而权重不均匀能买到更低的代价：若 $p_1 = 0.9$、其余 $999$ 个键平分 $0.1$，把 $K_1$ 放根后期望约 $0.9 \times 1 + 0.1 \times 11 \approx 2.0$，远低于平衡树的 $11$。
>
> 这正是 binary search（二分搜索）做不到的事。二分搜索固定按下标对半分，比较次数被锁在 $\lceil \log_2(n+1) \rceil = 10$，它根本不读权重；而最优 BST 把「访问分布」当成输入，所以能在同一批键上做得更好。跨课程连接就在这里：CLRS 第 12 章的基础 BST 只讨论形状与操作代价的关系（随机插入下期望深度 $O(\log n)$），不讲「给定权重如何最优」；本讲补上的正是「分布决定结构」这一层。同一层道理在 CSAPP 第 6 章也能看到：cache 的收益大小取决于程序访问的局部性，访问越不均匀，缓存越有用 —— 存储层与算法层在这里是同构的。
>
> 还可以再往下挖一层，把「约束」这个词具体化。与最优 BST 最像的邻居是 CLRS 16.3 的 Huffman coding（哈夫曼编码）：两者都在「权重决定树的形状」这件事上做功，但 Huffman 的树没有 inorder constraint（中序约束），合并哪两个结点完全自由，于是贪心成立 —— 每次取权重最小的两个合并，交换论证能证。一旦加上中序约束，问题变成 alphabetic code（字母序编码），两个最小权重如果中间隔着别的键就不能直接合并，贪心的选择性质随之消失，必须回到 DP 或者专门算法。这一对比把失效的原因定位得很准：不是权重本身捣乱，是约束让「局部最优的一步」不再总能被扩展成全局最优。
>
> 两个归属已经核查过。第一，静态最优 BST，也就是给定权重分布、构树一次、之后不再修改的版本，其 $O(n^2)$ 算法由 Knuth 在 1971 年给出，论文 *Optimum Binary Search Trees*，Acta Informatica 1(1)，14 到 25 页。第二，dynamic optimality（动态最优性）是另一个问题：访问序列事先未知、必须在线上自适应，Sleator 与 Tarjan 在 1985 年的 *Self-Adjusting Binary Search Trees*（JACM 32(3)，652 到 686 页）提出 splay tree（伸展树），并猜想它对任意访问序列与最优离线 BST 只差常数因子；这个猜想至今未证。本讲算的是前者，别把两者混成一件事。
>
> 所以最优 BST 的价值不止是那道题：它示范了一条推理链 —— 数树形（$\Theta(4^n)$）、看增长、判死刑、再回头找 DP 的切口。这个顺序在遇到任何「枚举空间太大」的新问题时都能照搬。

<span style="color:#c0392b">**最优 BST（续）**</span>

> <span style="color:#7f8c8d;">[原图说明] 原页附图：以 $K_r$ 为根的最优 BST 分解——左子树含 $K_i, \ldots, K_{r-1}$（代价 $e(i, r-1)$），右子树含 $K_{r+1}, \ldots, K_j$（代价 $e(r+1, j)$）。</span>

**DP 策略：猜测所有根（Guess all roots）**

```math
e(i, j) = \begin{cases} W_i & \text{若 } i = j\\ \min_{i \le r \le j} \left( e(i, r-1) + e(r+1, j) + W(i, j) \right) & \text{否则} \end{cases}
```

$+W(i, j)$ 计入根 $K_r$ 的 $W_r$，以及 $K_r$ 各子树中所有其他键**深度加 1** 带来的增量（DP 尝试所有局部选择方式，并利用重叠子问题）。

**复杂度（Complexity）**：$\Theta(n^2) \cdot \Theta(n) = \Theta(n^3)$，其中 $\Theta(n^2)$ 是子问题个数、$\Theta(n)$ 是每个子问题的时间。

> <span style="color:#1e8449;">**[note] Note（译者注）:**</span> 这条注要给一个可反复套用的模板：root-guessing（猜根）。它的形状是外层枚举分割点、内层是两个互不耦合的子问题、再加一项与分割点无关的区间代价。最优 BST 是这个模板的原型，matrix-chain multiplication（矩阵链乘）是它的兄弟。
>
> 先解决那个最容易被记住、也最容易被理解错的细节：为什么加的是 $W(i, j)$ 而不是 $W_r$。设 $e(i, j)$ 表示把 $K_i \cdots K_j$ 构造成一棵以某键为根、并把根的深度记作 $0$ 的子树时的相对代价。选定根 $K_r$ 之后，左子树的每个键、右子树的每个键都整体下移一层，深度各加一；根自己的深度是 $0$，比较次数是一。于是新代价等于左右子树的相对代价，加上所有非根键各加一份权重，再加上根自己那一份权重，恰好凑成 $e(i, r-1) + e(r+1, j) + W(i, j)$。关键在最后这一项与 $r$ 无关：比较不同候选根时它整体抵消，真正在起作用的只有两个子树的代价。
>
> 这个「与 $r$ 无关」还有第二层意义：绝对深度从不进入状态。若把绝对深度写进状态，比如记 $e(i, j, d)$ 表示根在深度 $d$ 时的代价，状态数立刻变成 $O(n^3)$，转移里还要处理 $d$，既慢又难写。而只要认识到深度只以相对方式影响总代价，状态就压回二维。这是「把全局平移量一次性结算」的手法，和 prefix sum（前缀和）同源：把一个区间里所有项共同的增量，折成一次区间查询 $W(i, j)$，而不是在每个子问题里重新累加。
>
> 用讲义末尾的四键反例走一遍，$W = (1, 10, 8, 9)$，$W(1,4) = 28$，其余区间和是 $W(1,2) = 11$、$W(2,3) = 18$、$W(3,4) = 17$、$W(1,3) = 19$、$W(2,4) = 27$。按长度递增填表。
>
> 长度 $1$：$e(1,1) = 1$、$e(2,2) = 10$、$e(3,3) = 8$、$e(4,4) = 9$。长度 $2$：$e(1,2) = 11 + \min\{10, 1\} = 12$（根取 $K_2$）；$e(2,3) = 18 + \min\{8, 10\} = 26$（根取 $K_2$）；$e(3,4) = 17 + \min\{9, 8\} = 25$（根取 $K_4$）。长度 $3$：$e(1,3) = 19 + \min\{26, 1 + 8, 12\} = 19 + 9 = 28$（根取 $K_2$）；$e(2,4) = 27 + \min\{25, 10 + 9, 26\} = 27 + 19 = 46$（根取 $K_3$）。长度 $4$：$e(1,4) = 28 + \min\{46, 1 + 25, 12 + 9, 28\} = 28 + 21 = 49$（根取 $K_3$）。
>
> 得到 $49$，与讲义 Figure 2 的代价一致。同一次填表还顺带给出「固定根」的代价，做对比很方便：根取 $K_1$ 时 $e(2,4) + 28 = 74$；根取 $K_2$ 时 $1 + 25 + 28 = 54$；根取 $K_3$ 时 $12 + 9 + 28 = 49$；根取 $K_4$ 时 $28 + 28 = 56$。四个数把「根的选择值多少钱」量化了：最差的根比最好的根贵 $25$，而权重最大的键当根只能排到 $54$。
>
> 复杂度来自两张乘起来的表：状态 $n(n+1)/2$ 个，每个状态试 $n$ 个根，合起来 $\Theta(n^3)$；四键时是 $10$ 个状态、每个最多 $4$ 个候选，约 $40$ 次比较。Knuth 优化（已核查，Knuth 1971）证明最优根 $R(i, j)$ 满足 $R(i, j-1) \le R(i, j) \le R(i+1, j)$，于是每个区间只需在很窄的窗口里试根，总工作量降到 $O(n^2)$。工程含义可以用数字说清：$n = 1000$ 时 $\Theta(n^3)$ 约 $10^9$ 次基本操作，按每次 $1\ \mathrm{ns}$ 估约 $1\ \mathrm{s}$；$n = 10^4$ 时跳到 $10^{12}$ 次、约 $1000\ \mathrm{s}$，接近 $17$ 分钟，而 $O(n^2)$ 版只需要 $10^8$ 次、约 $0.1\ \mathrm{s}$。差一个 $n$ 因子，在这里就是「能跑」与「跑不动」的分界。
>
> 跨课程连接：CLRS 15.2 的 matrix-chain multiplication（矩阵链乘）是同一个模板，$m(i, j) = \min_{i \le k < j}\{m(i, k) + m(k+1, j) + p_{i-1} p_k p_j\}$。区别恰在加法项：矩阵链的那一项依赖分割点 $k$，因为它是「最外层做一次乘法」的代价，切在哪里，乘法的三个维度就跟着变；最优 BST 的那一项 $W(i, j)$ 与 $r$ 无关，因为它来自「全部结点一起下移一层」这件与切法无关的事实。由此可以记一条判别法：递推里出现与分割点无关的区间项，说明有一个全局平移量被一次性结算掉了，模板照用，但候选根之间的比较只看子问题项。
>
> 回到正文那个 $+W(i, j)$：它的作用不是「加上根的权重」，而是「把整段深度平移的增量一次算清」。认错这一点，递推就会写成 $+W_r$，用四键的例子代进去立刻算出错的答案。

<span style="color:#c0392b">**交替取硬币游戏（Alternating Coin Game）**</span>

一排 $n$ 个硬币，价值 $V_1, \cdots, V_n$，$n$ 是偶数。每回合，一名玩家选择**这一排的第一个或最后一个**硬币，将其**永久移除**，并获得该硬币的价值。

**问题（Question）**：先手（first player）总是能赢吗？

**试（Try）**：$4\ \ 42\ \ 39\ \ 17\ \ 25\ \ 6$

**策略（Strategy）**
1. 比较 $V_1 + V_3 + \cdots + V_{n-1}$ 与 $V_2 + V_4 + \cdots + V_n$，选择较大者。
2. 游戏过程中**只从所选子集中取**（你总能做到！）

**如何最大化你赢得的钱数（假设你先手）？**

> <span style="color:#1e8449;">**[note] Note（译者注）:**</span> 这条注讲一个不写 DP 也能给出保证的论证模板：parity（奇偶位置）论证。它只回答可行性，即先手能不能保证赢，不回答最优性，即最多能拿多少。这两件事分开看，才看得清正文紧接着为什么要上 DP。
>
> 证明的形状是维护一条 invariant（不变量）。设 $n$ 为偶数，位置 $1, \ldots, n$ 奇偶交替。先手第一步取 $V_1$，这是奇数位，剩下区间 $[2, n]$，两端下标 $2$ 与 $n$ 都是偶数，于是后手只能取偶数位。后手取走一端后，区间变成 $[3, n]$ 或 $[2, n-1]$，此时两端一奇一偶，先手取那个奇数位的一端，剩下的区间两端又都回到偶数位。不变量「轮到先手时，区间两端同为偶数位」就这样被每一步恢复，归纳成立。结论：先手可以做到只取奇数位，后手只能取偶数位，双方的钱数之和在开局就已被结构锁定，分别是奇数位之和与偶数位之和。
>
> 用讲义那排硬币算一遍：$4, 42, 39, 17, 25, 6$。奇数位是第 $1, 3, 5$ 枚，和 $4 + 39 + 25 = 68$；偶数位是第 $2, 4, 6$ 枚，和 $42 + 17 + 6 = 65$；总和 $133$。先手选较大的一组，也就是 $68$ 那一组，第一步取 $V_1 = 4$。逐回合核对：剩余 $42, 39, 17, 25, 6$，两端下标 $2$ 与 $6$ 都是偶数，后手取谁都跑不出偶数位。若他取 $42$，剩 $39, 17, 25, 6$，先手取 $39$；再剩 $17, 25, 6$，两端下标 $4$ 与 $6$ 都是偶数，后手取一个，先手取 $25$，合计 $68$。若他第一步改取 $6$，剩 $42, 39, 17, 25$，先手取 $25$（下标 $5$ 是奇数），再剩 $42, 39, 17$，后手取任一端后先手取 $39$，合计仍是 $68$。
>
> 「赢」的判据是 $\max\{\text{奇数位和}, \text{偶数位和}\} > \text{总和}/2$，本题 $68 > 66.5$，成立。但这个判据只充分、不必要，因为它只用上了奇偶这一种策略。$n$ 为奇数时论证直接失效：两端下标同奇偶，先手取任何一端都无法把后手锁进某一组。给个反例就够清楚：$[1, 100, 1]$ 里先手最多拿 $2$（取左端得 $1$，后手取 $100$，先手再取 $1$），远低于一半的 $51$。
>
> 更值得记住的是：奇偶策略给的是下界，不等于最优。工作区里用穷举程序核对过一批小数据，$[1, 0, 1, 2]$ 就是一个反例 —— 奇数位和 $1 + 1 = 2$，偶数位和 $0 + 2 = 2$，奇偶策略只能保证 $2$，而 DP 的最优值是 $3$：先手取 $V_4 = 2$，后手只能在 $[1, 0, 1]$ 里取，无论他取哪一端，先手都能再拿 $1$。所以正文用 DP 重算同一个游戏不是重复劳动，而是把「能保证多少」升级成「恰好最多多少」。另一个边界例子是 $[10, 1, 1, 10]$：奇偶两组都是 $11$，总和 $22$，奇偶策略只能保证平局，DP 算出来也正好是 $11$，先手在这个数据上根本赢不了。
>
> 跨课程连接：这个证明的形状正是 6.042J 里 invariant（不变量）论证的标准用法 —— 找一个每轮之后必然被恢复的性质，用它排除对手的所有可能。区别在用途：6.042J 里不变量多用来证终止性与正确性，例如状态机不会进入坏状态；这里它证明的是策略的存在性，而且不变量本身就编码了策略，即「取那个奇数位的一端」。另一个连接在复杂度上：这个策略不需要看全局数据，只要两个和，$O(n)$ 一次扫描就够，与 DP 的 $\Theta(n^2)$ 形成对照 —— 这是「用结构换掉搜索」的另一种形式。
>
> 回到正文的策略 2「只从所选子集中取」：它之所以总能做到，正是上面那条不变量的直接推论，而不是运气好。

<span style="color:#c0392b">**最优策略（Optimal Strategy）**</span>

$V(i, j)$：轮到我们且只剩 $V_i, \cdots, V_j$ 时，我们能**确定赢得**的最大价值。

- $V(i, i)$：直接取 $i$。
- $V(i, i+1)$：取两者中较大者。
- $V(i, i+2)$、$V(i, i+3)$、$\cdots$

```math
V(i, j) = \max\{ (\text{范围变为 } (i+1, j)) + V_i,\ (\text{范围变为 } (i, j-1)) + V_j \}
```

**求解（Solution）**：$V(i+1, j)$ 子问题——对手取完后……

我们保证得到 $\min\{ V(i+1, j-1),\ V(i+2, j) \}$

其中 $V(i+1, j-1)$ 对应「对手取 $V_j$」，$V(i+2, j)$ 对应「对手取 $V_{i+1}$」。

于是

```math
V(i, j) = \max\left\{ \min\{ V(i+1, j-1),\ V(i+2, j) \} + V_i,\ \min\{ V(i, j-2),\ V(i+1, j-1) \} + V_j \right\}
```

**复杂度（Complexity）？** $\Theta(n^2) \cdot \Theta(1) = \Theta(n^2)$

> <span style="color:#1e8449;">**[note] Note（译者注）:**</span> 这条注要回答的是：为什么博弈型 DP 的递推必须写成 $\max$ 里套 $\min$，而不是一次 $\max$ 就够。原因是这里有两个人做决策，状态转移不再是「我挑最好的分支」，而是「我挑，然后对手挑，再轮到我挑」—— 三步里有两个决策位置，一次 $\max$ 只能表达一个。
>
> 严格写出来。设 $V(i, j)$ 表示轮到当前行动者时，他从 $V_i \cdots V_j$ 里能保证的最大收益。若我取左端：我拿 $V_i$，剩下 $(i+1, j)$ 轮到对手，对手在他的位置上也要最大化他自己的保证值 $V(i+1, j)$；而两人在同一堆硬币上分账，我拿到的等于区间总和减去对手拿到的，即 $V_i + S(i+1, j) - V(i+1, j)$，其中 $S$ 为区间和。这是三层的 complement form（互补式）写法。讲义用的是它展开一层后的形式：对手取完之后又轮到我，于是对手的两个选择分别留下 $(i+1, j-1)$（他取右端）与 $(i+2, j)$（他取左端），我在两个子区间里的保证值分别是 $V(i+1, j-1)$ 与 $V(i+2, j)$，而对手会挑让我更小的那个，所以内层是 $\min$。展开的好处是省掉区间和数组、每状态少一次加法；代价是 $V$ 的语义必须读成「当前行动者视角」。
>
> 两种写法在数据上必须一致，这一点工作区里核对过：对 $4, 42, 39, 17, 25, 6$ 分别用互补式与展开式算 $V(1, 6)$，都得 $68$。若把 $V$ 的语义误读成「先手视角」，内层的 $\min$ 就会被写成 $\max$，答案会偏大 —— 这是这类题最常见的错，而且错得很隐蔽，因为小数据上两种写法常常巧合相等。
>
> 把表填一遍（$n = 6$，状态 $6 \times 7 / 2 = 21$ 个）。长度 $1$：$4, 42, 39, 17, 25, 6$。长度 $2$ 取较大者：$42, 42, 39, 25, 25$。长度 $3$：$V(1,3) = \max\{39 + 4, 4 + 39\} = 43$；$V(2,4) = \max\{17 + 42, 39 + 17\} = 59$；$V(3,5) = \max\{17 + 39, 17 + 25\} = 56$；$V(4,6) = \max\{6 + 17, 17 + 6\} = 23$。长度 $4$：$V(1,4) = \max\{\min\{42, 39\} + 4, \min\{42, 42\} + 17\} = \max\{43, 59\} = 59$；$V(2,5) = \max\{\min\{39, 25\} + 42, \min\{42, 39\} + 25\} = \max\{67, 64\} = 67$；$V(3,6) = \max\{\min\{25, 25\} + 39, \min\{39, 25\} + 6\} = \max\{64, 31\} = 64$。长度 $5$：$V(1,5) = \max\{\min\{59, 56\} + 4, \min\{43, 59\} + 25\} = \max\{60, 68\} = 68$；$V(2,6) = \max\{\min\{56, 23\} + 42, \min\{59, 56\} + 6\} = \max\{65, 62\} = 65$。长度 $6$：$V(1,6) = \max\{\min\{67, 64\} + 4, \min\{59, 67\} + 6\} = \max\{68, 65\} = 68$。
>
> 顺带得到两个可对照的事实。第一，$V(1,6) = 68$ 恰好等于奇数位之和（注 #6 算过 $4 + 39 + 25 = 68$），说明在这组数据上奇偶策略正好达到最优 —— 但那是巧合，注 #6 里 $[1, 0, 1, 2]$ 就把它推翻了，那里奇偶只保证 $2$，DP 给 $3$。第二，第一行 $V(1,5) = 68 > V(2,6) = 65$，差值 $3$ 就是「先手已拿走 $V_1 = 4$、少了一个偶数位大数 $42$（$42$ 后来被对手拿走）」的净效应，这类差值动手算一次比看十遍递推有用。
>
> 复杂度和规模感：$\Theta(n^2) \cdot \Theta(1) = \Theta(n^2)$，每个状态两次取小、一次取大，$21$ 个状态共约 $63$ 次比较。对照穷举所有对局路径的 $2^n$ 量级：$n = 100$ 时是 $2^{100} \approx 1.27 \times 10^{30}$ 条路径，而 DP 只需要 $100 \times 101 / 2 = 5050$ 个状态。把博弈树压成一张区间表，这就是「对手也最优」这个建模假设换来的收益。
>
> 跨课程连接与拓展。一是 6.042J 的命题逻辑：$\max\min$ 是量词交替的数值化，$\exists x \forall y$ 与 $\forall y \exists x$ 不等价，只有前者对应「我能保证」，也就是我先定、对手后应；顺序一换值就变，这不是符号游戏，而是「谁先看到谁的选择」这个信息结构。二是 CLRS 第 15 章末尾那类游戏习题，也就是 optimal strategy for a game 那一型，本讲递推就是它的标准形态。三是博弈树搜索中的 minimax（极大极小）与 alpha-beta pruning：本讲的递推是不剪枝的 minimax 在一条区间轴上的特例，每个状态只有两个分支、分支后的状态由 $(i, j)$ 唯一索引，所以不需要维护搜索窗口；通用博弈树里状态无法这样索引，才必须靠 alpha-beta 剪掉不可能更优的分支。
>
> 所以内层的 $\min$ 不是保守，它是「对手替我选」的精确写法。把它删掉，算出来的是「对手配合我」的假最优，比算错更危险，因为它看起来更大、更乐观。

<span style="color:#c0392b">**贪心在最优 BST 问题上的反例（Example of Greedy Failing for Optimal BST problem）**</span>

> <span style="color:#7f8c8d;">[说明] 感谢 Nick Davis！</span>

> <span style="color:#7f8c8d;">[图 1 说明] 原页 Figure 1：某 BST 布局，代价 $= 1 \times 2 + 10 \times 1 + 8 \times 2 + 9 \times 3 = 55$。</span>

> <span style="color:#7f8c8d;">[图 2 说明] 原页 Figure 2：另一种 BST 布局，代价 $= 1 \times 3 + 10 \times 2 + 8 \times 1 + 9 \times 2 = 49$。</span>

**贪心反例的解读**：四键权重 $W_1=1, W_2=10, W_3=8, W_4=9$（比较次数 = 深度 + 1）。Figure 1（代价 55）把最大权重 $K_2$（$W_2=10$）放根：$K_2$ 比较 1 次，$K_1, K_3$ 各比较 2 次，$K_4$ 比较 3 次。但最优布局 Figure 2（代价 49）把**第三大**权重 $K_3$（$W_3=8$）放根：$K_3$ 比较 1 次，$K_2, K_4$ 各比较 2 次，$K_1$ 比较 3 次。对比可见：Figure 2 让 $K_4$ 从比较 3 次降到 2 次（省 $9$）、$K_3$ 从 2 次降到 1 次（省 $8$），代价是 $K_2$ 从 1 次升到 2 次（多花 $10$）、$K_1$ 从 2 次升到 3 次（多花 $1$），净省 $9+8-10-1 = 6$——所以「让多个较大权重都浅一点」胜过「让单个最大权重当根」。

> <span style="color:#1e8449;">**[note] Note（译者注）:**</span> 这条注要拆开看的是一个可复用的判断：贪心在最优 BST 上失效，不是因为「贪心不够聪明」，而是因为它用来比较的量（单个权重）和它实际影响的量（全树深度）之间隔着一层非线性 —— 权重是加性的，深度是结构性的，代价是两者的乘积，乘积把局部比较和全局效果彻底脱开了。
>
> 先看结构，这是全部的关键。递推 $e(i, j) = \min_{r} [e(i, r-1) + e(r+1, j)] + W(i, j)$ 里，$W(i, j)$ 与 $r$ 无关，所以「选哪个根」的比较只发生在 $e(i, r-1) + e(r+1, j)$ 这一项上，而这一项里根本没有 $W_r$ 的位置：根自己的权重只通过 $W(i, j)$ 贡献，它对所有候选根一视同仁。换句话说，贪心最看重的那个量在比较式里根本不出现，它出现的地方已经被整体抵消了。这就是「局部判据与全局代价脱钩」的精确形式，而不是一句形容。
>
> 用四键算一遍，$W = (1, 10, 8, 9)$。贪心选 $r = \arg\max_r W_r = 2$（$W_2 = 10$），代价 $e(1,1) + e(3,4) + W(1,4) = 1 + 25 + 28 = 54$。讲义 Figure 1 画的是 $55$，它的右子树把 $K_4$ 挂在 $K_3$ 下面，比「根固定为 $K_2$ 时的最好形状」多花 $1$。最优是根取 $K_3$：$e(1,2) + e(4,4) + 28 = 12 + 9 + 28 = 49$，对应 Figure 2。$49 < 54$，贪心的根选择输 $5$；若把子树的形状损失也算进去，$55$ 与 $49$ 差 $6$。
>
> 逐键对比能把「为什么输」变成可查的账单，比较次数等于深度加一。Figure 1（根 $K_2$）：$K_2$ 比 $1$ 次，$K_1$ 与 $K_3$ 各 $2$ 次，$K_4$ 比 $3$ 次，代价 $10 \times 1 + 1 \times 2 + 8 \times 2 + 9 \times 3 = 10 + 2 + 16 + 27 = 55$。Figure 2（根 $K_3$）：$K_3$ 比 $1$ 次，$K_2$ 与 $K_4$ 各 $2$ 次，$K_1$ 比 $3$ 次，代价 $8 \times 1 + 10 \times 2 + 9 \times 2 + 1 \times 3 = 8 + 20 + 18 + 3 = 49$。逐项差是：$K_2$ 从 $1$ 次变 $2$ 次，多花 $10$；$K_1$ 从 $2$ 次变 $3$ 次，多花 $1$；$K_3$ 从 $2$ 次变 $1$ 次，省 $8$；$K_4$ 从 $3$ 次变 $2$ 次，省 $9$；净省 $8 + 9 - 10 - 1 = 6$。关键读法是：把根从最大权重换成第三大权重，换来的不是「根少比较一次」，而是「两个较重、原本较深的键同时上浮一层」。
>
> 抽象成判据。贪心要成立，需要 greedy-choice property（贪心选择性质）：存在某个最优解包含贪心的第一步选择。这里它为假 —— 以 $K_2$ 为根的最好树代价 $54$，大于全局最优 $49$，所以任何「根是 $K_2$」的树都不可能是最优，贪心的第一步就把自己排除在最优解之外。反过来，DP 的正确性只依赖 optimal substructure（最优子结构），而这条性质已用替换论证证过。这就解释了那个反复出现的现象：DP 的结构通常成立，贪心的性质经常不成立 —— 前者只需要「子部分可以独立最优」，后者还需要「第一步就能选对」。
>
> 跨课程连接：CLRS 第 16 章的贪心章把判据摊成两组例子 —— activity selection（活动选择）有贪心选择性质，用 exchange argument（交换论证）可证；$0$-$1$ 背包没有，而 fractional knapsack（分数背包）有，差别只在「能不能把物品切开」。本讲的最优 BST 属于没有的那一类。交换论证在这里为什么失效？因为它要求「把贪心的选择与最优解的第一步对换后不劣」，而换一次根，整棵树的深度分布会全局重排，代价不是可以局部对换的量。再往上一层看，这和 6.042J 里「局部序拼不成全局序」是同一类现象：$W_2 > W_3$ 是局部比较，它推不出「以 $K_2$ 为根优于以 $K_3$ 为根」。
>
> 所以这个反例的教学价值在方法论上：写贪心之前的第一个问题不是「这样选看着对不对」，而是「这一步的选择会不会改变其他元素的代价」。本题答案是会 —— 所有其他键的深度都加一，于是必须交给 DP 去全局权衡。
