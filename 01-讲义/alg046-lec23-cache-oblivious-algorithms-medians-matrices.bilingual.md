- **内存层级（memory hierarchy）**
- **外部内存模型 vs 缓存无关模型（external memory vs. cache-oblivious model）**
- **缓存无关扫描（cache-oblivious scanning）**

<span style="color:#c0392b">**现代内存层级（Modern Memory Hierarchy）**</span>

到目前为止在本课中，我们把所有操作与内存访问都视为**等成本**的。然而，现代计算机有**内存层级**。

| | 大小 | 延迟 |
|:---|:---:|:---:|
| CPU | | |
| L1 | $\sim 10\text{KB}$ | $\sim 1\text{ns}$ |
| L2 | $\sim 100\text{KB}$ | $\sim 10\text{ns}$ |
| L3 | $\sim \text{MB}$ | $\sim 10\text{ns}$ |
| 内存 | $\sim \text{GB}$ | $\sim 100\text{ns}$ |
| 磁盘 | $\sim \text{TB}$ | $\sim 10\text{ms}$ |

层级中右侧的每一层**更大**，但由于数据需要传播的**距离更长**，**延迟也更长**。然而，不同层级之间的**带宽通常是匹配的**。

缓解延迟的常用技术是**分块（blocking）**：取一个数据字（word）时，**取包含它的整个块（block）**。用算法术语说，思想是**把延迟摊还到整个块上**。为使这个思想有效，我们还需要算法**使用块中的所有字（空间局部性 spatial locality）**，并在**缓存中复用块（时间局部性 temporal locality）**。

> <span style="color:#1e8449;">**[note] Note（译者注，内存层级与局部性）:**</span> 这一页用一张表把 CSAPP 第 6 章的内存层级浓缩了：CPU 到磁盘横跨 **6 个数量级**的延迟（1ns → 10ms），而带宽反而匹配——因为内存系统靠**传输整块数据**维持吞吐。**分块（blocking）** = 取一个字时顺带取整个块，把「每次访问的固定延迟」摊到 $B$ 个字上；**空间局部性** = 用上块里相邻的字（连续访问），**时间局部性** = 反复用已入缓存的块。你在 CSAPP 学过的「for 循环的数组访问顺序决定缓存命中率」正是这两条局部性的工程体现——本讲把它**提升为算法的复杂度指标**：不再数「操作数」，而数「内存传输次数（memory transfers）」。

<span style="color:#c0392b">**算法的内存模型（Memory Model of Algorithms）**</span>

<span style="color:#c0392b">**2.1 外部内存模型（External Memory Model）**</span>

- **缓存（cache）**：总大小 $M$，分成 $M/B$ 块；每块 $B$ 个字；访问**免费**。
- **内存/磁盘（memory/disk）**：无限大小，分成块；每块 $B$ 个字；**慢且按块**访问。

在此模型中，缓存访问是免费的。算法**显式地按块**读写内存。我们将**缓存与内存之间的内存传输次数**作为算法性能的一个重要指标来计数。

<span style="color:#c0392b">**2.2 缓存无关模型（Cache-oblivious Model）**</span>

与外部内存模型的**唯一区别**是：算法**不再知道 $B$ 和 $M$**。访问内存中的一个字会自动把**整个块**取入缓存，若缓存已满则**驱逐最近最少使用（Least Recently Used, LRU）**的块。

**每个算法都是缓存无关算法**，但我们希望找到**最小化新指标（内存传输次数）**的算法。

**为什么我们喜欢缓存无关算法**（相对于让算法知道 $B$ 和 $M$）？因为这样，算法可以**自动调优（auto-tune）**，在不同计算机上（可能有不同的 $B$ 和 $M$）**高效运行**。此外，这是**很酷的研究**！

<span style="color:#c0392b">**扫描（Scanning）**</span>

示例程序：

```python
for i in range(N): sum += A[i]
```

假设 $A$ 在内存中**连续存储**。外部内存模型可以把 $A$ **与块边界对齐**，所以它需要 $\lceil N/B \rceil$ 次内存传输。

---

<span style="color:#c0392b">**扫描（续）**</span>

缓存无关算法**无法控制对齐**（因为它不知道 $B$），所以它需要 $\lceil N/B \rceil + 1 = N/B + O(1)$ 次内存传输。$O(1)$ 个并行扫描仍需要 $O(N/B + 1)$ 次内存传输。

> <span style="color:#1e8449;">**[note] Note（译者注，扫描的 $N/B+1$）:**</span> 扫描是最简单也最重要的缓存无关原语。外部内存模型知道 $B$，能把数组 $A$ 的第一字对齐到块边界，于是 $N$ 个字恰好落在 $\lceil N/B \rceil$ 个块里、每块读一次。缓存无关模型不知道 $B$，$A$ 的首字可能落在某个块的**中间**，于是前后各多出一个「残余块」——总共 $\lceil N/B \rceil + 1 \le N/B + 1$。**$+1$ 是缓存无关的固定代价**：不知道 $B$ 的「无知」只换来常数个额外传输，因为**连续性保证了空间局部性**（块内字基本都会用上）。这个「$N/B + O(1)$」是全书反复出现的基准：**任何缓存无关算法的理想传输数都是「数据量/块大小 + 常数」**，偏离它就是没利用好局部性。

<span style="color:#c0392b">**分治（Divide & Conquer）**</span>

分治算法把问题划分到 $O(1)$ 大小。递归的**基例（base case）**要么是：
- 问题**适合缓存**，即 $\le M$，或
- 问题**适合 $O(1)$ 个块**，即 $O(B)$。

下面我们将看到各一个例子。

<span style="color:#c0392b">**4.1 中位数查找 / 顺序统计量（Median Finding / Order Statistics）**</span>

回顾算法的步骤：
1. 把数组看成按 5 分组（每组 $O(1)$ 大小）。
2. 对每组排序。
3. 递归求**组中位数的中位数**。
4. 按 $x$ **划分**数组。
5. 在**一侧**递归。

我们现在分析每一步的**内存传输数**。令 $MT(N)$ 为总内存传输数。
1. 免费
2. 一次扫描，$O(N/B + 1)$
3. $MT(N/5)$，这涉及一个预处理步骤，把 $N/5$ 个元素**合并**成一个连续数组
4. 3 个并行扫描，$O(N/B + 1)$
5. $MT(7N/10)$

---

<span style="color:#c0392b">**分治（续）**</span>

因此，我们得到递归式

```math
MT(N) = MT(N/5) + MT(7N/10) + O(N/B + 1)
```

求解该递归式需要设定基例。一个明显的基例是 $MT(O(1)) = O(1)$。但我们能得到更强的基例：**$MT(O(B)) = O(1)$**。用这个基例，递归式解为 **$MT(N) = O(N/B + 1)$**。（直觉：递归每一层的成本**几何递减**，所以**根层成本主导**。）

> <span style="color:#1e8449;">**[note] Note（译者注，中位数递归与根层主导）:**</span> 中位数查找（median of medians）是讲次 2 学过的**确定性选择算法**的缓存无关版本——步骤完全一样（5 分组、排序、中位数的中位数、划分、单侧递归），只是分析指标从「比较次数」换成「内存传输数」。$MT(N/5)$（中位数的中位数递归）+ $MT(7N/10)$（单侧递归）的总系数 $1/5 + 7/10 = 9/10 < 1$，所以**每层的传输成本几何递减**：$N/B$ 主导、后续层等比缩水，总和 $O(N/B + 1)$。**更强的基例 $MT(O(B)) = O(1)$** 是缓存无关分析的标志：当子问题小到适合 $O(1)$ 个块时，整个子问题一次传输搞定，无需再拆。这个「**几何递减 → 根层主导**」与矩阵乘法的「**几何递增 → 叶层主导**」（p4 下半）正好构成一对对照，是缓存无关分析的两大模板。

<span style="color:#c0392b">**4.2 矩阵乘法（Matrix Multiplication）**</span>

**问题（Problem）**：计算 $Z = X \cdot Y$，其中 $X, Y, Z$ 都是 $N \times N$ 矩阵。假设 $X$ 按**行主序（row-major order）**存储，$Y$ 按**列主序（column-major order）**存储以改善局部性。

若用**基本算法**，计算 $Z$ 中的一个元素需要一两个并行扫描，因为它要么扫描 $X$ 的新行、要么扫描 $Y$ 的新列。计算每个元素需要 $O(N/B + 1)$ 次内存传输，所以计算整个 $Z$ 需要 $O(N^3/B + N^2)$ 次内存传输。

反之，我们用**分块矩阵乘法（blocked matrix multiplication）算法**（不是 Strassen）。注意关键块应**连续存储**。我们得到递归式

```math
MT(N) = 8MT(N/2) + O(N^2/B + 1)
```

第一项是递归的子矩阵乘法，第二项是矩阵加法，需要扫描矩阵。

同样，我们可以有不同的基例：
- 弱：$MT(O(1)) = O(1)$
- 更好：$MT(O(B)) = O(1)$
- **甚至更好：$MT(\sqrt{M/3}) = O(M/B)$**

第三种情况代表**三个涉及的矩阵能一起放进缓存**的情形。因此，要乘它们，我们只需一次扫描把它们全部载入缓存。

若画出递归树，这一次**每层的成本几何递增**：$N^2/B,\; 8(\frac{N}{2})^2/B,\; 8^2(\frac{N}{4})^2/B, \ldots$。因此，**叶层成本主导**，总成本 = 每叶成本 × 叶数，

```math
MT(N) = O(M/B) \cdot 8^{O(\lg N/\sqrt{M})} = O(M/B) \cdot O((N/\sqrt{M})^3) = O\left(\frac{N^3}{B\sqrt{M}}\right)
```

> <span style="color:#1e8449;">**[note] Note（译者注，分块矩阵乘法的缓存无关分析）:**</span> 分块矩阵乘法（递归切成 8 个子矩阵乘法 + 4 个子矩阵加法）是缓存无关的**经典胜利**。**基本算法 $O(N^3/B + N^2)$** 的坏：每算一个 $Z[i][j]$ 要扫 $X$ 的一整行和 $Y$ 的一整列，行主序的 $X$ 行是连续的（好），但列主序 $Y$ 的「列」其实是一整列主序数组，扫描会反复**跳块**、浪费局部性。**分块版本**把矩阵切成适合缓存的子块，深度优先递归（subblock 乘完才换），使**每块子矩阵在缓存里被充分复用**。基例用**最强的 $\sqrt{M/3}$**：三个 $\sqrt{M/3} \times \sqrt{M/3}$ 子矩阵恰好一起放进缓存，一次扫描 $O(M/B)$ 搞定。递归树**每层成本几何递增**（8 个子问题 × 面积每层缩 4 倍 → 传输翻倍），所以**叶层主导**：叶数 $8^{\lg(N/\sqrt{M})} = (N/\sqrt{M})^3$，每叶 $O(M/B)$，总计 $O(N^3/(B\sqrt{M}))$。对比基本算法的 $O(N^3/B)$，分块把分母从 $B$ 改进到 $B\sqrt{M}$——**这是缓存无关矩阵乘法的著名下界匹配结果**（Frigo-Leiserson-Prokop-Ramachandran 1999）。注意讲义注明「不是 Strassen」——Strassen 是代数上少一次乘法，这里专注内存局部性；两者可叠加。此话题与你在 CSAPP 学的「矩阵分块乘法提高缓存命中率」完全同源，只是这里用**递归**而非**显式分块（loop tiling）**——递归天然不知道 $B$ 也能自动适配。
