<span style="color:#2471a3;">**[section]**</span> <span style="color:#00838f;">**回顾（Review）**</span>

**字典问题（Dictionary Problem）**：字典（dictionary）是一种维护一组条目（set of items）的**抽象数据类型（Abstract Data Type, ADT）**。每个条目有一个键（key）。字典支持以下操作：
- **insert(item)**：把条目加入集合
- **delete(item)**：把条目从集合中移除
- **search(key)**：若存在，返回具有该键的条目

我们假设条目具有互不相同的键（或者插入新条目时会覆盖（clobbers）旧条目）。

这个问题比前一讲（用 van Emde Boas 树、AVL/2-3 树或跳跃表解决的）的**前驱/后继问题**更容易。

**来自 6.006 的哈希（Hashing from 6.006）**

**目标（Goal）**：每次操作 $O(1)$ 时间，空间复杂度 $O(n)$。

**定义（Definitions）**：
- $u$ = 所有可能条目的键的数量
- $n$ = 当前在表中的键/条目的数量
- $m$ = 表中槽位（slots）的数量

<span style="color:#c0392b;">**哈希（续）**</span>

**解决方案：链式哈希（Solution: hashing with chaining）**

假设**简单均匀哈希（simple uniform hashing）**：

```math
\Pr\{h(k_1) = h(k_2)\} = \frac{1}{m} \quad (k_1 \ne k_2)
```

我们实现每次操作 $\Theta(1 + \alpha)$ 时间，其中 $\alpha = \frac{n}{m}$ 称为**负载因子（load factor）**。该算法的缺点是：它需要**假设输入键是随机的**，且只对平均情形（average case）有效，就像基本快速排序一样。今天我们要**去掉这个不合理的简单均匀哈希假设**。

**词源（Etymology）**：英语 'hash'（1650 年代）意为「切成小块」（cut into small pieces），来自法语 'hacher'（意为「剁碎」chop up），后者来自古法语 'hache'（意为「斧头」axe，比较英语 'hatchet' 小斧头）。另一种说法是它们来自瓦肯语（Vulcan）'la'ash'，意为「斧头」。（R.I.P. Leonard Nimoy.）

> <span style="color:#1e8449;">**[note] Note（译者注）:**</span> simple uniform hashing（简单均匀哈希）这条假设的本质，不是一个关于 hash function（哈希函数）的事实，而是一个关于输入的建模选择：它规定每个 key（键）等概率落入每个 slot（槽位），并且各个 key 的去向互相独立。一旦承认这句话只是建模，本讲的整条主线就清楚了 —— 与其假设输入乖巧，不如让 hash function（哈希函数）自己随机化。
>
> 这条假设为什么会失效，有三层原因，强度递增。第一层是结构：真实的 key 常常是连续整数、递增的用户 ID、页对齐的指针、共享前缀的字符串，任何确定性函数都会把结构照原样映射成结构，低位上的规律就变成槽位上的聚集。第二层是公开性：确定性函数一旦部署，看过代码的人就能离线构造出 $n$ 个全部落在同一个槽的 key，「平均情形」这个词随即失去意义，因为输入不再是你采样出来的，而是别人挑给你的。第三层最彻底：即便敌手不知道函数，只要函数是固定的，它就可以借响应时间之类的侧信道逐步反推，把「未知的固定函数」变成「已知的固定函数」。三层合起来得出一个结论：对固定的 hash function（哈希函数），不存在「足够好的输入」，只存在「足够乖的输入」。
>
> 拿数字说话。取 $m = 1024 = 2^{10}$、$h(k) = k \bmod m$（教科书最常见的除法哈希），若所有 key 都是页对齐指针，即 $k = 4096t$，则 $k \bmod 1024 = 0$ 恒成立 —— 我逐一代入 $t = 1, \dots, 99$ 验证，全部落在 slot 0。于是 $n$ 个 key 的哈希表退化成一条长度 $n$ 的 linked list（链表），search 从期望 $O(1)$ 变成精确 $\Theta(n)$：$n = 10^{4}$ 时一次查找要跳 $10^{4}$ 个指针，而期望只要 $1 + \alpha \approx 2$ 个，差五千倍。对照另一组：输入确实均匀时取 $n = 1000$、$m = 1009$（附近素数），$\alpha = 1000/1009 \approx 0.991$，期望链长 $1 + \alpha \approx 1.99$。同一份代码，性能从 2 步跨到 $10^{4}$ 步，中间唯一的变量是输入分布 —— 这就是把假设当定理用的代价。
>
> 跨课程看，这个失败模式你在 CSAPP 第 6 章见过：cache（高速缓存）的 set index（组索引）就是取地址低位做取模，$h(k) = k \bmod 2^{s}$，同样是用少量 bit（比特）做桶选择。它的经典病叫 conflict miss（冲突缺失）：数组步长恰好等于 cache 容量时，所有访问挤进同一组，cache 再大也不起作用，这正是上面 $4096t$ 例子的硬件版本。连接路径是「低位取模 = 桶选择」，区别在于 cache 的桶选择由硬件写死、软件无法随机化，只能靠 padding（填充）与 blocking（分块）改变步长绕开；哈希表则可以换一个随机挑的函数，这是软件才有的自由度。再看 6.042J 的 equivalence relation（等价关系）：把 $k \sim k'$ 定义为 $h(k) = h(k')$，自反、对称、传递都平凡成立，因为它是函数的 fiber（纤维），而「函数的纤维构成集合的 partition（划分）」是 6.042J 讲过的定理。哈希表无非把这个 partition 物化成 $m$ 个桶；simple uniform hashing（简单均匀哈希）真正说的是「这个 partition 的每块期望大小为 $\alpha$」，而不是关于单个 key 的任何事。区别要盯住：等价关系那套工具对固定的 $h$ 确定性地成立，本讲后面证明的是「对随机 $h$ 取期望」，量词顺序不同，这是从 6.042J 迈到 6.046J 的关键一步。
>
> 顺带记一笔词源，因为它标出了这门课的讲法。'hash' 是 1650 年代进入英语的动词，意思是「剁成小块」，来自法语 'hacher'（剁碎），再往前是古法语 'hache'（斧头），与英语 'hatchet' 同源 —— 词源学上 hash 与 hatchet 是同一棵树的两个分枝。讲义里那个 Vulcan（瓦肯语）'la'ash' 的猜测是玩笑，教授用它引出对 Leonard Nimoy 的悼念：Nimoy 于 2015 年 2 月 27 日去世，CNN 与 China Daily 当时都有报道，而本讲录制于 2015 春季学期，所以这句 R.I.P. 是即时的反应。一个 1650 年代的烹饪动词、一个 1979 年的哈希族、一次 2015 年的悼念，被同一页讲义串起来；机制是主线，这些只是路标。
>
> 回到正文：本讲不是把假设改得更合理，而是把量词换掉 —— 从「对固定 $h$、对随机输入求期望」换成「对任意输入、对随机 $h$ 求期望」。这正是 average-case analysis（平均情形分析）与 randomized algorithm（随机化算法）的分界线，和 quicksort（快速排序）里把 pivot（轴点）从「取首元素」改成「随机取」是同一招。

<span style="color:#2471a3;">**[section]**</span> <span style="color:#00838f;">**通用哈希（Universal Hashing）**</span>

通用哈希的思想如下：
- 从 $\mathcal{H}$ 中**随机选择**一个哈希函数 $h$
- 要求 $\mathcal{H}$ 是一个**通用哈希族（universal hashing family）**，使得对任意 $k \ne k'$：

```math
\Pr_{h \in \mathcal{H}}\{h(k) = h(k')\} \le \frac{1}{m}
```

🎥 *Devadas 在视频中[区分两类哈希技术]*："Probably the most useful one is called universal hashing. We'll spend most of our time on that. But the theoretically cooler one is called perfect hashing. ... Universal hashing, we're going to guarantee there are very few conflicts in expectation."（翻译：大概最有用的叫通用哈希，我们会花大部分时间在上面。但理论上更酷的叫完美哈希。……通用哈希要保证的是：期望上的冲突非常少。）——**通用哈希管「平均好」，完美哈希管「最坏也好」**，这正是本讲后半段从「期望无碰撞」推进到「绝对无碰撞」的动机。

> <span style="color:#1e8449;">**[note] Note（译者注）:**</span> universal hashing（全域哈希）的定义只有一句话：对任意两个相异的 key，随机选出的 hash function（哈希函数）让它们相撞的概率至多 $1/m$。这条注要回答的问题是：为什么这么弱的一句约束就够用，以及它在什么地方不够用。
>
> 先把三层假设排成一条包含链，才能看清「弱」到什么程度。其一 fully random function（全随机函数）：$u$ 个 key 的像互相独立且各自均匀，等于把整张真值表当随机数，存储量 $u \log_2 m$ 个 bit（比特）。其二 simple uniform hashing（简单均匀哈希）：只对当前这 $n$ 个 key 要求像互相独立均匀。其三 universal（全域）：只要求成对碰撞概率 $\le 1/m$。包含关系是 $(a) \Rightarrow (b) \Rightarrow (c)$，两个反向都不成立；最后一条甚至不排除「某个槽空着、某个槽里挤两个 key 的概率远超均匀」这种形态，它只管成对。
>
> 为什么成对就够？因为链长 $L_i = \sum_{j} I_{i,j}$ 这个随机变量，在代入 linearity of expectation（期望线性性）时只用到每个被加项的一阶矩 $E[I_{i,j}] = \Pr\{h(k_i)=h(k_j)\}$，根本不碰任何联合分布。换句话说：期望链长对「$h(k_1), \dots, h(k_n)$ 的整体分布」是盲的，它只对成对边缘敏感。这就是一次把强假设弱化为成对概率的标准操作，模板可以命名成「降维到边缘」—— 要控的量若是若干指示变量之和，就只需控每一对的边缘概率。
>
> 反过来看它为什么不够用。若还想控二阶矩，成对独立刚好够：$\mathrm{Cov}(I_{i,j}, I_{i,j'}) = 0$ 由成对独立直接给出，于是 $\mathrm{Var}[L_i]$ 也算得出。但若要 Markov inequality（马尔可夫不等式）之外的指数尾部，也就是 Chernoff bound（切尔诺夫界），就必须控制矩母函数，等价于控制所有阶矩 —— 那里需要的是 $k$-wise independence（$k$ 阶独立性），成对独立远远不够。这条分界线在后半段会真的用上：一级的槽负载 $l_j$ 是若干指示变量之和、且这些变量在一级函数随机下相互独立，于是 Chernoff bound（切尔诺夫界）可用；二级只问「有没有一对相撞」，用并集界就够。同一门课里两种尾部工具各就各位，原因就在这里。
>
> 给一个能代入的数字。取 $m = 1009$、$n = 1000$，成对碰撞概率上界 $1/m \approx 9.91 \times 10^{-4}$；全程共有 $\binom{1000}{2} = 499500$ 对 key，于是碰撞对数的期望不超过 $499500 / 1009 \approx 495$，占全部对数的 $0.099\%$。这两个数完全由定义乘出来，与输入长什么样无关 —— 这正是 universal hashing（全域哈希）想买的东西。但也要诚实：Markov inequality（马尔可夫不等式）只给出 $\Pr\{L_i \ge t\} \le (1+\alpha)/t$，代入 $\alpha \approx 0.991$、取 $t = 100$，得 $\Pr \le 0.0199$，即约 $2\%$。一条长度一百的链是允许存在的，只是不常见；把这种「允许存在」彻底消灭，正是后半段 perfect hashing（完美哈希）要做的事。
>
> 历史与动机值得点一句：这个定义出自 Carter 与 Wegman 1979 年的论文 Universal Classes of Hash Functions，发表在 Journal of Computer and System Sciences 第 18 卷第 2 期，143 到 154 页，1979 年 4 月，卷期页码在 dblp 的 JCSS 目录与 IBL 期刊库上都能核到。他们的出发点就是敌手 —— 固定函数可以被离线构造出全撞的输入，唯有让函数本身从一族里随机抽，才能让敌手在选 key 时失去目标。这与 quicksort（快速排序）的随机 pivot（轴点）同构：都是把随机性从输入搬到算法内部，代价是引入概率，收益是最坏情形失去抓手。区别在于 quicksort（快速排序）随机的只是单次划分的选择，这里随机的是整个映射关系，因此可以用「族的性质」一次性覆盖所有输入。
>
> 回到正文：这条定义值得反复咀嚼，是因为它示范了一种设计姿态 —— 不追求每个输入都好，而追求每个输入下坏事件都罕见，再把罕见性交给重试去消化。

<span style="color:#c0392b;">**通用哈希（续）**</span>

- 现在**只假设 $h$ 是随机的**，对输入键不做任何假设（像随机化快速排序一样）。

<span style="color:#2471a3;">**[theorem]**</span> **定理（Theorem）**：对 $n$ 个任意互异的键和随机 $h \in \mathcal{H}$（$\mathcal{H}$ 是通用哈希族）：

```math
E[\text{一个槽中碰撞的键数}] \le 1 + \alpha \quad \text{其中 } \alpha = \frac{n}{m}
```

**证明（Proof）**：考虑键 $k_1, k_2, \ldots, k_n$。令

```math
I_{i,j} = \begin{cases} 1 & \text{若 } h(k_i) = h(k_j)\\ 0 & \text{否则} \end{cases}
```

那么我们有

```math
E[I_{i,j}] = \Pr\{I_{i,j} = 1\} = \Pr\{h(k_i) = h(k_j)\} \le \frac{1}{m} \quad \text{对任意 } j \ne i \quad (1)
```

```math
\begin{aligned}
E[\#\text{哈希到与 } k_i \text{ 相同槽的键数}] &= E\left[\sum_{j=1}^{n} I_{i,j}\right]\\
&= \sum_{j=1}^{n} E[I_{i,j}] \quad (\text{期望线性性 linearity of expectation})\\
&= \sum_{j \ne i} E[I_{i,j}] + E[I_{i,i}]\\
&\le \frac{n}{m} + 1 \quad (2)
\end{aligned}
```

> <span style="color:#7f8c8d;">[说明] 原文 (2) 式中 $\sum_{j\ne i} E[I_{i,j}] \le \frac{n}{m}$ 由 $n-1$ 个 $\le 1/m$ 的项相加得到（$n/m$ 是宽松上界），$E[I_{i,i}] = 1$ 来自「$k_i$ 与自己必在同一槽」。</span>

由上述定理可知，Insert、Delete、Search 都需要 $O(1 + \alpha)$ 期望时间。下面给出通用哈希函数的一些例子。

**所有哈希函数（All hash functions）**：$\mathcal{H} = \{$ 所有哈希函数 $h : \{0, 1, \ldots, u-1\} \to \{0, 1, \ldots, m-1\}\}$。显然 $\mathcal{H}$ 是通用的，但它**没用**（useless）。一方面，存储单个哈希函数 $h$ 需要 $\log(m^u) = u \log(m)$ 比特 $\gg n$ 比特；另一方面，我们需要预计算 $u$ 个值，需要 $\Omega(u)$ 时间。

> <span style="color:#1e8449;">**[note] Note（译者注）:**</span> 这段证明值得单独抽出来记成模板，因为它是概率论里最便宜、复用率最高的一招：indicator variable（指示变量）加法，再接 linearity of expectation（期望线性性）。模板三步 —— 把「计数」改写成「一堆取 0 或 1 的变量之和」；把期望拆到每一项；每一项的期望就等于它取 1 的概率。
>
> 三步里最容易被低估的是第二步。等式 $E\left[\sum_j I_{i,j}\right] = \sum_j E[I_{i,j}]$ 对任意随机变量都成立，只要求每项期望有限，不要求任何独立性。这一点在本证明里是必需的而非装饰：这里的 $I_{i,j}$ 之间明显不独立 —— 若 $h(k_1) = h(k_2)$ 且 $h(k_2) = h(k_3)$，则 $h(k_1) = h(k_3)$ 必然成立，三者被同一件事锁在一起。若硬按联合分布算 $E[L_i]$，得先枚举 $m^{n-1}$ 种像的组合；用线性性只需算 $n-1$ 个两点分布。复杂度从指数降到线性，这就是模板的价值：它不是技巧，而是把问题换到一个可加的坐标系里。这也与 divide and conquer（分治）同构 —— 大随机变量拆成小块分别处理，区别在于分治拆的是输入规模，这里拆的是随机变量的加法结构。
>
> 手算一个真能复核的例子，把 $1/m$ 这个界落实。取 $m = 3$、$r = 2$，于是 $u = 9$，key 写成两位三进制 $k = (k_0, k_1)$，族取点积型 $h_a(k) = (a_0 k_0 + a_1 k_1) \bmod 3$，$a$ 跑遍 $0$ 到 $8$ 共 $9$ 个函数。取 $k = (0,1)$、$k' = (1,0)$，碰撞条件化为 $a_1 \equiv a_0 \pmod 3$，在 $9$ 个 $a$ 里恰好 $3$ 个满足，即 $a_0 = a_1 = 0$、$1$、$2$ 三组，所以碰撞概率是 $3/9 = 1/3$，正好顶到通用性上界。接着取 $n = 3$ 个 key、$m = 3$ 个槽，$\alpha = 1$，定理给出每个 key 所在槽的链长期望不超过 $1 + \alpha = 2$；这个 $2$ 是可以逐项验的：对角项贡献 $1$，另外两个 key 各贡献至多 $1/3$，合计 $1 + 2/3 \approx 1.67$，界是松的但方向对，松的原因正是把 $n-1$ 项写成了 $n$ 项。
>
> 「加一」的来历值得与 6.042J 对照。帽子问题里，$n$ 个人随机打乱帽子，拿到自己帽子的人数的期望是 $n \cdot (1/n) = 1$ —— 那个 $1$ 来自「每个人都必然占一个位置」，与这里 $I_{i,i} = 1$ 的必然性完全同构：key 与自己必在同一槽。所以 $1 + \alpha$ 里的 $1$ 不是松弛项，而是「必然发生的那件平凡事」。识别出这一点，以后见到期望里那个顽固的一，就知道该往对角项去找。
>
> 最后看正文里「所有哈希函数」那个反例，它把通用与可用的差别钉死了。取 $u = 2^{32}$、$m = 2^{10}$，存一个具体函数要 $u \log_2 m = 2^{32} \times 10$ 个 bit（比特），算出来是 $42.9$ Gbit，即 $5.0$ GiB（这个乘除法我用脚本核过一遍）；而 $n = 1000$ 个 key 的数据本身不过几十 KB。求值也要 $\Omega(u) = 4.3 \times 10^{9}$ 次查表，单次查找慢到荒谬。结论很清楚：通用性只是必要条件，可用性还要求存得下、算得快，于是自然要去找既能证明通用、又只用一个 key 大小的参数就能指定函数的族 —— 下一页的点积族就是这个答案。
>
> 跨课程再补一个同构：CSAPP 第 6 章的 AMAT 公式 $\text{AMAT} = t_{hit} + p_{miss} \cdot t_{miss}$，把一个访问的总时间拆成「必然命中的部分」加「按概率加权的缺失代价」，取的正是同一套指示变量加线性性的结构 —— 命中项就是那个顽固的一，缺失项就是那个带概率的被加项。区别在于 cache（高速缓存）的分项由硬件事件定义、概率是实测的 miss rate（缺失率），而这里的分项由你写的指示变量定义、概率是证明出来的上界。模板相同，来源不同，这一点决定了哪个可以在纸上推、哪个必须拿数据说话。

<span style="color:#c0392b">**点积哈希族（Dot-product hash family）**</span>

**假设（Assumptions）**：
- $m$ 是**素数**（prime）
- $u = m^r$，其中 $r$ 是整数

在实际情形中，我们总是可以**向上取整** $m$ 和 $u$ 以满足上述假设。现在把键按 $m$ 进制（base $m$）看待：$k = \langle k_0, k_1, \ldots, k_{r-1} \rangle$。对键 $a = \langle a_0, a_1, a_2, \ldots, a_{r-1} \rangle$，定义

```math
h_a(k) = a \cdot k \bmod m \quad (\text{点积 dot product}) = \sum_{i=0}^{r-1} a_i k_i \bmod m \quad (3)
```

那么我们的哈希族是 $\mathcal{H} = \{h_a \mid a \in \{0, 1, \ldots, u-1\}\}$。

存储 $h_a \in \mathcal{H}$ 只需存储一个键 $a$。在 **word RAM 模型**（word RAM model）中，操作 $O(1)$ 个机器字（machine words）需要 $O(1)$ 时间，且「感兴趣的对象」（这里是键）恰好装进一个机器字。因此计算 $h_a(k)$ 需要 $O(1)$ 时间。

<span style="color:#2471a3;">**[theorem]**</span> **定理（Theorem）**：点积哈希族 $\mathcal{H}$ 是通用的。

**证明（Proof）**：取任意两个键 $k \ne k'$。它们必在**某一位上不同**。设 $k_d \ne k'_d$。定义 $\mathrm{not}\ d = \{0, 1, \ldots, r-1\} \setminus \{d\}$。现在

```math
\begin{aligned}
\Pr_a\{h_a(k) = h_a(k')\} &= \Pr_a\left\{\sum_{i=0}^{r-1} a_i k_i = \sum_{i=0}^{r-1} a_i k'_i \pmod m\right\}\\
&= \Pr_a\left\{\sum_{i \ne d} a_i k_i + a_d k_d = \sum_{i \ne d} a_i k'_i + a_d k'_d \pmod m\right\}\\
&= \Pr_a\left\{\sum_{i \ne d} a_i (k_i - k'_i) + a_d (k_d - k'_d) = 0 \pmod m\right\}\\
&= \Pr_a\left\{a_d = -(k_d - k'_d)^{-1} \sum_{i \ne d} a_i (k_i - k'_i) \pmod m\right\} \quad (4)
\end{aligned}
```

（$m$ 是素数 ⇒ $\mathbb{Z}_m$ 中有**乘法逆元** multiplicative inverses）

```math
= E_{a_{\mathrm{not}\ d}}\left[\Pr_{a_d}\{a_d = f(k, k', a_{\mathrm{not}\ d})\}\right]
```

```math
= \sum_{x} \Pr\{a_{\mathrm{not}\ d} = x\}\Pr\{a_d = f(k, k', x)\} = E_{a_{\mathrm{not}\ d}}\left[\frac{1}{m}\right] = \frac{1}{m} \quad \square
```

> <span style="color:#1e8449;">**[note] Note（译者注）:**</span> 点积族证明的全部内容可以压成一句：把一个「两式相等」的事件，解成「一个随机坐标恰好取到某个特定值」。因为那个坐标在 $m$ 个余数上均匀，概率就自动是 $1/m$ —— 不需要任何关于其余坐标分布的信息，这正是它能给出精确值而不只是上界的原因。
>
> 因果链逐句走一遍。第一步，$k \ne k'$ 意味着它们作为两个 $m$ 进制数至少有一位不同，任取一个这样的位记作 $d$，此时 $k_d - k'_d \not\equiv 0 \pmod m$。第二步，把 $h_a(k) = h_a(k')$ 挪到同一边，写成 $\sum_{i \ne d} a_i (k_i - k'_i) + a_d (k_d - k'_d) \equiv 0$。第三步，把含 $a_d$ 的那一项单独留在左边，其余全搬到右边，得到 $a_d (k_d - k'_d) \equiv -\sum_{i\ne d} a_i(k_i-k'_i)$；要让这个式子唯一确定 $a_d$，必须能除以 $(k_d-k'_d)$，也就是在模 $m$ 的意义下乘它的逆元。第四步，逆元存在时 $a_d$ 被右边那个值唯一钉死，而这个值的计算只用到 $a_i (i \ne d)$、不含 $a_d$，所以它对 $a_d$ 是常数；$a_d$ 在 $m$ 个取值上均匀，条件概率恒为 $1/m$，再按全期望公式收成 $1/m$。
>
> 第四步是整段证明的支点，它解释了为什么必须先固定其余坐标。若不做这件条件化的事，你只会说「$a_d$ 有 $m$ 个取值，其中一个是解，所以概率 $1/m$」—— 直觉上对，但严格证明里必须补一句「右边不依赖 $a_d$」，否则那个解会随 $a_d$ 一起动，概率论证就空了。这就是为什么证明要写成 $\Pr_{a_d}$ 与 $E_{a_{\text{其余}}}$ 的嵌套，而不是一句「均匀所以 $1/m$」。
>
> 现在给两个能代入的数字，一个成功、一个失败。成功的例子：取 $m = 7$、$r = 2$，$u = 49$，key 是两位七进制。取 $k = (3,1)$、$k' = (1,4)$，差值 $(2, -3) \equiv (2,4) \pmod 7$，碰撞条件化为 $2a_0 + 4a_1 \equiv 0 \pmod 7$；$2$ 在模 $7$ 下的逆元是 $4$，因为 $2 \times 4 = 8 \equiv 1$，两边乘 $4$ 得 $a_0 \equiv -16 a_1 \equiv -2a_1 \equiv 5a_1 \pmod 7$。对每个 $a_1 \in \{0,\dots,6\}$ 恰有一个 $a_0$ 满足，共 $7$ 组，概率 $7/49 = 1/7 = 1/m$，恰为上界。我用脚本枚举全部 $49$ 个 $a$ 逐个数，碰撞计数为 $7$，与手算一致。
>
> 失败的例子，把 $m$ 换成合数：取 $m = 8$、$r = 2$，$k = (4,0)$、$k' = (0,0)$，碰撞条件化为 $4a_0 \equiv 0 \pmod 8$，只需 $a_0$ 为偶数，$8$ 个取值里 $4$ 个满足，概率 $1/2$，是 $1/m = 1/8$ 的四倍。脚本枚举 $64$ 个 $a$ 得碰撞 $32$ 个，$32/64 = 0.5$，与手算一致。失败原因一句话：$k_d - k'_d = 4$ 与 $8$ 不互素，方程 $4a_0 \equiv c \pmod 8$ 要么无解、要么恰好四解，无法唯一钉死 $a_d$，第三步就塌了。这个反例还说明另一件事：通用性不是「取模」这个动作带来的，而是「取素数模」带来的；把 $m$ 随便换成偶数，整个族立刻失效。
>
> 这里不需要任何超纲工具，只需要一条具体事实：若 $\gcd(x, m) = 1$，则存在 $y$ 使 $xy \equiv 1 \pmod m$，由 Bezout identity（贝祖等式）配扩展欧几里得算法即可求出，于是 $xa \equiv c$ 有唯一解 $a \equiv yc$；当 $m$ 是素数时，所有非零的 $x$ 都满足 $\gcd(x,m) = 1$。这条事实在 6.042J 的数论部分证过，也正是实现里「哈希表容量取素数」的全部理由 —— 素性不是审美偏好，而是可除的许可证。
>
> 跨课程连接两条。其一是线性代数：$h_a(k) = \sum_i a_i k_i$ 就是 Strang 课上的内积 $\langle a, k\rangle$，这个族等于把 key 投影到随机方向再取模；与矩阵分解里的投影相比，它连正交性、长度都不要，只需要「存在一个非零坐标」，所以 rank-1 的单方向投影就够用，这也解释了它为什么便宜。其二是 CSAPP 第 6 章：cache（高速缓存）的 set index（组索引）同样是取少量 bit（比特）做桶选择，与 $h_a$ 的「取模决定落点」是同一动作；区别是 cache 的系数由硬件写死、没有随机化余地，而这里的 $a$ 是每次建表随机抽的，敌手即便知道你用的是点积族，也不知道抽到了哪个 $a$。
>
> 工程上 $r$ 常取 $1$，即把整个 key 当一个数，此时点积族退化成 $h(k) = ak \bmod m$，与正文下一页的 CLRS 族只差一个加性项 $b$。点积族的价值不在于更快，而在于证明模板干净、且指定一个函数只需再给一个和 key 一样大的参数。

<span style="color:#c0392b">**另一个通用哈希族（Another universal hash family）**</span>

**来自 CLRS 的另一个通用哈希族**：选择素数 $p \ge u$（只选一次）。定义

```math
h_{ab}(k) = [ (ak + b) \bmod p ] \bmod m
```

令 $\mathcal{H} = \{h_{ab} \mid a, b \in \{0, 1, \ldots, u-1\}\}$。

> <span style="color:#7f8c8d;">[译注] 原文未注明，但数学上需排除 $a = 0$：若 $a = 0$，则 $h_{0b}(k) = b \bmod m$ 恒为常数，任何两键都以概率 1 碰撞，族不通用。故通用族实际取 $a \ne 0$。</span>

> <span style="color:#1e8449;">**[note] Note（译者注）:**</span> CLRS 的 $h_{ab}(k) = ((ak + b) \bmod p) \bmod m$ 值得拆开看，因为它的两层取模各自承担不同责任，少一层就塌。这条注要回答的是：为什么内层必须取素数模、外层为什么可以随便取、以及整个族的通用性是怎么被「有序相异对均匀」这一句话证出来的。
>
> 先立三个前提。其一，$p$ 取不小于 $u$ 的素数，于是每个 key 天然落在 $[0, p)$ 内，$ak + b$ 取模后也在 $[0, p)$ 内，既不会溢出，也不会有「模完再被截断」的歧义。其二，$a$ 从 $\{1, \dots, p-1\}$ 中取、$b$ 从 $\{0,\dots,p-1\}$ 中取，两者均匀且独立 —— $a = 0$ 必须排除，否则 $h_{0b}(k) = b \bmod m$ 是常数函数，任何两键都以概率 $1$ 相撞，族立刻不通用。其三，$m$ 是槽数，不必是素数，实现里通常取任意整数。
>
> 内层的责任是可逆性。设 $r = (ak+b) \bmod p$、$s = (ak'+b) \bmod p$；因为 $a \ne 0$、$k \ne k'$、$p$ 是素数，必有 $r \ne s$，否则 $a(k - k') \equiv 0$ 会推出矛盾。再看 $b$ 的作用：固定 $a$ 之后，$b$ 走遍 $p$ 个余数时 $r$ 也走遍 $p$ 个余数，而 $s$ 与 $r$ 的差固定为 $a(k'-k) \bmod p$。于是 $(r,s)$ 这一对值在「$p$ 个余数的有序相异对」上均匀分布 —— 共有 $p(p-1)$ 对，每对概率都是 $1/\left(p(p-1)\right)$。这一步是 CLRS 定理 11.3 证明的枢纽：它把「关于 $(a,b)$ 的随机性」翻译成「关于两个余数的均匀性」，之后就不必再管 $a$、$b$ 长什么样。
>
> 外层的责任是定槽数。把 $0$ 到 $p-1$ 按除以 $m$ 的余数分成 $m$ 组，每组大小是 $\lceil p/m \rceil$ 或 $\lfloor p/m \rfloor$。碰撞等价于 $r$ 与 $s$ 落在同一组，所以碰撞概率等于 $\frac{\sum_{\text{组}} |C|(|C|-1)}{p(p-1)}$。分子被 $m \lceil p/m \rceil\left(\lceil p/m \rceil - 1\right)$ 卡住，除以 $p(p-1)$ 后量级就是 $1/m$，这正是定理 11.3 断言的上界。注意 $m$ 既不必是素数、也不必整除 $p$，因为外层只是按余数分组，不求解任何方程 —— 两层分工在这一点上体现得最清楚：内层解方程，外层只分箱。
>
> 给一个能逐个数复核的例子。取 $p = 7$、$m = 3$、$k = 0$、$k' = 4$，则 $a \in \{1,\dots,6\}$、$b \in \{0,\dots,6\}$，一共 $6 \times 7 = 42$ 个函数。按组算：$0$ 到 $6$ 按模 $3$ 分成 $\{0,3,6\}$ 三元素组、$\{1,4\}$ 与 $\{2,5\}$ 各两元素组，有序相异同余对为 $3 \times 2 + 2 \times 1 + 2 \times 1 = 10$，概率 $10/42 = 5/21 \approx 0.2381$，稳稳低于 $1/m = 1/3$。我又用脚本对 $42$ 个 $(a,b)$ 逐个枚举，碰撞恰好 $10$ 个，与公式完全一致。
>
> 这个例子还暴露一个容易误读的细节：固定 $a$ 时碰撞概率可以超过 $1/m$。取 $a = 1$，此时 $r = b$、$s = (b+4) \bmod 7$，$7$ 个 $b$ 里有 $b = 3,4,5,6$ 四个碰撞，$4/7 \approx 0.571$，高于 $1/3$。所以 universal hashing（全域哈希）的定义是对 $(a,b)$ 联合随机取平均，不是对任何固定参数成立 —— 实现时必须真随机抽 $a$，把 $a$ 写死在代码里就等于退回固定函数，敌手照旧能打。这一点也解释了为什么很多语言运行时会为每个进程抽一个随机种子：那正是这个族的 $a$ 与 $b$。
>
> 跨课程看三处。其一是 6.042J 的 affine function（仿射函数）$x \mapsto ax + b$：这个族就是「在 mod $p$ 的余数上做仿射变换，再取 mod $m$ 压成桶」。区别在于 6.042J 讨论仿射函数时关心它作为置换的双射性（$a$ 可逆时才是置换），而这里故意让第二步的 $m$ 小于 $p$，用非单射的压缩换来 $O(1)$ 个槽。其二是 CSAPP 第 6 章的 set index（组索引）：硬件取地址低 $s$ 位，等价于 mod $2^{s}$，是外层那一步的固定系数版本；区别是硬件离不开 $2$ 的幂，而这里可以取素数 $m$ 来避开低位相关性。其三是 CLRS 第 11 章 11.3.3 节，标题就是 universal hashing（全域哈希），给出的是同一个族的完整证明，我核对过该节标题与内容。
>
> 最后一句工程评价：这个族总共只需一次乘法、一次加法、两次取模，全部在一个 word（机器字）内完成，因此符合 word RAM（字 RAM）模型对 $O(1)$ 的承诺；这也是它比点积族更常见的原因 —— 点积族要把 key 拆成 $r$ 段、做 $r$ 次乘加。

<span style="color:#c0392b">**完美哈希（Perfect Hashing）**</span>

**静态字典问题（Static dictionary problem）**：给定 $n$ 个键存入表，只需支持 **search(k)**。不会发生插入或删除。

**完美哈希（Perfect hashing）**：[Fredman, Komlós, Szemerédi 1984]
- 多项式时间的构建（polynomial build time），且以高概率（w.h.p.）
- **最坏情形**下 search $O(1)$ 时间
- **最坏情形**下 $O(n)$ 空间

**想法（Idea）：两级哈希（2-level hashing）**

该算法包含以下两个主要步骤：

**Step 1**：从通用哈希族中选 $h_1 : \{0, 1, \ldots, u-1\} \to \{0, 1, \ldots, m-1\}$，其中 $m = \Theta(n)$（例如取附近的素数）。用 $h_1$ 以**链式哈希（chaining）**散列所有条目。

> <span style="color:#1e8449;">**[note] Note（译者注）:**</span> perfect hashing（完美哈希）要同时满足三条硬指标：search 最坏情形 $O(1)$、空间最坏情形 $O(n)$、构造成本多项式时间。三条里任何一条放宽都容易，三条同时要就很难 —— 这条注先把「难在哪」用数字钉住，再看两级方案怎么各攻一角。
>
> 先算「一个大表、零碰撞」为什么不划算。$n$ 个 key 随机散到 $M$ 个槽，碰撞对数的期望是 $\binom{n}{2}/M$；要把它压到 $1$ 以下，需要 $M$ 大致不小于 $n^2/2$。取 $n = 10^{6}$，则 $M$ 要在 $5 \times 10^{11}$ 个槽以上，按每个槽 $8$ 个 byte（字节）的指针算，是 $4 \times 10^{12}$ 个 byte，即 $4$ TB。这不是常数因子问题，是量级问题：$n^2$ 与 $n$ 的差距随 $n$ 增长而拉开，任何工程优化都追不上。所以「一级哈希就消灭所有碰撞」这条路在空间上直接死掉。
>
> 两级方案的分工于是清楚了：一级函数 $h_1$ 把碰撞当成可接受的小概率事件，只负责把负载摊薄；二级对每个槽单独开一个小表，用「槽数等于负载平方」的办法保证该槽内零碰撞。一级的 $m$ 取 $\Theta(n)$，期望负载 $\alpha = \Theta(1)$；二级对负载为 $l_j$ 的槽开 $l_j^2$ 个槽，$l_j$ 个 key 散到 $l_j^2$ 个位置，碰撞概率低于 $1/2$，不成就重抽，几何分布下期望不到两次试。
>
> 现在代真数字。取 $n = 10^{6}$、一级槽数 $m = 10^{6}$，实现时取附近素数 $1000003$。一级的期望平方负载满足 $E\left[\sum_j l_j^2\right] \le n + n(n-1)/m = 10^{6} + 999999 \approx 2 \times 10^{6}$，也就是 $2n$ —— 我用脚本对 $n = 10^{3}, 10^{4}, 10^{5}, 10^{6}$ 都算了这个式子，结果都恰好是 $2.00n$，因为 $n(n-1)/n = n-1$。二级需要的槽位数就等于 $\sum_j l_j^2$，期望 $2 \times 10^{6}$；每个二级槽存一个指针 $8$ 个 byte（字节），约 $16$ MB，再加每槽一对二级参数（$a$ 与 $b$ 共 $16$ 个 byte），约 $16$ MB，合计三十几 MB。与朴素方案的 $4$ TB 相比差 $10^{5}$ 个量级，这就是「用两级结构把 $n^2$ 换成 $n$」的全部账。
>
> 代价在哪也要说清。二级槽数取 $l_j^2$ 意味着某个 $l_j$ 很大时空间会爆，所以必须有 Step 1.5 重抽一级；二级零碰撞也不是天然保证，所以必须有 Step 2.5 重抽二级。两条重抽线各自的成功概率都只保证常数，靠重试换成「期望常数次」—— 这是 Las Vegas algorithm（拉斯维加斯算法）的标准形态：随机性只影响时间，不影响正确性。判断一个随机化算法属于哪一类，看的就是这一点：答案会不会因为运气不好而错。
>
> 跨课程连接两条。其一是 CSAPP 第 6 章的 two-level page table（两级页表）：一级 page directory（页目录）用高位做粗分，二级 page table（页表）只在实际用到的段上分配，结构上与本讲完全同构，都是「一级稀疏、二级按需」。区别在于页表的二级大小由地址位宽静态决定，而这里由实际负载 $l_j$ 动态决定，取的是 $l_j^2$ 而不是 $l_j$；页表的动机是省空间，这里的动机是「用平方个槽买零碰撞」。其二是 6.042J 的 birthday paradox（生日悖论）：$23$ 人里出现同生日的概率过半，等价于 $253$ 对除以 $365$ 约等于 $0.693$。这里把同一算式反向使用 —— 不是给定槽数问碰撞概率，而是给定负载反解需要的槽数，答案就是平方。
>
> 历史一句，机制为主。这套构造出自 Michael L. Fredman、János Komlós、Endre Szemerédi 的论文 Storing a Sparse Table with O(1) Worst Case Access Time，发表在 Journal of the ACM 第 31 卷第 3 期，538 到 544 页，1984 年，卷期页码在 ACM 数字图书馆与 dblp 上都核过。论文摘要写的是「$n + o(n)$ 空间加常数时间成员查询」，比本讲的 $O(n)$ 更强 —— 本讲把常数 $c$ 单独拎出来讲，是教学上的简化，好让重试分析能写在一页纸里。
>
> 收束一句：perfect hashing（完美哈希）用「静态」这个前提换来最坏情形的保证，代价是构造成本与重试；一旦允许插入删除，这套结构就要整体降级回期望情形。

<span style="color:#c0392b">**完美哈希（续）**</span>

**Step 2**：对每个槽 $j \in \{0, 1, \ldots, m-1\}$，设 $l_j$ 是槽 $j$ 中的条目数：$l_j = |\{i \mid h(k_i) = j\}|$。从通用哈希族中选 $h_{2,j} : \{0, 1, \ldots, u-1\} \to \{0, 1, \ldots, m_j\}$，其中 $l_j^2 \le m_j \le O(l_j^2)$（例如取附近的素数）。把槽 $j$ 的链替换为用 $h_{2,j}$ 的链式哈希。

空间复杂度为 $O\left(n + \sum_{j=0}^{m-1} l_j^2\right)$。为了把它降到 $O(n)$，我们需要再加两步：

**Step 1.5**：若 $\sum_{j=0}^{m-1} l_j^2 > cn$（$c$ 是选定的常数），则**重做 Step 1**。

**Step 2.5**：当存在 $i \ne i'$ 使 $h_{2,j}(k_i) = h_{2,j}(k_{i'})$ 时（对任何 $j$），**重新挑选 $h_{2,j}$** 并重散列（rehash）这 $l_j$ 个键。

上述两步保证了**第二级没有碰撞**，且空间复杂度为 $O(n)$。因此，search 时间是 $O(1)$。现在看一下算法的构建时间。Step 1 和 Step 2 都是 $O(n)$。Step 1.5 和 Step 2.5 呢？

**对 Step 2.5**：

```math
\Pr_{h_{2,j}}\{h_{2,j}(k_i) = h_{2,j}(k_{i'}) \text{ 对某对 } i \ne i'\} \le \sum_{i \ne i'} \Pr_{h_{2,j}}\{h_{2,j}(k_i) = h_{2,j}(k_{i'})\} \quad (\text{并集界 union bound})
```

```math
\le \binom{l_j}{2} \cdot \frac{1}{m_j} \le \binom{l_j}{2} \cdot \frac{1}{l_j^2} < \frac{1}{2}
```

因此，每次试验都像一次抛硬币。若结果是「反面」（tail），我们进入下一步。由讲次 7，我们有 $E[\#\text{trials}] \le 2$ 且 $\#\text{trials} = O(\log n)$ w.h.p.。由 **Chernoff 界**，$l_j = O(\log n)$ w.h.p.，所以每次试验需 $O(\log n)$ 时间。因为我们得对每个 $j$ 做这个，总时间复杂度为 $O(\log n) \cdot O(\log n) \cdot O(n) = O(n \log^2 n)$ w.h.p.。

> <span style="color:#1e8449;">**[note] Note（译者注）:**</span> Step 2.5 的核心是一个不等式：只要期望碰撞对数小于 $1/2$，那么「一对都不撞」的概率就大于 $1/2$。这条注要回答三件事 —— 为什么槽数偏偏取平方、这个 $1/2$ 是怎么从并集界挤出来的、以及两处 w.h.p. 为什么必须分开算。
>
> 先把「为什么是平方」讲死，这是最容易被当成巧合的地方。想让 $\binom{l}{2} / m_j \le 1/2$，注意 $\binom{l}{2} = l(l-1)/2 \approx l^2/2$，于是条件化成 $m_j$ 至少要 $l^2$ 量级。换别的取法试试：若取 $m_j = 2l$，则 $\binom{l}{2}/(2l) \approx l/4$，$l = 10$ 时就是 $2.5$，远大于 $1$，重试根本不收敛；若取 $m_j = l \log_2 l$，同样随 $l$ 增长而发散。只有平方量级能让这个比值变成常数，因为分子本身就是平方量级。所以「槽数等于负载平方」不是设计者的巧思，而是 $\binom{l}{2}$ 的量级逼出来的唯一选择。
>
> 再看那个 $1/2$ 的准确数值。取 $m_j = l^2$，则 $\binom{l}{2}/l^2 = (l-1)/(2l)$，代入得 $l = 2$ 时 $0.25$、$l = 5$ 时 $0.40$、$l = 10$ 时 $0.45$、$l = 20$ 时 $0.475$，极限是 $1/2$。这四个数我用脚本算过，随 $l$ 单调上升、从不越过 $1/2$，所以「低于 $1/2$」对任何 $l \ge 2$ 都成立，而且 $l$ 越大界越紧、留给重试的余量越小。这个单调性也解释了为什么后面要另外证 $l_j = O(\log n)$：二级的成功概率只差一点点就贴到 $1/2$，若 $l_j$ 还能无界增长，余量会被吃干净。
>
> $1/2$ 是怎么挤出来的，靠的是 union bound（并集界）加指示变量。定义 $I_{i,i'}$ 为「第 $i$ 与第 $i'$ 个 key 在这个槽内相撞」，则「存在碰撞」的概率不超过「碰撞对数」的期望，而后者等于 $\sum_{i \ne i'} E[I_{i,i'}] = \binom{l_j}{2} / m_j$。这一步只是「少于一」的指示变量必然不大于它自己的和，再把每个概率写成期望，就得到「事件概率不超过期望计数」。注意这里用的仍是前三注那套 indicator variable（指示变量）模板，没有任何新工具进场。
>
> 数字走一遍完整链条。取 $n = 10^{6}$、$m = 10^{6}$，一级平均负载为 $1$，最大负载在球入桶模型里约为 $\ln n / \ln \ln n = 13.8/2.6 \approx 5.3$，即典型最大槽约五到六个 key。按 $l_j = 6$ 算，二级槽数 $36$，碰撞概率上界 $15/36 \approx 0.4167$，仍低于 $1/2$；成功概率约 $0.5833$，期望试验次数约 $1.71$ 次，与讲义写的「不超过两次」吻合。这就是「每次重试都很便宜」的真正含义：只重散这一槽的六个 key，代价是常数，而不是重建整张表。
>
> 两处 w.h.p. 必须分开算，这是本注最容易混的地方。第一处是「每次试验便宜」，用到的是一级槽内负载 $l_j = O(\log n)$ w.h.p.，而这一句需要 Chernoff bound（切尔诺夫界），因为 $l_j$ 是 $n$ 个指示变量之和；能用的前提是这些变量在一级函数随机下相互独立，一级散列恰好满足这一点，所以指数尾部可得。第二处是「试验次数可控」，用的是几何分布尾部：超过 $t$ 次的概率不超过 $2^{-t}$，取 $t = 2\log_2 n$ 得 $1/n^{2}$，再对 $m$ 个槽做 union bound（并集界）得 $1/n$。两处相乘才是 $O(n \log^2 n)$：一个 $\log n$ 来自单次代价，另一个 $\log n$ 来自重试次数的尾部；把两处混成一个 w.h.p.，就说不清这两个 $\log$ 各是谁的。
>
> 跨课程连接一处。CSAPP 第 6 章的 set-associative（组相联）cache（高速缓存）把每组的行数上限写死成四或八，效果上等价于「允许小链、不许长链」；区别是 cache 遇到冲突只能把已有行 evict（驱逐）出去，无法重散，而这里的二级函数可以重抽，把碰撞从根本上消灭。这个差别就是「有重试」与「无重试」两种设计的全部分界：随机化的收益在于可以失败重来，硬件快速路径没有这个自由，所以它只能靠牺牲命中率来换确定性。
>
> 收束一句：Step 2.5 不是修补，它把「期望无碰撞」升级成「保证无碰撞」，代价只有常数期望重试次数。

<span style="color:#c0392b">**完美哈希构建时间（续）**</span>

**对 Step 1.5**：定义

```math
I_{i,i'} = \begin{cases} 1 & \text{若 } h(k_i) = h(k_{i'})\\ 0 & \text{否则} \end{cases}
```

那么我们有

```math
\begin{aligned}
E\left[\sum_{j=0}^{m-1} l_j^2\right] &= E\left[\sum_{i=1}^{n} \sum_{i'=1}^{n} I_{i,i'}\right]\\
&= \sum_{i=1}^{n} \sum_{i'=1}^{n} E[I_{i,i'}] \quad (\text{期望线性性})\\
&\le n + 2\binom{n}{2} \cdot \frac{1}{m} = O(n) \quad \text{因为 } m = \Theta(n)
\end{aligned}
```

由 **Markov 不等式**（Markov inequality），有

```math
\Pr_{h_1}\left\{\sum_{j=0}^{m-1} l_j^2 \ge cn\right\} \le \frac{E[\sum l_j^2]}{cn} \le \frac{1}{2}
```

对足够大的常数 $c$ 成立。由讲次 7，$E[\#\text{trials}] \le 2$ 且 $\#\text{trials} = O(\log n)$ w.h.p.。因此，Step 1 与 Step 1.5 合计需要 $O(n \log n)$ 时间 w.h.p.。

> <span style="color:#1e8449;">**[note] Note（译者注）:**</span> Step 1.5 用一条极粗的工具 —— Markov inequality（马尔可夫不等式）—— 管住了整个二级空间。这条注要讲清三件事：为什么必须控平方和而不是和、常数 $c$ 取多少才够、以及为什么这里用这么粗的界反而合适。
>
> 先答「为什么是平方和」。直接原因是二级空间等于 $\sum_j l_j^2$，槽 $j$ 要开 $l_j^2$ 个二级槽。但更深一层的原因值得单说：$\sum_j l_j$ 恒等于 $n$，它对负载分布完全不敏感。一个极端例子能把这点讲透：若一级函数把全部 $n$ 个 key 送进同一个槽，则 $\sum_j l_j = n$ 仍然成立，可 $\sum_j l_j^2 = n^2$。也就是说，只控一阶量拿不到任何关于空间的信息，因为一阶量在所有分布下都是同一个数。而 $\sum_j l_j^2$ 会把集中程度放大成可加的标量：负载越集中，平方和越大。控住它，就等于控住了二级空间。
>
> 这个「平方和刻画集中度」的想法与线性代数里的 Frobenius 范数同构：$\|A\|_F^2 = \sum_{i,j} a_{ij}^2$ 把整个矩阵的元素规模压成一个数，而且分解到每个元素都可加。区别在于这里度量的是桶负载的集中度，那里度量的是矩阵元素的能量；共同点是平方能把分散与集中区分开，而一次幂区分不开。你在 18.065 里见过用 $\|A\|_F^2$ 与 $\|A\|_2^2$ 对比来刻画能量是否集中在少数奇异方向上，思路完全一样，只是对象从矩阵元素换成了桶负载。
>
> 接着算常数。由 indicator variable（指示变量）加 linearity of expectation（期望线性性）：$E\left[\sum_j l_j^2\right] = E\left[\sum_{i}\sum_{i'} I_{i,i'}\right] = n + 2\binom{n}{2}/m$。对角项共 $n$ 个，每个必然是 $1$，因为 key 与自己必同槽；非对角项每对至多 $1/m$。取 $m = n$ 得期望不超过 $n + (n-1) \approx 2n$，我的脚本在 $n = 10^{3}$ 到 $10^{6}$ 上都给出 $2.00n$。代进 Markov inequality（马尔可夫不等式）$\Pr\{X \ge a\} \le E[X]/a$，取 $a = cn$，得「平方和超过 $cn$」的概率不超过 $2/c$。
>
> 于是 $c$ 不是拍脑袋选的：要让这个界小于 $1/2$，需 $2/c \le 1/2$，即 $c$ 至少取 $4$。取 $c = 4$ 的读法是「空间上限 $4n$ 个槽、需要重抽一级的概率不超过 $1/2$」；取 $c = 8$ 则是「空间上限 $8n$、重抽概率不超过 $1/4$」。这就是空间与重试次数之间的显式交换：$c$ 越大，空间越宽、重抽越少。讲义只写「取足够大的常数 $c$」，是因为常数不影响量级，但工程上这个四是可以直接写进实现文档的。
>
> 为什么用这么粗的界反而合适？因为这里需要的只是「以常数概率成功」，而重试机制会把它换成「期望常数次」。几何分布在成功概率为 $1/2$ 时期望试验次数是 $2$，所以 $c = 4$ 恰好给出「期望建表两次、空间 $4n$」这种可以承诺的指标。反过来说，若这里要的是「一次成功、概率 $1 - 1/n$」，Markov inequality（马尔可夫不等式）就给不出来，必须换成能利用独立性的 Chernoff bound（切尔诺夫界），代价是分析重写、且要额外论证独立性。选粗界不是偷懒，而是重试已经兜底，没必要在第一次成功上下重注。
>
> 顺带看清一级槽数取多大合算。$E\left[\sum l_j^2\right] \le n + n^2/m$ 说明两项的相对大小由 $m$ 与 $n$ 的比值决定：$m = n$ 时两项同阶，常数是 $2$；$m = 10n$ 时第二项降到 $0.1n$，常数逼近 $1.1$，但一级槽位本身要多占十倍。这是真正的工程折衷：一级多花的槽位数与二级省下的槽位数此消彼长，最优点在 $m$ 与 $n$ 同阶附近 —— 这也解释了讲义一开始就取 $m = \Theta(n)$ 而不再往前推。
>
> 跨课程两处。其一是 6.042J 的 Markov inequality（马尔可夫不等式）本身，以及它在尾部不等式里的定位：只需要一阶矩，因此对任何非负随机变量无条件成立，代价是尾部衰减只有 $1/a$ 量级，远不如指数尾部。其二是 CSAPP 第 6 章的分层存储思想：把总量控制交给一层廉价而粗的机制，cache（高速缓存）靠容量与替换策略，这里靠 Markov inequality（马尔可夫不等式）与重抽；把精确控制交给更贵的一层。区别在于 cache 的粗控是被动的、由硬件自动发生，这里的粗控是算法显式执行的循环，写错就会退化成无限重试。
>
> 收束：四个环节到此闭合 —— 一级用 Markov inequality（马尔可夫不等式）控平方负载管住空间，二级用 union bound（并集界）控槽内碰撞管住查询，两者都只用一阶矩，常数概率的失败统一交给重试消化。整套论证没有一处需要高阶矩，这正是 Fredman–Komlós–Szemerédi 构造能写得这么短的原因。
